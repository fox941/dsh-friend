# 2026-10-29 调度空转排查与修复

版本：companion-adapter 0.20.1，架构保持 v0.22。

## 真实表现与原因

19:13:52 的 QQ 消息已经接收，但到 19:18:32 才回复，约延迟 4 分 40 秒。排查时 QQ 实际登录的是 AI 账号，OneBot 与 DSH 连接正常。

1. 同一次注意力决策选择了行为，同时新增未来浏览候选。新增候选推进事件版本，执行前检查将该决策误判为“有新事件”，把已选行为退回待选，反复调用模型。目标协调层的同步提案也存在相同路径。
2. 自动浏览仍在 60 分钟冷却内，但全局决策没有看到资源状态，仍选择浏览。执行失败后的收尾又把真实冷却原因覆盖为 `not_started`，让问题难以定位。
3. 19:16 的一次注意力决策输出达到 3200 tokens 上限，失败后的 60 秒重试间隔进一步增加延迟。
4. 用户请求的是自己账号的最新投稿，现有只读工具仅支持关键词搜索或明确视频，不具备按账号列举投稿的能力。泛搜索不能证明视频来自该账号。这与调度卡住是两个问题。

## 改动

- 同一次决策内的同步提案完成后，再记录执行所依据的事件版本。之后真正到达的新事件、异步状态变化仍使旧选择失效。保留并发去重与串行准入。
- 异步校验状态后重新检查事件版本，防止校验期间的新消息被漏掉。
- 休息决定附带的未来想法不再立即唤醒下一次付费决策；外部事件、到期时间和任务完成仍可正常唤醒。
- 在决策快照中给出浏览开关、自动/手动额度、冷却到期时间和能力范围。启动前复核；资源不足时停放任务，并允许重新考虑其他行为。资源条件恢复只重新开放候选，不强制执行。
- 修改活动配置时只唤醒被资源阻塞的候选，保留角色主动选择的推迟。执行结果保留真实失败原因。
- 注意力决策输出上限从 3200 调整为 8192 tokens，其他已授权预算保持不变。
- 对“我的账号最新投稿”且缺少明确视频的请求返回能力缺口说明。已排队旧请求在继续前也会核验；保留原始任务、观察、记忆及回执，不将泛搜索观察冒充目标投稿发布。

不设置聊天固定优先级，不强迫逐条回复，不改写情绪、人格或旧记忆。没有增加按账号查询投稿的新功能，仍需具体 BV 或视频链接。
