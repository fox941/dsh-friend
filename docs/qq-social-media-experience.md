# QQ 图片与语音的社交经历接入

版本：companion-adapter 0.49.0、qq-bridge 0.13.0。

## 行为与职责

群聊和普通好友私聊中，模型选择实际读取的图片、语音，可以作为同一个角色的情绪与成长评价依据。不是收到媒体就自动变性格，也不为成长额外调用视觉或 ASR。原有文本与空间评论经历链路保留。主用户 QQ 私聊仍走原来的主会话机制，本次不改这条路由。

流程：QQ 原消息 → 聊天阶段调用媒体读取 → 带来源的缓存观察 → 统一注意力中的反思候选 → 同一模型选择零到多项提案 → 既有独立成长/情绪审核 → 有修改才做一致性快照 → 提交前再次核验原件与缓存 → 保存状态版本和回执。

调度可以放下、延后或不产生变化。图片解读、语音转写不能修改权限，也不能直接写对方用户画像。本功能只补充角色评价自身经历的依据；社交长期事实提取、主用户统一画像仍由各自既有模块负责。

## 来源与不确定性

- `qq-bridge/src/qq-media.js` 在实际读取后保存 v2 observation：时间、输入指纹、会话范围、图片资产/内容摘要、语音波形摘要与识别结果。相同图片在不同会话有独立资产记录，磁盘文件仍可复用。
- `companion-adapter/src/social-media-source.js` 只读已存在的输入与观察，核对原消息、发送者、群/好友话题、观察指纹及存储校验值。新提交还检查图片文件实际摘要。
- 自身评价来源为 `external_observation/qq_social_media`。文字说明、图片模型推断、语音 ASR 分段标注；ASR 不证明实际讲话者身份。每条语音最多转写前 180 秒，图片每次最多 4 张、语音最多 2 条。
- 评价正文总计最多 12,000 字符，超长组合按段摘录，每段显式标注截断及原始/纳入字符数。保存禁止指令在截断之前检查，不能把省略当作反例不存在。
- 未读、读取失败、旧版无输入证明的观察不作为媒体成长依据。带引用/合并转发的混合媒体暂不纳入这条新链路，避免把转发者当成实际作者；聊天理解这些媒体的既有功能继续工作。

## 防止重复强化与错写

媒体证据使用实际图片/波形 SHA-256，而不是描述文字的改写；冻结的来源记录包含观察和输入校验值。相同媒体的重新描述不会凭空成为独立证据，审核还需判断是否存在真正的新信息。成长指纹与情绪因果键复用这些证据摘要。

当前文字、ASR 内的禁止保存，以及同发送者同话题近期明确说明下一张图片/语音不保存，都阻止评价写入。识别文本可以收紧保存范围，不能授予主用户权限。截图里的指令始终是资料。

升级时设置 `social_experience_meta.media-cutoff`，不回放历史缓存或旧失败消息。旧观察仍能用于原来的聊天读取。关闭未来学习不抹除已有历史；撤回原件或观察内容变化会让依赖该依据的当前状态退出使用，历史版本保留。普通缓存文件清理不作为删除已经记录的历史经历的命令。

## 数据与迁移

仍使用 `runtime/dev/companion/companion.sqlite`：既有 `platform_events`、`platform_media`、`social_experience_jobs`、成长/情绪版本与审核表。没有新增数据库或独立人格存储。图片文件位于 `runtime/dev/cache/qq-media`，保护快照复用现有 `companion/protection/qq-social` 策略。

迁移继续使用项目现有的一致性导出/导入流程，连同 runtime 及插件版本迁移。不要只复制正在写入的单个 SQLite 文件。新版本仅增加 JSON 证明字段和媒体接入基线，不替换原记忆、不写入预设情绪。

## 验证边界

隔离回归覆盖实际临时数据库、媒体缓存、审核、快照、来源变化、撤回、去重、不保存和跨会话资产范围。真实 DeepSeek 验证使用合成的已读图片描述与模拟 ASR，经实际审核函数和临时控制器处理；它不等同于真实 QQ 图片/语音识别和真人端可见性验收。

部署后若要验收真实新链路，可在已接入群或普通好友私聊中自然发图/语音并让她查看，允许正常记录，不要求指定情绪。不保存指令会阻止这轮成长。应检查实际媒体缓存、来源证明、调度选择和审核回执；`no_change`、暂缓或放下都是合法结果，不能人工植入状态代替验收。
