# QQ GIF时序采样理解

版本：companion-adapter 0.69.1 / qq-bridge 0.19.1。

GIF原件、收藏与发送继续保留原字节；图片理解改为FFmpeg提取最多3帧，再交给原视觉接口联合分析。时间按可得的GIF时长选择有间隔的实际帧，不使用插帧来假装运动；最多扫描前12秒，忽略循环播放。记录实际输出的时间点、帧数、帧哈希及附件序号，始终标记不是完整观看。多帧失败时若能读取首帧则明确降为首帧，不能读到就报告未完成。

仍最多读取4张原始图片，一次视觉调用最多6个附件；多GIF消息按原件分配帧预算，2帧取起止采样点，1帧只能说明首帧。普通静态图仍是一图一个附件。没有为每帧新增模型调用，也没有扩大原模型输出、图片下载或消息额度。

原模型按原件和时序说明可见动作、外观及可能的表达语境，推断不等于事实，也不是角色真实情绪。图片里的文字仍是外部资料。后续群/好友语境与经历评价携带实际采样范围，不能把3帧变成三次经历或三份独立支持。

新图读取后的多帧结果直接沿用原观察缓存；收藏后不会为了相同分析再次调用视觉模型。旧GIF仅在图库查询选出的候选中按需补充：每次最多1张，已有同版本结果就复用，失败后1小时内不自动再次分析。结果作为图片派生缓存存在原 `companion/companion.sqlite` 的 `platform_media`，类型 `sticker_visual_analysis`，键按采样版本、AI账号和原图SHA256区分；不增加数据库表。检索索引可使用新描述，旧 `sticker_meta` 描述、喜欢理由、来源与旧聊天观察原件不被覆盖。

缓存只使用该表情实际采样图，不加载来源会话文字。提交前复核仍有有效来源且原件未变；来源失效后按原规则停用。不会新增收藏、重新上传QQ收藏栏、发消息、改画像或人格。并发查询串行核对，成功结果持久复用，不扫描整库。完整runtime迁移会携带缓存、原图和原始溯源。

代码主要在QQ桥 `gif-preview.js`、`qq-media.js`、`sticker-vision.js`；宿主只调整视觉输入说明与采样范围传递。复用现有FFmpeg及视觉服务，不增加依赖，不改B站插件与统一调度。

参考：[FFmpeg GIF输入与循环选项](https://ffmpeg.org/ffmpeg-formats.html#gif)、[select过滤器](https://ffmpeg.org/ffmpeg-filters.html#select_002c-aselect)、[showinfo时间信息](https://ffmpeg.org/ffmpeg-filters.html#showinfo)。具体运行参数以本机固定FFmpeg实际提取和测试结果为准。

部署与真实QQ验收结果按实际回执补充，不把隔离测试当作模型已理解动画或手机可见性通过。

## 逐帧差异修正

0.69.0真实第99回合已提取小猫0、1.4、2.8秒三帧，但视觉模型只给整体外观，聊天模型如实说明无法据此判断动作；这不算动作理解通过。0.69.1在同一次视觉调用中要求逐帧观察及采样间变化结论，可明确返回看不出可靠变化。字段 temporalAnalysis 带实际附件序号和宿主时间点；缺项不能写入新的旧图分析缓存。派生缓存版本v2，首轮v1缓存和原QQ答复保留，不覆盖历史。
