# QQ 群聊与好友长期社交记忆

陪伴插件 0.32.0、独立 QQ 桥接 0.2.0。面向已接入群及其他好友私聊，主用户私聊继续使用原有记忆链路。辅助扩展 `napcat/qq-social-helper` 仍只负责群查询和加群。

## 一次交流如何处理

1. NapCat 原始事件按真实 QQ 号、AI 账号和群号生成话题。统一注意力仍可选择处理、等待或忽略。
2. 被选中的话题召回自己的社交记忆、当前发言人的昵称/名片历史，再交给现有同一角色表达。一个群内可记住多位成员，但 `subjectQQ` 明确区分发言人；不把同名者合并。
3. 表达结果可附最多三项记忆提案：对方兴趣、交流经历、待续话题或可修正的暂时印象。无值得保存的变化就为空。
4. 实际发送成功或模型选择沉默后，才把提案排入持久队列。独立审核在宿主没有正在执行的活动/聊天时处理；审核只可批准或否决原提案，不能扩写、更改其他人的条目。它是后台校验，不是第二个人格或回复调度。
5. 已批准的记录追加版本，再写入同一个 Mnemon Native 后端的隔离索引。索引失败保留记录和错误，可重试三次；近期已批准记录仍可召回，不影响已发送的回复。

普通私聊和每个群分别隔离。主用户的私密资料、自我描述和私人目标不会因此加载到群聊。模型记忆提案不能修改人格、情绪、权限或主用户资料；对方的兴趣不是 AI 自己的兴趣。

## 来源与修正

- 只接受本轮发送者原始文字的逐字依据。图片理解、语音转写、引用和合并转发仍可用于聊天，当前首版不直接拿它们写社交长期记忆。
- 明确要求“不保存/不记忆”以及接入测试时，不保存提案或昵称别名；这不限制正常回答，也不取消她选择沉默的能力。
- 名字来自同一 QQ 事件的昵称/群名片，只是别名，不改变账号身份；发言中的自称“主人”不能获得主用户权限。
- 修改和结束话题必须引用已召回的条目 ID、版本摘要，并属于当前发言人和原话题。提交时再次比较版本，保留旧记录。审核中有更新就不覆盖后来版本。
- 撤回、损坏或失效的来源不再作为可用记忆；历史记录保留。不会因为撤回新说法，就自动把更早的说法认定为当前事实。
- 不自动回灌旧聊天，不把尚未发送或回执未知的 AI 文本写成共同经历。未完成的审核在重启后标记中断，不自动重复调用模型。

审核依然依赖模型判断，不能保证每次语义判断正确。原文、内容、旧版本和审核结果均可检查；避免把暂时印象写成不可更改的性格结论。

## 数据位置

| 位置 | 内容 |
| --- | --- |
| `runtime/dev/companion/companion.sqlite` 的 `qq_social_*` 表 | QQ 别名、来源绑定、审核队列、追加式记忆版本、Native 回执与索引状态 |
| `runtime/dev/memory/qq-social/data/qq_<话题摘要>/mnemon.db` | 按 AI 账号和原群/好友私聊隔离的 Mnemon Native 检索索引，第一次实际写入时建立 |
| 既有 `platform_events` | 原始 QQ 事件和真实回复回执 |

复用现有 Native 可执行程序，没有新增模型服务或另装记忆产品。社交索引不注册进主用户默认空间，防止被普通全局召回误带入其他场景。每条记录标明外部发言归属，Native 使用 external 来源，关闭自动差异合并；索引重试先查找同一完整记录，避免丢回执时重复添加。版本账本保留正文与证据，以便追溯及索引故障时恢复。

完整实例备份、迁移以及现有 Native 导出会包含新子目录。迁移仍搬完整 `runtime/dev`，不要只搬默认 `memory/data/default/mnemon.db` 或只复制插件源码。

## 查看与配置

双击 `Social-Memory.cmd` 查看计数。命令行用固定版 Node 执行 `scripts/social-memory.mjs group <群号>`、`friend <QQ号>` 或 `note <完整条目ID>`，可看原文依据、旧/新版本、审核结果和索引状态。工具只读，不触发模型、建库或修改记忆。

`friend-adapter.config.platforms.socialMemory` 可设置 `enabled`、`recallLimit`、`recallChars`、`dailyReviews`。默认每次最多八条/6000字符、每天三十次审核、每次最多三条提案；审核达到限额保留排队，不限制聊天次数。队列最多一百个待审核事件，满时不会声称已经保存。审核超时六十秒，索引操作三十秒，检索最多十五秒；取消后不提交迟到的审核结果。自动执行活动时会等待，不强行打断观看或聊天。

本版新增社交表，旧版普通代码更新校验器会因存储实现变化而拒绝直接升级。这是保留的保护，不应删库绕过。当前电脑通过停机一致性备份后安装；旧电脑首次升级需要同样的受控存储升级。完成整机迁移后，后续不改存储结构的更新仍沿用现有流程。
