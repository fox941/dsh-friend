# QQ 表情库管理页

版本：companion-adapter 0.70.1 / qq-bridge 0.20.0。

在 DSH 的「记忆系统 → 表情库」查看同一 AI 已收藏的表情。支持静态图、原始 GIF、描述／标签／喜欢理由搜索、可用／已停用／来源不可用筛选、分页及刷新。展开「收藏记录」可查看当时的喜欢理由、私聊或群来源及时间。GIF 如已有采样分析，可查看动作变化说明；打开页面不会新调用视觉模型。

QQ 收藏状态来自已有提交和核验记录，页面明确标为「曾确认」，不代表此刻手机收藏栏的实时状态。仅有接口接受回执不能算确认；较新的取消记录也不能抹掉较早的真实确认。页面不轮询 QQ，也不执行收藏、取消收藏或发送消息。

## 停用和恢复

- 停用：阻止该图进入模型的可用候选，也在资源读取后及实际收藏／发送提交前再次核对。已排队但未实际提交的旧选图不能绕过停用。已经提交到平台的消息无法由此撤回。
- 恢复：仅重新开放后续候选，不重放已失败、取消或完成的操作。若原来源已失效，恢复不会使其重新有效。
- 两者都不删除原件、QQ 收藏栏、收藏理由或既有来源，不要求 AI 以后必须使用某张图。

页面只提供这两个管理开关，没有上传、删除、群发或手动植入人格的入口。收藏和表达仍由原模型与现有工具决定。

## 存储与迁移

原表情库沿用 `runtime/dev/channels/qq/stickers/shared-3197399707/`：`index.db` 保存图片目录和来源，`memes/` 保存原始文件。旧的会话表情目录继续保留。

停用状态独立存入现有宿主 journal 的 `platform_meta`，键为 `qq-sticker-control:v1:<AI QQ>:<图片 SHA256>`。每次管理操作的旧值、新值、时间与请求编号追加到 `platform_media` 的 `sticker_management` 记录。没有新增数据库表、记忆库或模型调用额度；人物画像、情绪、性格与长期记忆不在这次变更范围内。

迁移时按已有停机／打包方案迁移完整 `runtime/dev`，不要只复制 `memes/` 或表情 `index.db`：管理开关和原来源校验也依赖宿主 journal。完整运行目录迁移会同时保留原图、分析缓存、停用开关及管理历史。

## 权限和一致性

复用 DSH 已认证的 owner 页面连接，提供三个精确路径：列表 GET、原图 GET、状态变更 POST。agent 连接不能调用；状态变更还要求同源 Origin、JSON 和有界参数。原图通过 ID 获取，服务端核对账号范围、来源有效性、路径、媒体类型及内容哈希，不向页面提供本地路径或签名下载链接。

每次变更带版本号和唯一请求编号，开关与审计在同一事务提交。版本过期返回冲突，不覆盖另一窗口的后续操作；同一请求重试返回已有结果，不撤销后来发生的恢复。网络结果不明时页面刷新实际状态，不自动重试。读取损坏的控制记录时停止使用该项，保留原数据供排查。

列表和预览只读，不触发旧库迁移、额外识图或平台写入。页面来源理由仅供 owner 管理查看；模型跨会话检索仍只得到图片本身的描述与标签。
