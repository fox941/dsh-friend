# 画像更正结果的自主回报（0.45.0）

## 行为

QQ/B站主用户私聊的画像更正完成、部分完成、被否决、暂缓或失败时，可以形成内部结果回报候选。仍由同一角色的统一注意力决定是否关注，再由同一模型结合自我、感受、原请求和真实回执决定告知、暂缓或沉默。没有强制即时通知，没有固定语气；“后台完成”与“已经告诉用户”是两个状态。

初次安装会记录已有更正状态，不补推旧的完成结果。原先未完成的工作将来出现新的实质状态仍可形成新候选。轮询和现有注意力预算保持原配置，不另加守护进程。公开评论、群聊和其他好友不在本入口范围。

## 复用与职责

- `companion-adapter/src/profile-notice-source.js`：核验原主用户消息、原平台绑定、当前更正版本和逐步执行回执，构造结果资料。资料不是新用户输入，也不是新的独立事实证据。
- `profile-notices.js`：汇集状态变化、候选与原平台目的地、去重、过期、可恢复发送意图和回执。复用现有 `ProactiveStore` 的独立命名空间，复用已有注意力的 proactive 类型，不另造调度器或记忆库。
- `profile-notices-host.js`：无工具表达与独立出站核验。可以自然说明已经保存的真实结果，但不能把部分完成说成全部完成，也不能把“正在玩”扩写为“喜欢”。
- QQ 复用绑定主用户的 `privateText` 串行发送接口，OneBot 返回平台消息ID后记为 sent，不冒充已读。
- B站插件新增主用户私聊结果发送端口，复用原客户端、风控间隔、请求防重及精确读回。与普通私信共用发送锁，不构造额外社交回合或用户消息。实际 POST 前再次核验结果和新消息。

B站平台已受理但未通过精确读回时为 unconfirmed，发送中断无可靠回执时为 unknown；均不自动重发，不计入已确认发表上下文。已确认发送的回报仅提供给原平台、原主用户私聊的后续上下文，便于接续自己说过的话；公开场景和其他联系人不加载。

## 防过时与控制

新更正正在核对时可暂缓旧回报；同一画像族出现更晚更正、原消息失效、目标后来被修改或该批已被撤销后，旧候选不再按旧值发送。更正提案、审核、表达、出站核验和网络提交各阶段分别核对当前来源及版本。已发消息保留为历史，不能收回已经发出的网络包。

连续变化先使旧的未发候选失效，只留下仍有效的结果。重复收集或重启不重复回报同一状态；沉默、否决或已发状态不被再次强制执行。暂缓只保存重新考虑的条件，不保存定时补发的正文。结果候选默认有效24小时，每次最多20个未发送候选；超期停止。

原话明确“不要通知/不用告诉我”不生成回报；原平台后续 `/stop` 或“不要再通知”使待发回报失效。已有主用户 `friend_proactive_control` 的暂停、恢复、取消未发机会也联动本模块。关闭记忆写入或注意力协调时本模块不对外发送。

## 存储、查看与迁移

全部随原实例 `runtime/dev/companion/companion.sqlite`：

- `profile_notice_meta`：启用基线。
- `profile_notice_observed`：已观察状态签名，包含固定计划的步骤进展。
- `profile_notice_proactive_control/items/attempts`：复用现有出站存储格式、独立表空间；原主动分享记录不搬迁。
- `profile_notice_receipts`：平台受理与读回结果。

人物画像 → 更正与撤回页新增“结果回报”，分别显示待选择、沉默、待发、已发、未知或未确认；`friend_profile_changes_read` 也可只读查询。查看不触发发送。原画像、Runtime、Native、自我状态不因结果回报新增或重复写入。

迁移继续打包整个实例，无需单独搬通知数据。新表随原数据库迁移。保护快照与撤销仍保护原更正，不会撤销已经发送的通知；撤销后旧候选应失效，不能把旧完成消息重新发出。

## 验证边界

隔离验证使用真实 Runtime/Native、真实 QQ 出站函数和 B站协议客户端，网络由测试传输替身承接，不连接真实用户发消息。覆盖自主选择、沉默/暂缓、独立否决、来源/账号/场景边界、连续更正、手工后续修改、发送未知、重启防重和实际提交前的取消。

官方模型以合成事实检查表达及“部分完成不能说全部完成”“正在玩不能推断喜欢”的独立否决。真实账号送达须另行取得实际回执和用户可见性；安装不会为了演示修改真实偏好、重放旧请求或强制模型选择发送。
