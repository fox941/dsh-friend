# QQ 主用户文字通道

2026-10-28，companion-adapter 0.11.0 / 架构 v0.13。

这版在现有外部插件内增加 QQ 文字桥接，不修改 DSH、Mnemon 或已安装依赖。复用 dsh-onebot 的 WebSocket 连接、鉴权、重连及请求回执代码；身份、原话、会话、发送队列由我们实现。没有安装其完整 QQ 插件，没有增加 AstrBot。参考、固定提交和 BSD 许可证见 plugins/companion-adapter/QQ-REFERENCES.md。

```text
你的 QQ → AI 的 QQ / NapCat → 本机 OneBot WebSocket
  → 核验实际登录账号 + 绑定发送者 + 私聊
  → 持久接收记录 / 平台消息ID去重 / 原话来源
  → 专用 companion 会话（与 Web 分开）
  → 同一记忆读写、成长、情绪及夜间整理
  → 本轮回应意图 → 沉默留痕 / 保存最终文字及到期时间
  → 新消息与取消检查 → 持久发送记录 → 原绑定账号及回执
  → 实际完整送达的文字才成为交流证据
```

## 首次配置和登录

需要你的主 QQ 号和一个不同的 AI QQ 账号。绑定资料只保存在本地 runtime，登录由本人扫码完成。

1. 运行 Stop-Dev.cmd，停机后双击 Configure-QQ.cmd，输入两个账号。不输入密码。相同账号再次配置保留绑定 ID 和连接令牌；不支持悄悄换成别人的账号。
2. 安装 QQ NT。双击 Start-QQ.cmd，浏览器打开仅本机可见的 NapCat 管理页，用 **AI 的 QQ 账号**扫码。本项目不保存 QQ 密码。助手不会自动扫描二维码。
3. 双击 Start-Dev.cmd。模型连接会先向 OneBot 查询实际登录账号，账号不符时不接收聊天。
4. 用你的主 QQ 给 AI QQ 发一条普通私聊。先验证收发，再检查记忆。可在 DSH companion 中要求调用 friend_qq_status 查看实时状态，不要把本地“配置成功”当作“已经登录”。

Start-QQ 使用固定 NapCat Shell v4.18.41，默认本机 OneBot 3001、管理页 6099。已有 QQ 进程或端口被占用时，辅助启动器拒绝另启，不停止或注入现有个人 QQ。QQ 安装位置从注册表读取，换电脑也可运行 `powershell -File scripts/QQ.ps1 -QQPath "新的QQ.exe绝对路径"`。启动不主动请求管理员权限。

NapCat 引擎在 `.tools/napcat-v4.18.41`。固定下载为官方 [NapCat.Shell.zip](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41)，SHA-256 `6801f93e533846cea05f4f531874a0e84371ab2331c5585b57cd7e3b869cf96b`。发布压缩包已核验；本机 QQ 9.9.36.53644 与该引擎的真实登录、单轮私聊收发已通过；更长时间稳定性仍需观察。

Stop-Dev.cmd 会停止 AI 回复，不自动结束 QQ 客户端。NapCat 自身登录仍可保留，需要退出时在它的管理页操作。没有全局杀 QQ 进程的脚本。

## 独立运行组件

遇到 QQ 已启动但 NapCat 登录页未就绪时，可以运行根目录的 `Setup-QQ-Node.cmd`。它下载官方固定版本 v4.18.41 的 Windows Node 包，核对 SHA256 后安装到 `.tools/napcat-node-v4.18.41`。安装完成后，原 `Start-QQ.cmd` 会优先使用该组件，首次登录仍由本人扫码确认。该入口也可在从 Git 获取源码的另一台电脑上运行。

独立组件使用仓库内的 `scripts/qq-node-entry.cjs` 加载原固定引擎及本项目辅助扩展，沿用 `runtime/dev/channels/qq/napcat` 的配置。启动器会串行处理启动请求，重复点击时复用本项目已有的独立服务。工具下载和平台登录数据保存在本机忽略目录中。

## 数据、身份及迁移

| 位置（相对于 runtime/dev） | 内容 |
|---|---|
| channels/qq/config.local.json | 两个账号、固定绑定 ID、本机 OneBot 令牌、对话限额 |
| channels/qq/napcat/ | NAPCAT_WORKDIR：NapCat 配置、缓存、日志、管理页令牌 |
| companion/companion.sqlite 的 qq_* 表 | 账号绑定、专用会话 ID、原始文字收件箱、最终文字发件箱、预算与回执 |
| companion.sqlite 的 growth_event_origins | 成长/情绪所依据的 QQ 原话渠道；不改写旧事件 |
| dsh-home/ 下原会话 | QQ 专用会话原件，仍由 DSH 持久化 |
| memory/ 及 companion.sqlite 原有表 | 同一个角色的事实、兴趣、性格、自我、情绪和整理进度 |

QQ 原始消息外层保持 DSH 的 user 来源以兼容 Mnemon 召回；principal 内携带绑定、双方账号、平台消息 ID、收件记录 ID。仅在与持久原件、会话、消息 UUID、正文摘要全部一致时认作主用户。不是按昵称、正文自称或任意插件标记判断身份。网页原始主用户交流继续有效。

先停 DSH 和 NapCat，再备份/复制整个 runtime 实例；代码、固定引擎和依赖也要带上或重装，保留 profile/.friend-packages。NapCat 的工作目录随 runtime 迁移，**QQ 客户端自己的登录缓存由 QQ 管理，不保证全在此处**，新机器可能需要重新扫码。这不会清空角色记忆。跨机器启动、不同项目路径下会话 cwd 的重绑定尚未完成端到端验收；不要只搬一个 mnemon.db，也不要删除旧会话另建角色来掩盖路径错误。

## 当前边界

- 首版仅绑定主用户的文字私聊；群聊、其他联系人、机器人回声在进入模型前拒绝。不接受自动好友申请。
- 图片、语音、转发和引用消息不自动读取，不把别人的引用文本当成主用户原话。纯附件没有可处理文字时不触发模型。本次未实现 B 站、抖音、主动联系或自主刷视频。
- 多条快速消息串行进入各自回合；只发送本轮最终文字，不转发模型思考、工具结果、网页发言或中途文本。网页和 QQ 共用持久状态，各自保留聊天上下文，不保证逐句实时同步短期历史。
- 持久去重避免同一平台消息重复调用模型/重复写入；中断回合保留原文及状态，不擅自再次执行。QQ 消息不会单独生出另一套人格。
- 发送回执丢失或进程在发送时退出，标记 unknown，不自动重发。可能因此漏掉一条实际没发出的回复，换取不重复发送；OneBot 没有跨客户端恰好一次投递保证。friend_qq_status 可查看统计，原记录在 qq_inbox/qq_outbox，首版没有人工重发按钮。
- 默认每日最多300条普通消息、每分钟20条、待处理20条、单条6000字符、单轮180秒。/stop 可绕过普通额度停止当前处理，不撤销已经写入的记忆。连接前/离线期间的消息不保证补拉。
- 配置命令受实例停机锁保护。多文件配置先禁用桥接，再写 NapCat，全部完成后启用；中断保持关闭。配置和日志包含本地凭据/原话，继续按 runtime 私有文件处理。

## 验证范围

自动测试覆盖身份冒用、去重、原话核验、跨层来源、连续消息、停止、来源篡改、转发/引用排除、发送结果不明、配置中断及旧功能回归。另用隔离 DSH、真实 DeepSeek 和认证的本机 OneBot 模拟器验证 QQ→Web 记忆、Web→QQ 更正、相同自我/情绪工具、重启、重复投递及丢失发送回执。模拟账号不会真正发送 QQ，测试数据不进入真实角色。

这些结果不代表已完成真实 QQ 登录、平台投递或长时间在线验证；实际账号扫码与一轮私聊收发已另行验证，并获主用户确认收到回复。协议接入不等于官方 QQ 开放平台授权方式。
