# 不提供BV号的视频回忆

2026-10-30；companion-adapter 0.28.0，attention-scheduler 0.2.0，架构 v0.30。

## 实现范围

新增主用户会话工具 friend_video_recall，接在现有Mnemon与0.27.0视频笔记/原片段查询之间：模糊问题 → 原Mnemon召回 → 可追溯视频候选 → 同版原件回查。Web和绑定QQ等沿用原主用户权限；不同平台共享同一角色，没有新的人格或后台循环。

通过DSH公开tools.execute组合调用现有mnemon_recall；携带原agent、parent token、rootCallId和取消信号，遵守原工具guard与本轮固定View，不直接调用CLI做独立搜索。普通/复杂召回原有次数、字符包络、重复查询重放和质量筛选继续由friend-three-tier控制。

## 查询和候选

query最多300字符；可给一个忠实的alternateQuery（最多160字符）以及最多八个片段检索词。改写由当前主模型决定，不另开辅助模型。只有初次没有找到可追溯的视频时才使用备选查询；额度已关闭、Source不可用或取消时停止。原已调用的Mnemon查询与新组合工具共享预算。

不能凭长期记忆正文中出现BV号就认定看过。候选必须同时通过：

1. 该Native条目由本轮允许的Mnemon召回返回，原空间仍可通过现有Native读取规则访问。
2. apply_steps存在已应用的native_add/event回执，Native ID/空间与回执一致；当前正文与冻结操作正文完全相同。
3. 应用属于activity-memory协议，原件为B站实际观察，原话、范围与哈希仍匹配；活动允许学习，且批次未撤回。
4. 精确读回同BV/分P/CID的原文引用后，再核对一次Native正文未在期间改变。

失败或改动的来源被跳过并计数，不自动补写记忆或恢复旧记录。不把普通用户提及、待看标题、无保存观察、没有回执的旧导入或别人的转载当观看证明。当前桥接限定本项目可追溯的Native经历；将来换后端需要对应来源映射适配，原数据仍可保留。

按原召回名次合并同视频候选；rankScore仅用于排序，不表示正确概率。每次最多返回四个候选，默认三个；即便只展示一个，只要实际找到多个，仍标明ambiguous。角色可以核对上下文、精读某个候选或说明不能确定，不强制选第一名，也不要求每次询问用户。

每个候选带视频URL、分P/CID、实际观察ID、时间和原文证据，可继续friend_video_notes_read精读。返回总量不超过12,000字符，省略明确标记；至少保留所返回候选的锚点原文。不同视频/版本不拼成一次经历，字幕、转写与画面推断继续分别标注。

## 复用和限制

复用已有dsh-mnemon/Native检索、来源应用账本与视频笔记，没有新数据库表或独立向量库。不修改嵌入配置；已配置的能力由现有Mnemon使用，没有嵌入时仍按其可用检索能力工作。查询改写并不等于向量语义理解，不保证所有中文同义改写命中；无结果可能是来源未保存/失效、预算或检索能力不足。

技术读取不产生新经历、兴趣、情绪或人格变化。不重新看视频，不调用B站发现接口，不替用户发布或发消息。笔记需要时可以按原规则重建派生缓存，长期经历本身不会被回忆修改。

依据：Mnemon Native官方用法 https://github.com/mnemon-dev/mnemon/blob/master/docs/USAGE.md ；固定DSH公开tools.execute组合调用契约，原源码位于upstream/deepseek-harness/packages/core/tools/src/index.ts。没有引入LlamaIndex、VideoRAG或第二套视频MCP。
