# 通用画像更正与撤回（0.44.0）

## 范围与使用

首版处理已绑定主用户的 QQ 私聊、B站私信里**新的、明确的通用偏好更正/撤回**。例如真实地表达“以前那个称呼改为……”“我不再喜欢……，撤回这条偏好”。不要为了验收说不真实的偏好。

普通聊天仍由角色决定是否回复。后台约每15秒检查一次，等待模型及活动空闲后核对；这不是15秒保存承诺。普通记忆入口识别到这类更正后交给协调器，避免直接新增一份新旧并存的当前画像。

首轮回答可能早于后台审核，不能据一句“记住了”判断成功。可询问她更正进度（私聊工具 `friend_profile_changes_read`），或在 DSH → 记忆系统 → 人物画像 → **更正与撤回** 查看旧值、新值、原因、状态和应用批次。

首次安装建立收件基线，**不重放旧聊天**。含“接入测试”“不保存记忆”的本轮仍禁止写入，也包括更正/撤回；真实更正请另发明确原话。群内局部称呼、临时要求、其他好友、公开评论中的更正暂不归此入口。普通补充兴趣不自动覆盖旧兴趣，引用/假设/歧义可被暂缓或否决。

## 架构与存储

协调器位于 `plugins/companion-adapter/src/profile-changes*.js`，复用 Mnemon Native、公共 Runtime Source、独立审核与现有应用保护，不增加记忆服务进程。QQ 插件新增可选只读过滤端口，不搬迁其社交库，也不修改 B站插件源码。

1. 从已结束的真实收件记录读取新原话，核对绑定账号、原事件、会话/平台来源和禁止保存标记。
2. 枚举当前已审核通用画像及对应常驻原件，由模型提出替换/撤回关系；再由独立、无工具模型请求逐项审核。两次调用计入现有共享记忆审核额度；正常聊天不依赖这两次审核成功。
3. 编译固定写入计划。先保存一致性快照，失败不继续；每一步前重新验证来源、旧目标及已写入目标，保留逐步回执。
4. Native 新增本次变化原件；旧默认 Native 通过现有更正链添加“历史原件”标记，完整保留原正文。QQ 社交原件留在原库，通过读取端口停用旧画像族。
5. 仅更换/移除精确关联、版本未变的常驻条目。`memory/runtime/memories.json` 仍是 Runtime 事实源，`USER.md` 仍由 Runtime 生成。不会直接编辑这两个文件。
6. 最后在 `runtime/dev/companion/companion.sqlite` 的 `profile_change_*` 表事务提交当前版本关系与摘要关联；旧原话、旧版本和审核记录保留。QQ/B站私聊通过同一人物画像视图读取当前值。

新值默认保留私聊边界。旧偏好曾公开，不代表新的私人称呼/兴趣也可以公开；公开场景停用旧值，不携带私下新值或撤回理由。原群内专属称呼可继续优先于通用约定，首版不擅自撤销局部约定。

## 保护与限制

本模块不是跨 Native、Runtime、SQLite 的单一原子事务。中途失败会显示 `partial`，保留实际发生的步骤；后台只能核对并继续已有固定计划，不重新编造模型批准、不盲目重发旧消息。已批准而未完成的更正期间暂停自动摘要维护。

调用预算耗尽、材料过多、关系含糊或旧记录后来发生变化时，保留原件并暂缓。单条来源最多2项变化，每项至多8个明确旧副本，至多32个有效候选、8个完整写入步骤；超限不截断后偷偷写一部分。扫描沿用现有有界来源目录，不承诺语义识别覆盖所有历史句子。

撤销沿用项目入口：停止实例 → `Undo-Memory.cmd 应用批次UUID` → 成功后启动。除 Native、Runtime 的原有保护外，还检查当前画像关系及摘要关联未被后来修改；按目标恢复元数据，**不会整库覆盖 companion.sqlite**。Native 已有任何后续写入、目标后来改写、快照过期或缺少准确归属时会保守拒绝。撤销后同一原话不自动再执行；恢复偏好需要新的本人原话。

迁移仍复制/打包整个实例运行数据，包含 companion.sqlite、Runtime、默认 Native、QQ 社交 Native 与原平台会话。仅复制 USER.md 或一个 mnemon.db 不完整。保护快照按现有16份/512MiB额度管理，不新增夜间备份计划。
