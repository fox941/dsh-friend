# QQ 社交记忆的增量整理与维护

2026-10-31。构建版本：companion-adapter 0.33.0 / qq-bridge 0.3.0。

**当前状态：隔离开发、打包安装和测试已完成，尚未部署到主实例。** 本轮检测到项目中有同时进行的 B站插件抽离，涉及 companion-adapter 同一批文件；必须合并并行改动后再部署，不能整目录覆盖。主实例仍使用原安装包，角色、记忆、平台登录未被本轮修改。

## 分工与触发

- Mnemon Native 继续负责按 QQ 群／好友范围检索；权威记录和历史版本在 companion.sqlite。
- 新生命周期协调代码在 qq-bridge/src/social-lifecycle.js。不会把 QQ 社交空间注册到主用户的全局记忆池。
- 现有夜间整理被统一注意力选中后，先处理 QQ 社交增量，再继续原来的主用户记忆整理。没有新增独立人格或新的模型定时轮询。
- 每次最多扫描 20 条已处理事件，以账号对应的持久 rowid 游标推进。只有同一范围、同一发送者、比目标记忆来源更新的原话，才能用于更正或结束话题。超过这一批的增量留到后续整理。
- 整理模型最多提 3 项 revise/close；每项须带原话逐字依据、目标 ID 和当前内容哈希。第二次独立审核只批准或否决。没有证据就保留，不凭时间流逝宣布兴趣改变、话题结束或印象为真。聊天入口继续负责新增记忆和去重；夜间不生成新的事实。
- 夜间提案及审核计入 QQ 社交记忆共享的每日 30 次调用额度，单次输出上限 8192 tokens，整次社交维护最多 180 秒。暂停、取消、额度不足保留已完成的增量检查点。

## 时效管理

热／温／冷在这里是访问标签，并不是另建三份库：7 天内为 hot；此后按类型衰减，低于初始新鲜度四分之一为 cold，其余为 warm。

| 类型 | 新鲜度半衰期 |
|---|---:|
| 待续话题 | 14 天 |
| 暂时印象 | 30 天 |
| 兴趣自述 | 120 天 |
| 交流经历 | 730 天 |

数值是可调工程初值，不是人类心理规律。它们仅影响召回排序，不修改真实性、证据、人格或情绪。相关的 Native 命中仍能把冷记忆召回；检索不会自动把事实变得更可信，也不会刷新证据日期。经验保留较高的基础排序。

## 写入保护与撤销

- 只有确实要改变权威记忆内容／状态才做前置一致性 SQLite 快照，复用原 protection-sql.copyDatabase 的完整性检查、SHA256、超时和体积限制。
- 快照失败阻止写入，聊天发送回执不受影响。日常审核已通过的决定保留为 backup_blocked，恢复后重试快照，不重复付费审核。
- 快照目录：runtime/dev/companion/protection/qq-social。最多保留 16 份，合计 512 MiB；单份上限 512 MiB。清理旧快照不删除变更台账或记忆原文。
- 新表 qq_social_batches / qq_social_changes 保存批次、逐项旧值新值、原文依据、独立审核、快照回执；qq_social_maintenance_cursor / qq_social_maintenance_calls 保存增量进度与调用次数。原表没有改列或删行。
- 撤销须停机并持有原离线锁；撤销前再备份，并在事务内复核目标。目标内容／状态变化或任何后来批次触及目标就拒绝，不恢复整库，不覆盖其他群的新记忆。
- 新增记录撤销为 retracted，更正／关闭记录撤销时恢复该批次的旧状态。新旧记录仍保留。Native 派生索引不物理回滚，召回必须通过权威记录的当前状态和来源核验，因此撤销的索引命中不能重新变为有效记忆。
- 昵称观察、审计记录、增量游标是控制元数据；不是每次元数据写入都创建快照。首版没有物理遗忘、自动删原文、无限次撤销或撤销的撤销。

## 本地命令（部署后生效）

```text
Social-Memory.cmd status
Social-Memory.cmd group 719030047
Social-Memory.cmd changes
Social-Memory.cmd changes <批次完整ID>

Stop-Main.cmd
Social-Memory.cmd undo <批次完整ID>
Start-Main.cmd
```

查看为本机只读操作，不调用模型或真实平台。撤销命令不会自动停掉正在运行的实例，而是拒绝在线修改。不要用其他人的消息触发管理命令。
