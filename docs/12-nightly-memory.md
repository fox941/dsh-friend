# 夜间增量整理、暂停与遗漏补做

当前：companion-adapter 0.5.0，架构 v0.7。自研外部协调层，复用现有 DSH 模型服务、持久会话、jobs 和 Mnemon Runtime/Native 公开接口。没有修改 DSH 或第三方源码，没有增加常驻进程或冷归档数据库。

## 默认如何运行

- 项目安装后启用上海时间 `02:00` 的日程。首次安装等待下一次日程，不立即处理全部旧聊天。
- 电脑和 DSH 宿主需要在运行；没有注册 Windows 开机自启或唤醒任务。关机、睡眠时不能整理，恢复运行后按未处理的原始交流补做。
- 直接陪伴会话至少空闲 60 秒才启动；用户开始新一轮聊天会取消当前审核或停在下一步检查点，待空闲后继续。不会把后台投递伪装成新的用户消息。
- 无新交流时不调用审核模型；正常完成不自动唤醒聊天，不在普通闲聊中反复播报进度。

关机错过多天时合并成一次当前增量任务，不为每个错过的日期写日记。扫描和每次输入都有界，超出批次上限的交流留给下一次，不保证一次处理完全部历史。

## 聊天中控制

| 请求 | 效果 |
|---|---|
| “查询最近的夜间整理结果” | 读取日程、任务、批次、报告、应用检查点及额度 |
| “暂停夜间整理，重启后也保持暂停” | 持久暂停，取消当前及已排队任务；不会下次启动自动恢复 |
| “恢复夜间整理” | 恢复原有日程；到期未处理的增量会在空闲后补做 |
| “现在整理一次” | 排队一次，等当前交流结束及空闲后执行；不改变自动日程开关 |
| “取消这次整理” | 停止当前及已排队任务，未来自动日程仍保留 |
| “重试任务……，先核对原回执” | 从现有任务及报告检查点继续，不盲目重放已发生的写入 |

工具为 `friend_nightly_read` 与 `friend_nightly_control`。控制要逐字核对本轮主用户请求。工具返回 queued 仅表示排队，不表示已经改动记忆。预演回合仍只读，不能顺便修改夜间设置。

## 后台处理流程

1. SQLite 持久日程到期后领取一次任务，检查空闲状态及记忆写入开关，通过公开 jobs 注册宿主任务。
2. 使用独立 `nightly_preview_cursors` 读取本实例固定 workspace 内、非 fork 的原始直接陪伴会话。它与手动 `preview_cursors` 分开，因此手动“只看建议”不会让夜间漏掉未应用的原始交流。空会话轮转只更新扫描时间，不推进尚未处理的来源序号。
3. 复用只读预演，召回相关当前记忆，生成有原始 ID、逐字引文、时间和条件的提案。报告与扫描游标一起持久提交。
4. 先保存报告检查点，再以独立宿主维护授权复用可恢复应用流程。重新打开原始事件、核实现行版本、读取有界反例并审核，之后逐步写入和读回。
5. 保存每批报告与应用回执；状态及历史可查询。重启优先核对已有报告和计划，无需为已完成的预演再请求模型。

夜间授权只覆盖已配置的本地记忆维护，不授予浏览、账号操作、任意文件写入或新人格编写。原话明确要求用户本人再次确认、永久不保留或仅临时使用时，后台不能越过这些限制。

同一旧事实的已知完全相同副本统一更正；相关既有自我认识只标为待复核，保留依赖和旧版本，不增加支持次数。后台总结和重复召回均不是新经历。普通工作事项可按原文转存到已有 Native 后退出常驻；USER、关键约定及重要经历不因低频而被自动删除。

## 限额和恢复

| 配置 | 默认 |
|---|---|
| 日程 | Asia/Shanghai 02:00；本版固定该时区，时刻可配置 |
| 检查间隔 / 空闲等待 | 30 秒 / 60 秒 |
| 每次最多批次 | 2；每批沿用预演的会话、事件与字符上限 |
| 夜间每天最多审核模型调用 | 4；预演与应用合计，失败、取消也计账 |
| 单次任务时间 | 180 秒；单个预演/应用仍有各自更短的超时 |
| 普通失败自动重试 | 最多 1 次，至少等待 120 秒 |

仍同时遵守预演与应用各自每天 6 次的共享上限。无新依据、keep/duplicate 等无需写入项不强行调用应用审核。额度耗尽时保留报告，次日恢复额度后继续。

应用已部分写入或版本冲突时，任务显示 `needs_attention`，不会在后台反复强制覆盖；查询原回执后可明确重试。重试先核对旧步骤，后来又被用户改掉的目标不能恢复为旧值。跨层不是原子事务，事实改了而状态复核未完成时，相关旧认识暂时退出上下文。

关机中断保留 `interrupted` 检查点，宿主恢复后空闲补做。主用户取消或持久暂停不会被当成普通故障自动重试。单次任务 `completed` 只表示本次有界处理结束，部分语义提案仍可处于待定，超限历史仍可留给下一次。

## 数据及迁移

任务、日程、暂停、预算和调用记录均在既有 `runtime/dev/companion/companion.sqlite` 的 `nightly_*` 表；原报告仍在 `preview_*`，应用日志仍在 `apply_*`，事实仍由 Mnemon 保存。没有新增第二个事实库。

迁移仍须停机备份或复制整个 `runtime/dev`，并保留代码与 profile 的 `.friend-packages`；仅复制 Native 数据库不足以延续原始依据、扫描进度、自我状态和失败恢复。不同路径及不同后端的转换仍需适配，不承诺直接替换兼容。

项目安装器只给缺失的 `nightly` 配置补上默认值，保留现有自定义设置。配置位于 profile 的 `cordis.patch.yml` 中 `friend-adapter.config.nightly`；聊天中的暂停另存在 SQLite。普通暂停不必修改配置文件。

## 验证及边界

夜间专项测试覆盖初次等待、日程边界、多天遗漏、手动预演独立游标、重复、前台打断、回执中断恢复、暂停重启、共享预算、取消、失败重试和宿主公开接口。真实 DSH/DeepSeek 在独立实例验证自动补做、跨层实际写入、空增量、查询、暂停和重启。详细数量与备份见根目录 `verification.json`。

Native 仍是相关抽样，不能证明全库没有冲突。没有全库定期合并、按年龄自动遗忘、独立冷库、跨 Provider 转换或新增情绪模型；夜间协调层的通过也不证明长期人格或任意中文语义已经可靠。
