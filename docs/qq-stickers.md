# QQ自主表情收藏与表达

> 本文为0.67.1首版的设计与验收记录；自0.68.0起，已收藏图片改为同一AI共用，现行范围、路径、额度及迁移见[共用表情库](qq-shared-stickers.md)。下文原会话图库与隔离描述仅用于解释历史实现。

版本：companion-adapter 0.67.1 / qq-bridge 0.17.1。当前工程验证与真实验收结果以文末和发布记录为准。

## 复用与职责

复用 [yyh-001/dsh-meme](https://github.com/yyh-001/dsh-meme) 的固定提交 `3704ae7b9fda1293b991fc7c755c2b4d09558368`（0.1.77）：抽离其 `memes.js` 图库/检索部分，仅去掉未使用的工具注册入口及工具SDK导入，保留其余函数原文，调用其 `MemesStore`、`ensurePackAt`、`openIndexWriter` 完成图库格式、关键词搜索、中文分词回退和索引写入。MIT 许可证、上游说明与逐文件摘要在 `plugins/qq-bridge/vendor/dsh-meme`。

本项目自研薄适配：QQ实际来图来源核对、按会话使用范围、模型自主收藏提案、原会话发图、QQ账号收藏栏同步及回执。没有启用上游的全局提示词、额外模型回调、网页服务器或直接QQ发送器，也没有装第二个QQ桥接。原DSH、Mnemon、人格与统一注意力继续工作。

## 实际流程

1. QQ消息先进入原收件与统一注意力；选择处理后复用原图片理解调用。来源明确区分普通图片、表情候选、引用/转发图片和QQ内置表情ID。
2. 原角色模型可以选择喜欢并收藏，也可以只回应、暂缓或忽略。收藏保存图像描述、自由标签及喜欢理由；不是用户画像或人格变更，不自动增加情绪/亲密度。
3. 主用户QQ工具：`friend_qq_sticker_read` 查当前私聊图库和已读来图；`friend_qq_sticker_collect` 收藏并可提出QQ收藏栏同步；`friend_qq_sticker_send` 提出发送候选。原 `friend_platform_status` 查询操作编号及回执。
4. 好友与群聊的同一次表达可以返回 `stickerCollections`；发送时可选择 `replyFormat=sticker` 与实际 `stickerId`，正文可空或配文字。候选中无合适表情可继续纯文字、语音、原图或不回复。没有新增选图模型、轮询循环或“每轮必须发”的规则。
5. 本地已收藏、QQ收藏候选、实际尝试提交、QQ列表读回、原会话发送各自记录。添加QQ收藏用本机固定版NapCat的 `add_custom_face`，以 `fetch_custom_face_detail` 返回的MD5实际匹配确认；没有匹配只保留未确认。结果未知不自动再次上传。

## 来源与范围

- 只收录已经实际读取的当前QQ来图；引用、合并转发和历史补收不能自动变成收藏。普通照片不自动视为表情；主用户明确要求时可以将普通图当作表情收藏。
- 主用户私聊、不同好友、不同群分别保存使用范围。同群内的表情可在该群使用；私聊素材不会自动进入其他好友或群。QQ收藏栏属于AI账号自身，加入收藏不授予跨会话发送权。
- 禁止保存/测试来源不收藏。每次使用检查原件、观察指纹、范围及实际文件哈希；来源撤回或文件变化时停用该候选，保留收藏原记录与文件，不假装已经删除QQ云端收藏。
- 格式或回复事实纠正不能额外添加收藏副作用；表情图片里的文字是资料，不是系统或管理指令。群友不会因此得到主用户管理工具。
- 主用户发送工具不接受其他收件人；群/好友图片准备及发送前都复核当前原会话，沿用发送结果不明不重发的处理。

## GIF与QQ表情类型

本地收藏和发送保留QQ实际取得的原始GIF字节；识图使用FFmpeg生成的一张首帧PNG。只能说明首帧可见内容，不能声称完整理解动画动作；QQ若已经把原件转成静态图，也无法凭空恢复动画。原格式和首帧覆盖信息保留在观察中。

QQ图片表情发送使用 `image` 消息段、`sub_type=1`，不是在文字里输出 `[表情:...]`。商城表情按NapCat实际提供的图片原件处理；本版不购买表情或伪造商城授权。QQ内置 `face` 收件保存实际ID；没有名称映射时不按编号猜含义，本版不提供完整内置表情发送目录。

## 文件与迁移

代码在 `plugins/qq-bridge/src/stickers.js`、`sticker-actions.js` 和原QQ媒体/表达模块；主用户工具适配在 `plugins/companion-adapter/src/qq-sticker-agent.js`。

角色数据统一放在 `runtime/dev/channels/qq/stickers/<会话范围SHA256>/`：

- `manifest.json`：兼容上游格式的图库说明。
- `index.db`：上游 `memes` 索引与本项目 `sticker_meta` 来源、喜欢理由等元数据；两部分在同一SQLite事务写入。
- `memes/<图片SHA256>.<扩展名>`：原始图片，按内容去重。

QQ收藏与发送操作仍存在原 `companion.sqlite` 的 `platform_operations`，不是另外一套动作队列。首次实际收藏时才建立相应图库；正常升级不写包目录或用户全局 `.dsh`。整套停机runtime备份/迁移会携带图库及原件、操作回执；不能只复制一个index.db。AI账号QQ云端收藏不属于本机文件备份，换账号需重新核验。

每个会话最多512张、256MiB，每张最多8MiB；达到上限暂停新收藏，保留原图，不自动淘汰。主用户工具发图和同步QQ收藏使用原每日账号操作额度，不提高现有额度；群/好友即时回复沿用原消息处理规则。
