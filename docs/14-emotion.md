# 多项情绪、背景心境与事件重评

当前 companion-adapter 0.7.0 / 架构 v0.9。自研外部模块，复用 DSH 模型与上下文、既有成长预算和 companion.sqlite。没有新增服务或运行依赖；没有给角色预填名字、关系、快乐基线或固定七种情绪。

## 现在如何表示感受

多条情绪经历可以并存，每条保存：关联事项、开放标签、自然语言感受、事件对自己的意义、原因、原话、判断把握、时间锚点、时程、依赖的非情绪自我认识、状态与历史版本。高兴、幸福感、担忧可以各自存在；同一标签关联不同事项时保留独立原因，展示取最明显者，不简单加分，正负不相减。

一次真实交流可提出1–4项变化，另外一次无工具模型请求审核，允许接受、拒绝或暂缓。源码参考 ALMA、FAtiMA 与 dsh-feiyu-mood；具体固定提交、文件及取舍见 [EMOTION-REFERENCES.md](../plugins/companion-adapter/EMOTION-REFERENCES.md)。EMA 用于事件评价思路，EmotionML 用于区分类别、强度、把握、时间和来源；没有移植完整框架或宣称复现其研究结果。

## 如何变化

| 部分 | 实现 |
|---|---|
| 短期感受 | 从已提交的时间锚点进行半衰期投影，读取和重启不重新计时 |
| 缓慢背景心境 | 同一事件通过较慢时间核形成余留；是工程近似，没有预设开心/中性基线 |
| 性格、兴趣、自述 | 保留原来的成长审核，情绪模块不会自动写入稳定性格 |
| 新进展 | 引用已有 episodeId 重评；用新的绝对程度更新，不任意累加 |
| 事情解决 | resolve 对应经历，结束其当前感受；背景余留继续淡化，其他感受保留 |
| 原先误读 | retract 对应经历，退出当前与背景，保留原文和修正历史 |

程度使用 slight/moderate/strong，内部映射为0.2/0.5/0.8，再由程序按时间投影。事件时程 brief/normal/lingering 对应半衰期30/90/360分钟，表示本次事件的时程选择，非按情绪标签强制指定。背景时间核比短期慢4倍，并有渐进形成的过程。低于0.04退出当前展示，不删除历史，也不声称所关联的问题已经解决。数值是工程参数，尚未做心理量表或行为效果校准。

把握 low/medium/high 与程度分开，来自审核器的判断，未经概率校准。低把握项保留供核对，退出确定的当前感受和心境注入。读取只计算投影，不改时间锚点、不新增证据、不提高把握。相同原话跨会话也不会增加同一经历的支持；同义事件由模型审核辅助判断，仍可能误判。

## 如何使用

- “读取你当前保存的多项情绪，区分程度、原因和判断把握。” → `friend_emotion_read`。
- “查看这项担忧依据哪次原话，后来怎样变化。” → `friend_emotion_history`。
- 新交流有实际变化时，角色可用 `friend_emotion_propose` 提出 upsert / resolve / retract，不要求每轮调用，也不需要用户逐项批准。

明确要求“只查询、不修改”的回合只读取和报告；普通真实交流允许先读取当前版本再提交变化。读取本身不成为新的情绪事件；不把旧回执或自我描述当新外部经历。当前 API 仅接受本地主用户直接交流；B站、QQ和外部活动来源尚未接入。

模型每轮读取有界的自然语言情绪摘要，最多3项当前感受、2项背景影响；更多项目可查工具。后台数值无需模型自行做 PAD 运算。自然语言原因仍可能被模型误解，尚未系统证明情绪对表达和决策的影响强度。

## 数据、迁移和保护

新增 `emotion_*` 表与既有 `growth_*` 分开。保存不可变版本、当前指针、原始事件关联、审核批次及每次审核尝试；原话复用 growth_events。它们都位于 `runtime/dev/companion/companion.sqlite`，整实例备份和迁移自动包含。

升级不会拆分或重写旧 emotion:current：原句、原版本、原依据和原到期时间保留；到期前可作为标明旧格式的资料看到，到期后不作为当前注入。新的情绪使用独立经历表，旧 growth 接口的 emotion 分支仅作内部兼容，公开工具已引导使用新接口。

情绪与成长共享默认每天20次审核预算；开始的失败和取消也计数。版本并发时暂缓，混合批次在同一事务中提交，取消或异常不会留下半批情绪。夜间整理等待情绪审核让路，没有新增后台空转调用。

新情绪提交同步推进全局状态版本，因此整理之后形成的新感受会阻止旧批次撤销覆盖。独立的原有情绪在撤销其他记忆批次时保留。依赖的自我版本失效后，相关感受退出注入等待复核；即使以后恢复了相同文字的新自我版本，也需要重新核对依赖，避免自动伪造连续性。

当前最多24项活跃/低把握/待核对感受；查询有128项上限，超出显式报告省略，完整历史可按ID查看。没有自动物理遗忘、全库情绪分析、自主活动或新的管理页面。现有GUI可查看工具回执，详细状态通过上述工具读取。
