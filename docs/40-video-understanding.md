# 视频阶段性理解与原片段回查

2026-10-30；companion-adapter 0.27.0，attention-scheduler 0.2.0，架构 v0.29。

## 数据与职责

继续沿用 DSH、原视频读取、统一注意力、浏览意图、Mnemon 和人格/情绪审核。本次在 companion.sqlite 新增一张 activity_video_notebooks 表，保存可重建的阶段性笔记修订；在原始观察表增加按 BV/分P/CID 查询的索引。没有安装 LlamaIndex/VideoRAG、引入向量库、增加后台调度循环或修改第三方代码。

原始字幕/转写、抽样画面解释及区间仍在 activity_observations 和 activity_video_segments；待看/续看与未解疑问继续由原浏览模块负责。新表只保存“根据这些片段，暂时怎么理解、有什么问题”，不代表已核实事实或稳定人格，也不替代长期记忆。迁移仍停机复制完整 runtime/dev，并携带匹配版本插件。

## 增量笔记与修订

复用原 reflect 调用，可额外产生最多三条 understanding/question 笔记，每条须引用本次 excerptIndex 的真实编号。省略 videoNotes 时，宿主根据本次有引用的 summary 派生一条暂定理解；空数组表示不新增。没有额外的模型整理调用。

修订可引用同 BV、分P、CID 下当前有效的旧笔记 ID，必须给出新依据与修订理由；原文与旧笔记保留。原件哈希、笔记哈希和版本在提交/读取时核对。同批不能重复替换一个旧笔记；过期版本不覆盖后续内容。笔记及活动回执同一事务提交，重复任务/重启接续不新增一份同源笔记。笔记形状或引用错误复用原有最多一次反思格式纠正，不加新重试循环。

笔记的来源引用与结构经过程序校验，但其语义仍是模型的暂定解释，没有新增独立真伪鉴定器。已有长期经历、兴趣及情绪继续分别审核；读回笔记、摘要和修订不会变成新的独立证据。旧记忆不因笔记修订自动删除。

## 检索与续看

新增同一角色的 owner-scoped 工具 friend_video_notes_read，Web/绑定主QQ等沿用原权限边界。接受明确 BV/链接、query、最多八个 keywords；可按 CID 分版、用 evidenceId 精确回查引用，或 includeHistory/beforeRevision 分页查看修订。工具不看新视频、不调用模型、不写 Mnemon/人格/情绪。

先匹配暂定笔记并回查所引用的原文，再在同版视频的全部允许学习的历史原文分段中做字面匹配，补回笔记未概括的细节。中文问题使用运行时 Intl.Segmenter 分词，可由角色换同义关键词；这是本地字面检索，不是向量语义检索，不能保证复杂改写命中。查询按指定视频过滤，不扫描全体人格/跨平台记忆。返回条数有界，序列化结果最多 12,000 字符，省略明确标注；每条返回的当前笔记同时附带原件。历史页中的旧引用可再用 evidenceId 精确读取。

实际画面描述仍是模型推断，引用范围仍是抽样区间，不证明逐帧理解。旧版只有文字且无 CID 的观察单独保留为 text 版，不与新版画面拼接。未匹配不表示事件没有发生；模型可以调整查询、补看或说明未知。

续看选择与反思自动获得同版视频的有界笔记及按既有未解问题检索到的旧原件，原最近三份摘录继续提供。看什么、补看哪里、何时停止仍由同一模型与统一注意力决定。单窗60秒、每轮最多三窗及所有原预算沿用。

## 旧数据与无保存

首次回查时可由旧活动中已经保存的有依据反思派生笔记；不重新解释、不调用模型、不改写旧活动状态、旧观察或 Mnemon。笔记 ID 由视频版本、观察 ID 与序号确定，可依据原观察与反思重建。

learn=false 的新活动只保留原技术观察与回执，不生成笔记，也不进入本工具的历史检索/索引。已有允许保存的旧观察仍可查询和首次派生；“只读查询”不表示首次回查绝不写派生缓存。模型明确省略笔记、过期未应用等回执会被重建过程尊重。
