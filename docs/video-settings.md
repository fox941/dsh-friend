# 视频参数在线配置

版本：companion-adapter 0.73.0 / bilibili-tool 0.7.0。

在 DSH 左侧「B站工作台 → 设置 → 视频观察与采样」修改，点击「检查并保存修改」，确认旧值和新值后保存。只编辑输入框仍是草稿；保存成功后无需重启项目。

| 参数 | 原默认值 | 可用范围 | 作用 |
|---|---:|---:|---|
| 单个观察窗口最长 | 60秒 | 5–120秒 | 每个新窗口的时长上限，模型可以选择更短 |
| 每批最多观察窗口 | 3窗 | 1–3窗 | 一批处理后让出执行器，再由她选择后续 |
| 普通观察每窗采样画面 | 4张 | 1–6张 | 普通分段观察的画面数量 |
| 连续观看每窗采样画面 | 12张 | 4–24张 | 连续模式的时序图片数量 |

实例已有显式配置优先于上表默认值。未保存任何覆盖时继续使用原实例配置；只修改一项不会将其他项重置成默认值。所有范围沿用原视频引擎，没有扩张日额度、调用上限、证据容量或权限。

## 什么时候生效

新任务、连续观看的后续批次使用保存后的有效值。已经开始的一批，在准入时取得完整配置快照，并在原观察检查点保存；中途修改不会改变这批窗口计划、采样数量或证据预算，也不会中断它。

同一批因暂停、关机或进程重启而继续时，使用该批原快照，跳过已经保存的片段；下一批再采用新参数。旧版本检查点如果没有采样快照，首次进入新版本时以当前有效值建立快照，保留旧的已保存观察与计划，不声称还原了缺失的历史配置。

设置页分开展示「已保存的采样设置」与「当前批次」。没有当前批次时明确显示；旧批次缺少快照时不推断其参数。界面和配置读取不启动观看、模型、转写或平台操作。长片仍需她选择是否继续，不会因保存参数立刻观看。

显式请求的片段长度仍须符合生效批次的单窗上限。降低上限后，尚未开始且显式要求更长片段的旧请求，继续由原输入校验报告不匹配，不暗改原话或突破上限。更多画面会增加处理时间与模型用量，抽样仍不等于逐帧理解。

## 持久化与保护

配置覆盖保存在原 runtime/dev/companion/companion.sqlite 的 platform_meta，键为 bili-video:settings:v1。记录四项白名单覆盖、递增版本与更新时间。它是运行设置，不是长期记忆、兴趣、情绪或人格。

各批配置快照在原 activity_runs.request_json 和 activity_video_sessions.state_json 中保存；不增加数据库表。迁移沿用完整 runtime 打包和匹配插件版本的原流程。

复用工作台原 owner 认证、同源 POST、版本冲突校验、重复请求回执和同一数据库事务。管理回执保留被修改项的旧值与新值；任何一项无效或回执写入失败，全部回滚，不出现一半配置生效。视频配置另有递增版本，命令行修改或数值改回原值也会使旧页面版本失效。

存储中的视频设置损坏或越界时，停止采用该设置启动新的视频工作，保留原件供排查，不静默覆盖成默认值。普通与连续采样分别保持原6张／24张视觉请求上限；其他高权限能力与证据容量不开放在此页编辑。

静态 Bilibili-Console.cmd 和原白名单配置文件入口也支持 video 分组；静态页展示已持久覆盖项，完整有效配置以运行中的工作台为准。
