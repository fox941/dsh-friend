# 活动与选择

入口：DSH → 记忆系统 → 自我与成长 → 活动与选择。由 companion-adapter 0.55.0 提供，复用已有调度、浏览和诊断记录。

## 页面内容

- 当前调度阶段，最多12条执行或暂停事项、32条待办、最近20条选择。列表只是有限取样，顺序不是固定优先级。
- 单条事项的状态、最后记录的原因、重新考虑条件、关联选择和历史转换。详情扫描最近100条选择，最多呈现8条关联选择与20条状态转换；诊断清理后不能还原完整历史。
- 浏览任务已保存的抽样区间与检查点。观察流程完成不表示看完整片，不提供虚构的播放器进度。
- QQ连接、账号核验与最近入站分别展示。B站展示保存的收件服务记录，不重新核验登录。
- 已保存的资源额度、冷却时间、当前被跟踪的模型调用和近期调用异常。旧异常不等于当前故障。

## 如何判断沉默

只有明确保存的模型暂缓/放下标记，才标为模型选择。资源等待、执行错误、准备执行和待选择分别显示。执行错误优先于旧的暂缓理由。失效或失败的选择不是已执行证据；缺少原因保持未知，不能从消息文字、心情或等待时长推测动机。选择休息不会自动把每条待办标成忽略。

处理完成、接口受理、读回原件、提交核验与对方可见是不同事实；页面只展示已有证据，不制造送达结论。

## 实现边界

后端 BehaviorView 复用原 SQLite 与控制器纯状态快照，挂在已有 owner 鉴权 GET 接口。详情只接受类型白名单和UUID；未登录401、agent peer403、非GET405，禁用缓存。没有新表或新后台服务。

页面不调用模型、不轮询平台、不执行调度 tick/due/choose，不改预算、记忆、情绪、人设或任务状态。刷新只读取现状，没有重试、重发、唤醒按钮。正文经凭据模式过滤和长度限制，只展示保存的简短原因，不展示模型请求或隐藏推理。

源码位于 plugins/companion-adapter/src/behavior-view.js；页面复用 client.js、self-state-view.js 和 self-state-host.js。QQ/B站/调度器插件源码没有改动。迁移继续携带原 runtime 和插件，无需另建数据目录。
