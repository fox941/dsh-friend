# 自主待办与目标的复用、补充和新建

2026-11-04，companion-adapter 0.60.0，attention-scheduler 0.2.1。

## 为什么补这一层

视频待看列表原本已按BV和分P保持唯一，但调度的自由探索事项只按kind+topic精确键去重，长期目标也主要按稳定键与规范化标题去重。换一种表述仍会创建相近的问题。开发前只读检查有10条未结束的自由浏览意图，其中多条在询问同一迷宫视频的实际解题过程；它们也包含个体识别等不同问题，不能按同一视频粗暴合并。

## 如何决定

统一注意力的原模型请求增加relatedIdeas，最多呈现32项尚未结束的自由探索意图，包含等待状态、当前主题、版本标记和是否可补充/合并。长期目标仍使用已有longTermGoals。没有增加相似度服务、常驻模型、嵌入数据库、判断模型或调度循环。

模型逐项比较对象、实际问题、片段、内容版本和完成标准，再选择：

- new：确实是不同问题，创建新自由待办；新长期目标仍用propose。
- reuse：同一问题的另一种表达，记录关联并沿用原事项；不改变状态、等待条件或执行进度，也不因再次提及而唤醒。
- supplement：相关的新关注点。自由任务仅在尚未执行、没有检查点时可把主题改写为覆盖原问题与补充问题的简短主题，旧主题和完整旧状态保留。长期目标则只追加planningNotes，保留原标题、完成标准、采纳情况、步骤和真实回执。

同视频不同问题可new；当前模型可以不提出任何建议。索引标记truncated时不声称已经检查全部历史。语义等价仍由模型判断，程序不能证明两个自然语言问题真的等价。

## 原有重复事项

模型在reuse/supplement中可附mergeFrom，指向本轮呈现的另一项同类自由待办。只有两项均未执行、没有活动结果或调度检查点，且版本仍匹配时才可合并。目标事项保留原等待条件；重复项标记cancelled并记录planningMergedInto，原行不删除，完整来源状态进入历史。不把合并算作观看、执行完成、成长支持或新事实。

已有长期目标支持新提案复用与补充；本版不批量合并两个已有长期目标的执行步骤。合并不同视频版本、不同问题或不同来源范围属于模型误判风险，当前同类、来源范围及版本检查只能限制工程影响，不能替代语义判断。没有启动一次性扫描清理或手工批量取消正式待办，既有事项由自然调度自行考虑。

## 一致性与失败处理

ID及版本必须来自本轮宿主呈现的索引，旧版本不能覆盖后来的暂停、进度或主题。消息、群聊/私聊回复、账号操作、夜间整理和目标步骤均不进入自由待办合并范围。已有活动runId、结果或attention_checkpoints记录时不允许改写或合并取消。

补充及合并在同一数据库事务中写当前状态与审计。新建复用调度器原来的稳定键与持久offer；如果入队后、审计写入前中断，再试只会找到原事项，不会再次入队，原decision ID也保留在payload中。失败不会回退到无条件新建，不会冒充模型主动沉默，错误通过lastEffectError可见。重复同一操作使用原回执，不重复修改；关闭事项不自动复活。

目标的expectedRevision为整数；自由待办的expectedRevision为不透明字符串，两者不能混用。模型格式错误在行为提交前沿用已有一次纠正，不增加原最多两次请求/超时上限。版本或资格实际变化则拒绝写入。公开、未绑定用户来源仍不能修改主用户私密目标；不保存/临时使用规则继续沿用。

## 存储、查看与迁移

- 正式实例的runtime/dev/companion/companion.sqlite新增planning_idea_changes一张规划审计表，记录决定ID、前后状态、合并来源及回执。
- 长期目标继续复用companion_goals、goal_changes和goal_operations；补充说明留在原目标中，原来源历史保留。reuse仅记历史，不虚增目标版本制造重评循环。
- 主用户可用friend_attention_status查看planning索引与近期变更；friend_goals_read传目标id查看目标步骤、补充及来源历史。
- 长期记忆、USER画像、人格和情绪不由这一层改写。原完整runtime迁移方案继续适用；没有新增实例外数据目录。

## 验证

源码及实际安装包专项覆盖：复用不唤醒、补充保留状态/进度、不同问题独立新建、可追溯合并、并发旧版本拒绝、失败原子回滚、重启幂等、入队与审计中断、跨类别/账号操作隔离、原来源权限，以及目标版本类型的单次纠正。最终计数与全量结果以.work/intent-reuse-acceptance.json为准。

六组真实DeepSeek关系演练均只发送脚本中的虚构资料，使用实际协议校验和控制器，在隔离数据库应用。分别覆盖自由待办同义复用、同视频不同疑问新建、相关补充、两个已有重复项合并、目标同义复用、目标补充。演练要求输出一个关系提案，不代表生产自然选择每次都会提出或合并。

保留测试过程中的失败：早期目标提案字段被拒绝；后续发现模型把目标版本写成字符串，已增加整数指引及提交前校验，复用原一次格式纠正。真实角色材料没有发送给额外评估模型，也没有为了测试植入兴趣、目标或记忆。部署后只读核验加载、原件和数据保留；多日自然去重质量继续观察。
