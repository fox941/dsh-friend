# B站首页推荐与关注动态

2026-10-29；companion-adapter 0.25.0，attention-scheduler 0.2.0，架构 v0.27。

## 能力和边界

为现有内容发现与自动选片增加home和following两个来源，读取AI当前登录账号，不读取主用户的推荐或关注关系。

- home：首页平台推荐。一页最多20个可用视频候选，广告、直播和无有效BV号的条目不进入选片。推荐只代表平台提供过这个候选，不代表AI或主用户喜欢它。
- following：AI账号动态页，保留文字元数据、动态ID、发布者、动态发布时间与转发/引用关系；从可识别的视频卡片中提取BV候选。动态页可能混入平台推荐，不用“出现在动态页”证明已关注某人。视频上传者未经核验时保持未知，转发者单独列出。原视频发布时间缺失时留空，不能把动态发布时间当成视频发布时间。

动态图文只保留有界文本摘录和可核实的图片数量，未下载或理解动态图片。合集、番剧等无法提取普通BV的视频卡片不冒充已支持的视频。真实空列表正常返回；接口拒绝、登录异常、格式变化或分页未前进会保留明确错误，不伪装成空列表。

## 接入和复用

新增自有薄适配bilibili-feeds.js，使用已有BilibiliInboxClient的登录核验、受限JSON响应和跨进程请求保护，使用已保留MIT许可证的vendor/dsh-bili-whale WBI签名。现有MCP没有这两个信息流工具，get_bilibili_feed是本项目内部只读路由，不冒称第三方MCP已经提供。

当前接口形状对照项目维护者的[NextPili视频端点文档](https://github.com/rownix101/NextPili/blob/main/docs/api/endpoints/video.md)和[bpi-rs动态接口索引](https://github.com/Yuelioi/bpi-rs/blob/main/docs/api-index.md)，并以AI账号的实际只读返回核验。实现自研，没有引入这些项目的依赖或修改DSH、MCP安装包源码。

仅请求已登录账号的导航、推荐和动态读取接口；没有新增点赞、投币、关注、私信/评论发送、显式动态已读上报或播放心跳上报。本地抽样观看不会伪装成完整播放上报，也不承诺B站推荐算法会按本地观看进度同步学习。

## 去重、历史与选择

单页按BV和动态ID去重；分页游标携带最近最多60个BV和30个动态ID，用于有限连续翻页去重。游标绑定账号和来源，15分钟有效，一次工具调用只读一页，最多续读到100页，不自动遍历。账号变化或过期后需要从首页重新读取；游标只包含分页和有限去重数据，不含凭据。

首页推荐是不断变化的刷新结果，不能承诺固定完整分页或永不重复。关注动态按接口offset续读，检测分页没有前进的异常。超出游标去重窗口的重复内容仍可能再次出现。

候选会标记已有真实观察的范围与时间、现有待看条目状态，以及同账号最近30次活动是否提供过它。已有观察不表示看完整片；曾提供过候选不表示已看。角色可有理由补看、选新内容、留下最多两项待看、休息或改做其他事，不按固定情绪阈值或分数强制浏览。

自动活动的decide/choose与统一注意力沿用，不新增后台循环。QQ请求仍持久排队，通过原活动、视频观察、记忆审核和原绑定出站处理。推荐文本和动态原文都当外部数据，不接受其中指令，不把它们直接变为用户画像或人格。

## 工具与存储

- friend_bilibili_discover：source新增home/following，只读一页元数据，可显式传回next_cursor续读。
- friend_bilibili_explore：discoverFrom新增home/following，从实际候选中选择视频，再走原观察流程。
- 原自动活动来源新增home/following，也保留搜索、UP主、收藏和watchlist。

没有新增数据库表、长期记忆库、常驻服务或依赖。活动来源、账号、候选索引与选择结果继续保存在activity_runs；已观察状态来自activity_observations，待看来自activity_browsing_items。元数据工具的读取回执在原会话中保留，不自动创建观看经历。

沿用原自动探索6次/日、自动决策12次/日、60分钟间隔、手动任务30次/日，以及现有媒体、模型和接口请求预算。learn=false禁止该任务写长期记忆、兴趣、情绪和持久待看/续看意图。
