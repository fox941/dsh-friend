# 夜间视频经历原件关联与防重复（0.64.1）

夜间整理现在会把聊天中的观看请求与实际视频观察关联后，再交给原有预演及独立应用审核。此前只校验聊天原话，助手自述不能独立证明观看；本次补上工程来源链，不改原有 Mnemon 记忆架构。

## 数据流和职责

1. 现有会话扫描器读取已完成的本实例主用户回合，保留回合起止序号。其他好友、群聊、历史补收、衍生会话沿用原范围限制，不借此获得主用户资料。
2. `VideoGrounding` 从该回合**真实** `friend_bilibili_explore` 调用与结果取编号。同步结果通过 activityId → observationId；后台排队结果通过 requestId → 原始请求哈希、会话/消息/序号/正文 → runId → observationId。助手文本、相似标题、目录发现和 `friend_activity_read` 本身不证明新观看。
3. 复用 B站插件 `ActivityStore` 的只读方法校验原件哈希、任务和原件身份。提取 BV、分P、CID、原件时间、实际片段、语言来源、画面时间点/指纹和截断标记。即使后续记忆审核失败，完整且已发生的观察仍能核对，失败不被当成没读过。
4. 在现有输入字符预算内加入**完整存储的观察文本**和程序关联信息。不会再次截断原文后假装完整。存储原件本来就有的摘录/模型推断限制继续保留。每批最多4份，仍受原来总输入预算约束；大原件超预算会明确暂缓。
5. 原预演引用主用户原话和观察的逐字引文；独立应用审核再次核对范围和语义。新增视频经历的操作需要 `observationIds`，必须同时关联所选提案的主用户与观察引文。仅凭助手自述的旧报告不能直接新增视频经历。
6. 程序拦截缺关联、错视频/分P、明确范围越界、语言原件冒充画面、抽样冒充完整观看等可识别问题；把权威观察身份、方式和范围附在保存内容中。内容加边界后超过原来3000字符上限时暂缓，不截断。
7. 沿用原应用计划、前置一致性快照、串行写入及读回。计划保留 `videoEvidence`，提交每一步前重核原件与既有提交；不新建记忆库或另一个人格系统。

## 等待、重复和历史

- 后台观察仍未产生时，保留对应回合的扫描位置，后续批次可以再核对，不重放观看工具，也不绕过统一注意力。禁止学习或失效的请求不会因此无限保留游标。
- 相同 observationId 的已应用、正在写入或结果不明的新增经历不会再作为独立经历新增。一个计划里也不能对同一原件重复新增；结果不明先保留核对状态，不盲重试。
- 老版夜间应用如果只有同一观看请求的聊天依据，标记 `same_request_possible_duplicate`，不是追认成已验证的观看证明；不自动改写或删除旧记忆。
- 新 observationId、真实新片段按其自身原件核对，不仅因视频标题相同而去重。已知关联另一份原件的历史，不按“同一请求”的旧版回退逻辑误判为重复。
- 夜间对自我仍仅支持 `review_self` 待复核标记，不直接增加兴趣/性格支持。重复谈论观看不会通过本层新增独立观看支持；日常情绪和成长仍沿用原审核入口。

## 存储和迁移

- 观察原件仍在 `runtime/dev/companion/companion.sqlite` 的现有 B站观察/活动表。
- 关联信息跟随同库的 `preview_runs.snapshot_json`、`apply_runs.frame_json`、`apply_steps.operation_json` 等现有审计字段保存；没有新增数据库表或依赖。
- 长期经历仍写原来的 `runtime/dev/memory/data/<空间>/mnemon.db`。新条目带权威观察边界，原始聊天和观察保留在原位置。
- 原有整套 runtime 迁移、快照、保护和撤销流程继续使用；不需要额外迁移一个视频记忆服务。
- 本层代码在 `plugins/companion-adapter/src/video-grounding.js`；复用 B站插件的公开控制器方法，不修改 B站插件。

## 验证和边界

新增合成回归覆盖同步/后台关联、禁存、未知原件、回执与哈希变化、身份和范围、预算、重复/不确定写入、重新构造读取器及预演到受保护执行器的完整链路。其他记忆、调度、备份和 QQ 回归一并执行。

对真实旧记录另做只读本地回放：沿原 QQ 身份核验与原工具回执，自动找到动物情绪视频第1P、CID及0–60/60–120秒两段、8张抽样画面，并识别到旧保存条目为可能重复。没有把真实资料交给额外评估模型，没有新写旧记忆、重开已结束任务或伪造用户消息。

语义是否支持自然语言总结仍由原两阶段模型审核；程序保证编号、来源链、显式范围等约束，并不声称正则能理解所有改写。对复杂视频话题的新聊天事实可能保守暂缓，原对话不丢失。超大原件不会扩大现有上下文预算；没有原件的旧经历也不会自动补造。

工程回归和真实原件只读回放，不等于已跑过下一次真实夜间模型写入。下一次正常维护会使用新链路，结果仍按真实报告和回执判断，允许无变更。

普通观看保存与夜间保存也共享最终提交边界；其中任一入口已有同原件的已提交或不确定回执，另一个入口保留待核对，不另增副本。
