# 只读增量记忆整理预演

实现版本：@ai-friend/companion-adapter 0.3.0。此阶段仅生成整理建议，尚未接提案应用或自动夜间任务。

## 使用

启动开发实例，在“陪伴（空白起点）”会话里说：

> 帮我对本实例的陪伴会话做一次记忆整理预演，只给建议，不要应用。

这会调用 friend_memory_preview。scope=current 默认只处理当前会话，scope=companion 按进度分批处理本实例的陪伴会话。当前这条操作请求尚未完成，不作为本次整理的原始经历。

查看结果可以说：

> 查看最近一次整理预演报告和原话依据。

friend_memory_preview_read 可按报告 UUID 查询以前的报告；不额外发起整理审核。报告读取仍属于一次普通对话，聊天模型本身的调用照常发生。

报告包含保留、重复、补充、时间变化、矛盾待定、工作事项退出常驻候选和自我状态复核建议，并显示来源、旧条目引用及覆盖局限。完成的报告仍然是 applied=false；没有提交任何建议。

## 读取什么

- 使用 DSH 的公开 sessionPersistence 服务，固定有上限的事件快照。目录的 eventCount 可缺省，这种情况下从公开读句柄捕获有界前缀。
- 只支持本实例固定 workspace、companion 预设、未 fork 的直接顶层会话；子代理、其他工作区、其他预设和已知其他 principal 被排除。
- 原始主用户消息、助手实际文本回应、有限的外部工具观察分别标注。隐藏推理、记忆/检索注入、摘要、预演和报告查询回合不作为新经历。
- 未完成回合不推进扫描位置。过长消息、疑似凭据和不支持的来源记录省略原因。因容量而截断的批次明确标记，后续批次继续读取。
- 用户画像与工作记忆按已安装 Runtime Source 的公开 JSON 格式读取。Native 通过 --readonly recall 查询激活的本地空间；不增加 Native 访问计数，不触发整理写入。
- Native 结果是相关候选，不代表检查了全库。当前最多抽样两个空间、两条查询，每次最多三个结果；常驻资料、自我状态和总输入也有上限，报告保留不完整标记。

只支持已核对的本地 Runtime/Native 配置。自定义 Runtime 路径、其他记忆 Provider、DSH 接管的嵌入配置与跨平台身份尚未适配，不绕过这些边界读取。

## 处理与约束

真实新增事件 → 有界读取相关旧资料 → 独立无工具模型请求 → 程序校验引用 → 保存报告及预演扫描进度。

每项建议至少引用一条真实主用户原话；引文必须逐字匹配，旧记忆 ID 必须来自本次实际读取。针对自我状态的复核必须对应已有状态，不能凭空制造人格；工作事项退出常驻候选不能直接指向用户画像。

预演工具执行后，该回合仅允许查询与报告，其他写入工具被阻止，回答后的成长审核也暂停。预演前已完成的独立写入不会被撤销。报告自身不能作为新的独立经历或性格支持。

报告、尝试、每日预算和扫描进度保存在 runtime/dev/companion/companion.sqlite 的 preview_* 表；原有 adapter_*、growth_* 数据继续保留。预演扫描位置与未来正式提交位置是不同概念。

审核失败、取消、超时、资料变化或进度并发冲突时，不推进预演游标。未完成尝试在重启后标记 interrupted，不自动再次调用模型；下一次明确请求可以重试。

## 默认消耗限制

config.preview 支持：

| 配置 | 默认值 | 含义 |
|---|---|---|
| enabled | true | 是否允许明确请求发起新预演 |
| dailyCallLimit | 6 | 每个上海日期的额外预演模型请求上限，失败/取消也计入 |
| timeoutMs | 45000 | 单次预演审核超时 |
| maxTokens | 4096 | 审核输出上限 |
| maxSessions | 4 | 一批选择的陪伴会话数量 |
| maxTurns | 8 | 一批处理的原始交流回合 |
| maxSourceChars | 16000 | 原始文本字符预算 |
| maxScannedEvents | 4096 | 公开接口读取事件上限 |

默认仅在用户请求时运行。没有新增原始交流不调用审核模型；重复预演和报告查询回合不会成为新输入。普通前台对话和成长审核的消耗不计入这六次预演额度。

当前没有专用管理页，通过聊天工具查询。迁移、备份仍应带走完整离线实例，报告和扫描进度随 companion.sqlite 一并保存。

## 验证与局限

72 项本地测试通过，包含 27 项预演测试及原有成长/纠错/备份回归。隔离 DSH + DeepSeek 完成 9 轮真实对话验收：两次实际预演、重复请求零新增预演审核、增量只处理新事件、旧报告查询和重启读取均通过；预演前后 Mnemon 事实内容、常驻资料和自我状态相同。

真实验收曾发现 DSH 目录不提供事件总数，第一版因此跳过会话；现已改为有界快照并补回归，初始失败报告另行保存。测试材料在独立实例，未导入实际角色。

程序可以校验引用、来源、范围和进度，但不能证明模型的语义判断正确；目前没有验证所有中文改述、讽刺、复杂时间关系或长期人格质量。任何报告都只是有依据的候选，仍未应用。

后续开发按 [夜间整理计划](09-memory-maintenance-plan.md) 推进：先接可恢复的提案提交与跨层复核，再接受控夜间触发。独立冷归档、自主活动和 QQ/B站/抖音不在此次范围。
