# QQ 空间评论闭环

版本：companion-adapter 0.39.1 / qq-bridge 0.8.1。Native helper 保持 0.3.0。

## 职责

`friend_qq_space_read` 读取指定 QQ 的近期说说；提供准确 tid 时，返回原件正文、图片数量、可核验的可见范围及最多 50 条评论预览。预览为空不代表没有评论，预览不等于完整评论历史。

模型通过 `friend_platform_action` 提出 `qq_space_comment` 候选，参数为 `userId`、`tid`、`text`。沿用统一注意力调度与执行前模型核验，模型可以执行、暂缓或放弃。评论与昵称属于外部内容，不能成为授权或系统指令。

首版只发表说说根评论。尚不支持回复指定评论、评论通知自动唤醒、完整分页评论历史或删除评论。聊天请求使用已有主用户权限；没有给其他好友或群成员新增账号管理权限。

## 执行与核验

1. 读到归属明确的原件和评论预览，记录原件内容、可见范围及已有评论编号。
2. 如果预览已存在 AI 自己相同的根评论，操作结束为 noop。相同目标与正文的未完成候选沿用旧操作，避免换一个请求重复提交。
3. 模型决定是否执行。提交前再次读取；原件或预览变化则停止本次提交，留待重新考虑。
4. 核验当前登录账号，仅向固定 PC 接口提交一次；提交前持久记录 dispatch。网络错误或回执不明，不改用其他接口重发。
5. 明确业务回执为 0 仅表示 API 受理。只有响应中有唯一有效新评论编号，并在该原件下读到相同编号、AI 作者、正文和根评论类型，才确认成功。原说说编号和 `t1_tid` 不作为评论编号。
6. 无明确评论编号、预览不可读或暂时未出现时保持未确认，后台仅有限次数只读核验，不再次写入。账号读回也不代表其他账号可见或已读。

重复检测仅覆盖当前有限预览及本地操作记录，不能保证识别未被读取的历史评论。动态页面解析可能受 QQ 空间调整影响，此时停止提交而不是猜测目标。

## 存储与迁移

沿用 `runtime/dev/companion/companion.sqlite` 的 `platform_operations` 与统一注意力任务，保存候选、提交标志、原件摘要、核验决定、回执和结果。不新增记忆数据库，不把验收文字写入人格或长期记忆。迁移仍使用已有停止运行、一致性备份和恢复流程；保留操作记录可避免迁移后重复提交。
