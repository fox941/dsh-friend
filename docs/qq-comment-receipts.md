# QQ 空间评论回执与自动观察

版本：companion-adapter 0.39.2、qq-bridge 0.8.2，Native helper 仍为 0.3.0。

## 本次修正

feeds3 页面评论编号是说说内序号；它不保证等于写接口返回的评论 ID。先前 0.39.0/0.39.1 的直接相等比较不足以证明两者对应，本版停止用该比较自动确认。原有历史记录保留，不回写成成功。参考固定上游提交的 [评论编号说明](https://github.com/Gu-Heping/onebot-qzone/blob/e2c6da0ffea8937adac690352647bb023c312759/doc/feeds3-parser.md)。

目前本读取链路没有可证明的 API 评论 ID 与页面序号映射。因此空间评论的读回可结束为 observed，不能自动声称 confirmed；其他平台操作原有确认方式不变。

## 状态含义

- accepted：业务回执受理，尚未读到可用匹配项。
- observed：用同一 AI 账号，在相同作者、相同 tid 的说说下，读到唯一匹配作者、正文、根评论类型的评论；它未出现在提交前有限预览的编号列表中。单独保存“原件作者＋tid＋页面序号”引用，保留 API 返回编号且不混用。
- observed 不证明该评论属于本次提交，也不证明全量历史中从未出现过同文；不代表其他账号可见或已读。模型答复与操作查看均明确表达此限制。
- unconfirmed：限定次数读回仍没有足够观察证据。
- unknown：提交后连接、响应解析或业务回执不确定；不自动重发。

observed 是本次观察的结束状态，不继续等待缺失编号或重复执行。相同目标与正文的新候选仍复用旧操作。

## 脱敏诊断

`qzone-comment-receipt.js` 只记录固定白名单路径的字段类型、数值业务码、标识长度与 SHA-256、HTTP 状态和粗粒度内容类型；未知顶层字段只统计数量。完整解析结果仅计算哈希，不落原始响应。

不保存 Cookie、响应头、服务器返回文案、未知键名和任意响应字符串。HTTP/解析失败也保存有限诊断；代码与 ret 冲突时不假装受理，不切换接口补发。支持解析显式 commentId 大小写变体，但仍标记为未映射 API 标识。

诊断沿用 `platform_operations.value_json` 内的 receiptDiagnostics，观察证据沿用 verification，无新表、新库或记忆数据。`QQ-Operations.cmd` 和模型状态工具展示观察结果、原请求及脱敏诊断。

## 兼容既有记录

最近 24 小时内、同一 AI 账号、已经 dispatch 且明确受理、保留原准备证据、状态为 accepted/unconfirmed 的旧评论，可以获得一次版本化的只读观察机会。统一注意力仍可核对、暂缓或放弃；稳定任务键避免每轮产生新机会。不会复活 rejected/cancelled/unknown，不会重新评论。verificationOnly 任务有执行层检查，不能变为新的平台写入。

模型可按原主用户请求选择是否回报 observed 结果；观察与通知送达分别记录。无保存请求继续禁止写入长期记忆和人格。

## 验证

最终回归数量与部署状态见 `.work/qq-comment-receipts-acceptance.json`。真实验收复用用户已确认可见的旧评论，只读取，不为采集响应而再发新评论。旧响应未保存，无法反向重建其字段；实际新回执的诊断格式仍需等待下一次正常评论产生，不能用测试夹具冒充捕获到旧响应。
