# QQ 空间评论监测与指定回复

版本：companion-adapter 0.40.0、qq-bridge 0.9.0。Native helper 保持 0.3.0，不改 DSH 核心或 B站插件。

## 覆盖范围

每约 3 分钟使用 AI 当前登录态读取自己近期最多 20 条说说及每条最多 50 条可见评论。它是有限页面的新增可见评论监测，不是 QQ 官方完整通知流，不覆盖所有历史评论、好友空间、空间访客、点赞通知或其他平台。

首次成功读取仅建立基线，不追发历史回复。新进入监测范围的说说首次读取也只建基线，所以第一轮之前已有的评论可能不形成通知。API 不可读不等于没有评论，不推进为新的空基线。断线期间的恢复仍受近期页面范围限制，不能保证补齐全部遗漏。

每次最多纳入 20 个新可见来源，溢出的未推进指纹，下次继续。跟踪最多 40 条说说，每条保留最近 150 个评论指纹；持久事件键进一步去重。基线与事件写入使用同一 SQLite 事务，失败不留下“已推进但事件没入库”的一半结果。AI 自己的评论仅加入基线，不形成自我对话。

## 行为链路

认证读取 → 来源事件落盘 → 统一注意力 → 同一模型选择 reply/defer/ignore → qq_space_reply 候选 → 原账号操作额度及执行前模型核验 → 单次提交 → 有限只读观察。

收件不强制抢占聊天或观看。暂缓后重新判断，不发送提前缓存的旧稿；评论消失、正文变化或原件可见范围改变时停止旧来源。7 天未处理的来源过期。首次观察时间不是发布时间，页面时间仅为解析估计。

空间来源按“AI账号＋说说作者＋tid”隔离，作者 QQ 来自认证页面；昵称和正文不能自称主用户。绑定主 QQ 出现在空间仍被识别为同一主用户，但不加载私聊记忆，也不在此表达回调开放账号管理工具。

本版空间表达仅为文字，不直接写社交长期记忆或人格。原 QQ 群聊和好友私聊记忆继续运行；不能把新增空间上下文说成已经长期记住。

## 指定评论回复

- 自动来源使用真实 `eventId`；原说说、来源序号和作者由保存的事件与当前原件交叉核对，不能混入其他目标。
- 主用户工具也可指定 `userId`、`tid`、`commentSequence`、`text`，序号必须来自实际空间读取。
- 首版只允许 AI 自己说说下的评论。楼中楼来源必须同时读到所属根评论；提交到原根线程并指向来源作者，不猜楼层，不冒充向其他人回复。
- 提交前再次核验原账号、源内容、可见范围和接收者，禁止准备后改收件人。
- 复用固定 PC 请求，参数参考固定上游 `commentEmotion` 的 `commentId/replyUin/commentUin`；提及部分由程序根据原作者生成，不采纳正文中的目标声明。不升级到其他框架，也不在结果未知后切换接口重发。
- 接口可能不接受页面序号，受理也可能没有可用 ID；不把“支持参数”当作真实成功。缺失或拒绝回执保留实际结果。

页面序号与 API 评论 ID 不等同。观察要求实际原根线程、原接收者、AI 作者和正文匹配；可结束为 observed，不能冒充本次提交归属已确认或他人已读。无法观察时限定次数后为 unconfirmed，结果不明不重发。

## 数据与开关

沿用 `runtime/dev/companion/companion.sqlite`：

- platform_meta：`qzone-inbox:v1:<AI QQ>` 保存基线与轮询状态，`:policy` 保存开关。
- platform_events：`qzone_comment` 保存原件引用、作者、来源哈希和有限正文。
- platform_operations：`qq_space_reply` 保存模型提案、目标核验、dispatch、回执及观察结果。

不保存页面图片地址、Cookie 或原始网络响应；回执诊断沿用白名单类型和哈希。迁移整个实例会保留基线、来源与提交去重记录。

主用户可用 `friend_qq_space_inbox` 查看/切换监测开关；`friend_platform_status` 包含 spaceInbox 状态，`QQ-Operations.cmd` 查看指定回复操作。所有开关仍受总平台写开关与 Test 实例禁用约束。
