# 模型交接与工具回执诊断（0.57.0）

修复记忆审计中确认的 P2：模型请求工具的正常 tool-calls 被旧采集器归为 failed，导致诊断失败次数和“活动与选择”的异常列表失真。

## 分类含义

| 记录 | 含义 |
| --- | --- |
| handoff | 完整消费了带工具块的模型流，模型交给工具处理；工具是否成功另看结果 |
| completed | 模型流正常 stop；不等于整轮对话、审核或平台送达成功 |
| limited | 模型输出达到上限 |
| cancelled | 调用取消或模型返回 aborted |
| interrupted | 运行中断，原结果尚不能确认 |
| incomplete | 没有结束帧、消费者提前退出，或 tool-calls 缺少工具块 |
| failed | 真正的流异常、错误结束或流协议异常 |

unsuccessful 保留“失败/取消/中断/不完整”的合计，并另给 failures、handoffs、limited 等分类，避免把取消直接解释为服务故障。usage和耗时沿用原记录，不补造、不重复计算。

## 工具实际结果

工具诊断来自 DSH 公开 session/event 的 tool/call 和 tool/result，以实际 session ID、调用 ID 及事件序号关联。tool/result.message.isError 为 true 时保留“工具返回错误”；非错误结果只说明工具返回，不证明工具正文里的业务成功、平台送达或对方已读。

新增 diagnostic_tool_calls 位于原 runtime/dev/companion/companion.sqlite，仅存名称、标识、序号、时间、结果标志及可核对的模型调用关联，不存参数、输出正文、完整异常或提示词。调用缺失时明确标为 result_only，不虚构工具名称或模型关联。重复事件不重复计数；结果一旦记录不被第二份冲突结果覆盖；跨会话和后来复用的 call ID 分开处理。

同现有诊断一样，默认保留30天、每表最多20000行，清理仅删除诊断元数据；后台不因此重试工具。禁用采集则不记录新事件。构造时的未结束诊断标为 interrupted，不重放实际工具。

## 旧记录与可视化

只将旧 status=failed 且 error_kind=tool-calls 这一个组合解释为 handoff，返回 rawStatus、rawErrorKind、legacyCorrected，原行及tokens不改写。这不证明旧工具执行成功，旧工具回执不会被补造；实际错误工具仍以原会话或已有操作回执为准。

DSH → 记忆系统 → 自我与成长 → 活动与选择 → 资源、冷却与模型调用，分别展示“近期模型流异常”“近期模型流与工具交接”“实际工具回执”。查询只读，不唤醒任务、不调用模型、不发送消息。

## 验证与迁移

验证覆盖完整交接、真实工具错误、截断、取消、进程重启、消费者提前退出、流协议异常、只读旧分类修正、跨会话关联、重复事件、敏感正文不入库、保留策略和页面展示。真实验收读取原诊断、确认统计分类和旧行保留；不要求用户制造错误或发送测试消息。

本版只在既有数据库增加一张诊断表和两个索引，无第三方依赖、无新数据目录，沿用完整 runtime 备份迁移。安装前做一致性快照并保留代码副本；旧版不读取此表，完整回退以部署快照为准。记忆正文、人物画像、自我状态和行为选择策略不由本次修复更改。
