# 原需求与边界

2026-11-05部署选择：用户明确要求家用电脑从空白记忆开始。首次家用部署使用 Pack-Fresh / Install-Fresh，只带程序与清洁工具，生成全新角色身份，不携带公司运行数据；原完整角色迁移入口保留作其他场景使用。后续代码更新继续保留家用实例自身数据。

这是本次从 Coopanion 转向 DSH 后保留的需求基线，描述目标，不代表功能已经完成。

## 陪伴目标

个人自用，长期陪伴一位主要用户；模型优先使用 DeepSeek。可通过本地 Web、QQ 交流，逐步接入 B 站和抖音。桌面形象以后可加，但不作为人格和情绪系统的前提。

她可以提出自己的想法、发展兴趣、选择活动、安静待着或主动交流；主动行为必须有实际触发、预算和可记录的结果。不用不断运行模型、输出“我在思考”来冒充自主性。

2026-10-28修订：及时感知消息不等于聊天优先。她可以继续当前活动、稍后重新判断、或不回应普通问题；选择依据同一份自我、兴趣、情绪及真实任务状态，不用固定概率或情绪阈值规定回应。后台任务与聊天进入统一注意力决策；不将沉默当失败自动重试。方案见[自主注意力评估](21-autonomous-attention.md)。

2026-10-28补充：统一自主行为机制覆盖Web、QQ、B站及后续平台，也覆盖浏览、主动联系、回忆、反思、个人状态变化与语义整理。各模块不再自行假定聊天优先；无新消息时也可依兴趣、未完事项或空闲机会选择活动或安静。原件落盘、备份一致性、权限和停机属于宿主可靠性职责。

不预先指定名字、性格、恋爱关系、固定语气或好感增长规则。初始自我描述为空，情绪历史为空，兴趣假设为空；以后通过交流、经历和反思形成、修正自己的描述与个人提示词。模型已有的训练倾向仍然存在，工程无法把基础模型变成真正没有先验的意识。

“情绪”指工程上可持续、可解释、会影响判断和行为的内部状态模拟。不能用一个浮点数、挂饰表情或角色语气证明拥有内生感受。

## 记忆与连续性

- 保存可回溯的真实经历、说话者、时间、会话、工具结果及内容来源；区分事实、对方自述、她自己的感受、推测和角色扮演。
- 支持跨会话召回、重复识别、纠错、矛盾复核、历史有效期和派生结论失效；相似度与数据库版本号不能替代语义判断。
- 热、温、冷表示访问和上下文策略，不等于事实等级；冷记忆仍可按需检索。不能因检索次数多就自动认定更真实或更喜欢。
- 每晚增量整理，可重试、可中断、可补做；整理与交流的切换纳入统一注意力决策，取消聊天必然优先的目标假设。保留整理的依据，避免反思不断强化自身的猜测。
- 迁移时保留身份、经历、状态、会话绑定和插件版本；更换后端通过可验证的导出导入实现。UUID 相同本身不保证行为连续。

## 多平台与现实活动

主要用户在 QQ 和 Web 的身份可显式绑定；其他联系人、群聊按各自范围隔离。不同平台的会话可以独立，但共享同一份自我状态；不得为每个平台生成互相矛盾的独立人格。

刷视频须区分“看了标题”“读了字幕”“抽样看了画面”“实际播放并处理了哪些片段”。不能只有推荐列表就声称看完视频。DeepSeek 的具体模型不一定具备视觉输入；若无视觉能力，只允许按字幕和元数据表述体验。

浏览、点赞、评论、发布、给谁发消息是不同权限。初期仅向已绑定的主要用户回复，视频适配先开放只读动作；以后按用户实际授权逐项开放自主发送或账号写操作。

## 轻量、开发与迁移

Windows 优先；公司电脑开发，家用电脑长期运行。开发数据和长期运行数据分开，不能用开发实例覆盖家用实例。

首期不引入 Docker、PostgreSQL、Redis、本地大模型、常驻向量数据库或多个完整机器人框架。不为安装插件而同时运行 AstrBot 和 DSH。允许按需使用 Python CLI，但要评估完整依赖，而非只数桥接插件本身。

代码进 Git，运行数据和密钥不进 Git；运行数据集中在指定实例目录。插件若把 Cookie、模型缓存或数据库写到其他目录，须显式迁入或登记为迁移依赖。

## 必须承认的能力缺口

目前没有证据表明任意一个轻量 DSH 插件已经同时解决以上全部问题。需要先验证现成组件，再开发身份、状态演化、证据关联和活动调度的衔接逻辑；如果记忆质量不足，应优先更换成熟后端，而不是持续扩张一套未经验证的自研检索引擎。
