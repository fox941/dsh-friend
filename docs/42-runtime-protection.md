# 运行保护与恢复

2026-10-30；companion-adapter 0.29.0，attention-scheduler 0.2.0，架构 v0.31。

## 职责

在原 DSH Host 之外增加轻量 Node 保护进程；复用系统进程、命名管道和现有数据库，只负责技术故障。无新模型调用、第三方守护框架、网络服务或数据库。角色依然通过原统一注意力决定继续、切换、暂缓、沉默或休息。

数据链路：平台事件 → 原适配器 → 原统一注意力/模型 → 原执行器。技术链路：保护进程 → 经过令牌核验的本地控制管道 → 只读健康提供器。健康数据不进入人格或聊天提示词。

Host 的健康提供器是本插件新增的公开子路径 runtime-health。它读取内存中的实际流进度和本地状态，不发平台请求。内容只含 UUID、存储可读性、连接核验标记、接收失败次数、模型阶段及进度时间；不含聊天正文、提示词、模型输出、密钥或 Cookie。不更改 DSH、Mnemon、NapCat 或 whale 的源码。

## 检测与恢复边界

每 15 秒检查一次。QQ 连接异常给予 90 秒重连缓冲，再提示检查 NapCat 与账号；B站连续接收失败或未绑定时提示检查网络/登录，不把所有网络错误判为登录失效。已有平台适配器继续自行重连/轮询。保护层不代为登录、补发消息、重放外部写入，也不重置平台游标。

模型流每次产生真实 chunk 都更新内存进度；累计运行很久不等于卡死。180 秒没有新进展只表示“可能等待服务”，仅提示检查，不取消请求、不强杀 Host。五分钟内三次 stream_error 提示检查接口；max-tokens 仍属于原预算诊断。静默、排队、等待事项和正在看视频均不作为故障指标。

确认记录中的进程已经退出、或没有 Host 记录时，才考虑启动；启动前核对持久身份 UUID、数据可读、端口空闲、没有存活的运行/离线维护锁及未完成撤销。进程还活着但无响应、PID 被复用、记录归属不符、原数据缺失或身份变化时保留现场。任何未知进程都不会被强杀。

十五分钟滚动窗口最多三次启动尝试，退避 10/30/60 秒；实际周期受到 15 秒巡检间隔影响。额度持久保存，守护进程重开不清空；窗口届满后可再次尝试。Recover/Restart 是明确的人工重试入口，可重置额度，但仍须经过身份、端口和锁检查。

手动 Stop 先持久写入“停止且关闭自动恢复”，再请求 Host 优雅停止。优雅停止失败会报告错误并保留进程，自动恢复仍保持关闭。保护进程意外退出不会杀掉 Host；下次 Start 可接管同一已核验实例。目前不注册 Windows 开机任务，电脑重启后需要手动 Start。

## 操作入口

- Start-Dev.cmd：启用保护，启动或接管原实例，打开现有 Web 页面。
- Stop-Dev.cmd：关闭自动恢复并优雅停止 Host；备份、升级、离线撤销前使用。
- Runtime-Status.cmd：查看当前实测 Host/通道状态、守护是否运行，以及最近一次巡检和事件；历史快照有 checkedAt，不等同当前测量。
- Restart-Dev.cmd：关闭自动恢复 → 优雅停止 → 经检查后启动；不清空角色。
- Recover-Dev.cmd：保留存活实例；若已退出则解除重试冷却/额度再检查恢复。

也可通过 scripts/AiFriend.ps1 -Action Start|Stop|Status|Restart|Recover -NoBrowser 使用同一入口。npm 的 start/stop/status/restart/recover 也转向 scripts/runtime.mjs。底层 host.mjs 保留作诊断/首次人工初始化入口，正常使用应走统一入口。

本保护版本以已有持久 UUID 的实例为对象；没有身份数据库时保持阻止状态，不把数据丢失当作第一次启动去创建新角色。全新空白部署的首次初始化需要先按原 host.mjs/initialize-memory.mjs 初始化一次；本次没有做新电脑安装向导或迁移打包。

## 状态保存与通知

runtime/dev/operations/state.json 保存期望运行状态、原 UUID、重试时间；status.json 保存最多一百条运行事件和最新状态。guard.json 保存机器相关 PID/管道令牌，属于本机临时控制文件，不放入备份；status.json 也属于可重建的状态快照。完整迁移仍应停机并复制完整 runtime 数据，不单独复制记忆库。

只在故障状态变化、恢复时通知，使用 Windows 自带 NotifyIcon 提示；系统可能压制或延迟气泡，不能保证用户看见，Runtime-Status.cmd 和状态文件可供检查。不会经 QQ、B站或邮件给其他人发送通知。

离线撤销和备份/安装器都检查保护进程，避免 Host 临时退出时后台又启动。离线撤销继续持有与 Host 共用的独占 host.lock。备份继续在开始/结束检查进程状态并逐文件校验一致性，失败快照不会报告成功；没有引入在线热备份。

## 恢复的实际含义

这里的恢复是“用同一个 runtime 重开原进程”。任务是否能从具体步骤继续，取决于原执行器已有的持久检查点和回执；原来需要人工确认的未知结果仍保持未知。保护层不把所有中断任务无条件重做，因此不能保证所有长任务都自动完成。

## 实现依据

Node.js 原生 child_process/spawn 与命名管道；Windows 通知采用系统 NotifyIcon.ShowBalloonTip：
https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon.showballoontip?view=windowsdesktop-9.0
。技术监管独立于角色决策，没有接入第二套 agent 调度器。

验证详见 .work/runtime-guard-release.json 与 .work/runtime-guard-compat.json。故障测试使用独立假 Host、临时 SQLite 与模拟时钟；真实 DSH/Native/DeepSeek 的隔离联调单独记录，均不代表已经连续运行多天。
