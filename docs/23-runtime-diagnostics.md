# 运行观察与行为诊断

2026-10-29，陪伴插件0.16.0，架构v0.18。继续使用现有DSH与Mnemon/Native。

## 使用

- 双击项目根目录的Diagnostics.cmd，查看最近24小时摘要。
- `scripts/Diagnostics.ps1 -Hours 72 -Json`查看最近72小时JSON报告。
- 在主用户Web或QQ会话中调用friend_diagnostics_read，可传hours、limit和intentId；intentId筛选该事项的状态历史。

本地入口在DSH停机后也能只读查看已有统计。读取不调用模型、不推进意图、不刷新情绪或增加记忆。让AI解释报告本身仍属于一次正常聊天，模型表达所需调用会照实计入。

## 记录哪些内容

1. 意图状态：新事项、选择、暂缓、按时间/新事件/任务结束唤起、执行、暂停恢复及结束。保留ID、状态、等待条件和短理由，不复制原始消息载荷。
2. 调用统计：通过DSH公开llm/stream接口被动观察选择、交流生成、情绪审核、反思、成长、记忆和活动调用；利用官方请求标记区分会话表达和未分类辅助调用。不改请求、不提前读取模型流、不新增模型判断。调用统计保存路由、阶段、时间、tokens及有界请求指纹，不保存提示词、消息、输出正文、凭据或内部推理。
3. 风险线索：长时间无进展、反复暂缓、相同请求多次出现，以及情绪原件缺失、引文不匹配、来源含不保存措辞、纯反思强化等可核验异常。没有自动修复、删除或优先回复。

一次模型流正常结束不代表提案被接受，也不证明平台已经发送。公开回复是否可见继续以原发送回执和游客读回为准。主动沉默不是技术失败；等未来事件或等待时间未到，不按漏回复处理。

## 用量与覆盖范围

inputTokens为未缓存输入，缓存读取/写入单独计入；reasoningTokens已经包含在outputTokens中，不重复相加。累计usage帧取最后一次报告。未报告用量保留未知，不当作零费用。耗时统计为本机观察到的流消费时间，不是模型服务器独立执行耗时；P50/P95最多使用时段内最近5000条有效耗时样本。没有内置货币价格推算。

诊断从本次升级开始采集，旧模型调用和旧状态变化不补造；已有队列和情绪历史仍能作为当前状态检查。报告明确标识采集起点、保留范围和不完整覆盖；采集起点不代表电脑从那时起一直在线，也不能据此累计真实连续运行天数。长文本/多模态请求超过指纹预算时跳过指纹，相同指纹也只是需查看的候选，可能属于合理重试。

情绪检查最多查看时段内最近1000个版本，未完事项最多100个，完整时序可按intentId查询。检查不能自动裁定反讽、引用、否定或感受是否自然；不保存措辞可能来自引用，须结合已有friend_emotion_history等接口核对原件。它不代替人工语境评价，也不把模型自评分数视为客观准确率。

## 存储与职责

所有记录在runtime/dev/companion/companion.sqlite中的diagnostic_meta、diagnostic_model_calls、diagnostic_intent_events。默认保留30天，每日清理时两个记录表各限制到最近20000条。配置diagnostics支持enabled、retentionDays（7–90）、maxRows（1000–100000）。清理只涉及诊断记录，不处理情绪、长期记忆、原始聊天、平台回执或实际意图。

记录失败会保留当前进程的错误计数并放过原模型流；它不构成零开销或绝对不受磁盘故障影响的承诺。进程中断时未完成的调用标记interrupted，无法确定的耗时与tokens不补估。仍使用现有停机备份和完整runtime迁移，无新数据库服务、监控平台或常驻人格。
