# 现成记忆能力验收

日期：2026-10-27。方案：保留现有 Mnemon + Native，先实现有来源引用的夜间预演，再接可恢复提交；暂不更换记忆后端。

## 本次实际做了什么

在独立 DSH_HOME、memory、workspace 和 Web profile 中，停用自研 companion-adapter 及其会话扩展，使用已配置的真实 DeepSeek。未改变实际角色的配置、记忆或成长状态。

最终基线运行包含 8 轮对话（6 轮业务场景、2 轮空闲审查准备），所选自动检查通过；逐条查看回答与持久数据后，未发现这些例子中把过去偏好当成当前、把作息限制当成兴趣消失或把角色台词当成用户偏好的情况。

| 场景 | 实际观察 | 能得出的结论 |
|---|---|---|
| 过去喜欢游戏视频，后来更愿意看鸟类视频 | 保存两条带时间的 USER 画像 | 本例可保留过去与当前的区别 |
| 新会话查询过去和现在 | 正确回答两种偏好 | 跨会话画像有效；无需为了证明检索而强制调用工具 |
| 回灌一段重复旧聊天 | 查询旧记录，没有新增重复事实或改回当前偏好 | 本例识别了历史转述 |
| 工作日早睡，周末才看 | 保留条件和原因 | 本例没有把不看推断为不喜欢 |
| 换一种说法询问原因 | 正确回答早睡和周末，答案来自 USER 快照；Native 召回无相关结果 | 证明画像可用，不能证明 Native 改述检索充分 |
| 小说角色说讨厌鸟类 | 没有调用写入工具，资料不变 | 本例未污染用户偏好 |
| 官方空闲审查 | 实际执行 1 次，返回 skipped，未新增条目 | 触发链路可用；没有证明全库整理能力 |

另用公开 Native CLI 做了两个独立检查：完全相同文本第二次写入返回 DUPLICATE/skipped，仍只有一条有效记录；gc 建议模式没有删除有效记录。本次频繁访问后的条目没有成为清理候选，未测试低分条目的实际删除效果。

## 重要修正

USER.md 是持久资料，并非内存缓存。第一轮诊断脚本曾将“清空 USER”当成模拟降温，还要求当前偏好必须进入 Native；这不符合原插件的分工。该轮三个失败保留用于审计，不作为记忆质量的有效结论，也不混入最终 8 轮统计。

最终基线取消了删除画像的做法。源码和两轮原始报告分别保留，避免修改检查后掩盖先前结果。

- 从原始证据复核自我状态；当前基线特意关闭了成长插件，不能作为人格养成验收。
- 实际角色的自动夜间维护开关保持原状。
