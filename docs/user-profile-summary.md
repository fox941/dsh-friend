# 常驻用户画像维护与统一展示（0.43.3）

本次复用 Mnemon Runtime Source 和既有受保护应用管线，在 companion-adapter 内增加轻量协调层。DSH、Mnemon、QQ桥接、B站插件的源码不作修改。

## 从哪里看

刷新 DSH 网页，进入「记忆系统 → 人物画像」。页面通过 Mnemon 公开的 `installMemorySourceUI` 扩展点注册，包含：

- 常驻摘要：真正存在于 Runtime `target=user` 的条目。
- 来源事实：当前绑定主用户的已审核称呼、习惯、兴趣和偏好；保留 QQ/B站/主会话来源、原话、人物或场景适用范围、公开边界。
- 维护记录：自动维护、已有同文条目、未选为常驻、待核对、后来被改写、撤回或撤销等状态及应用批次。

原「运行时记忆 → 用户画像」卡片仍读取同一 Runtime 数据，新增常驻条目后这里也会显示。新页面是只读视图，点击刷新不会触发模型审核或修改记忆。数据走 DSH Connection 已认证的共享 Fetch 接口（精确 GET 路由，仅主用户可读）；没有另开公开 HTTP 画像接口。

## 数据放在哪里

| 数据 | 文件 |
| --- | --- |
| 常驻画像的事实源 | `runtime/dev/memory/runtime/memories.json` 的 `target=user` 条目 |
| Runtime 生成的上下文文件 | `runtime/dev/memory/runtime/USER.md`，不要手工编辑它 |
| 社交原件、审核、版本及摘要维护关联 | `runtime/dev/companion/companion.sqlite`，新增 `profile_summary_state` 表 |
| 原长期记忆 | 原 QQ 社交库、Mnemon Native 等原位置；不搬走、不删原件 |
| 一致性快照 | 原 `runtime/dev/companion/protection/snapshots`，沿用既有保留策略 |

`profile_summary_state` 保存来源标识、指纹、维护状态、对应 Runtime 版本和应用批次。它不取代原始记忆；字段 `origin` 仍保留 Runtime 原本的跨机器含义，未滥用来标记 QQ/B站来源。迁移仍携带整个原实例 `runtime/dev`，不要只复制 USER.md 或某一个数据库。

## 什么时候更新

每 60 秒检查一次；只在前台模型、平台操作、观看、夜间整理等没有忙碌时工作，每轮至多处理一个来源，最多维护 8 条摘要。没有额外守护进程，也没有新增独立模型供应商。

1. 从既有完成审核的记录读取类型化事实；QQ 历史偏好兼容已有 `profileRule`。
2. 用绑定 QQ/B站账号识别主用户，拒绝按昵称或“我是主人”的口头主张关联身份。
3. 只选择人物范围的稳定称呼、偏好、习惯、兴趣。场景专用称呼、一次性经历、禁止保存或补收资料不提升为常驻。已有核心 USER 原条目不再复制。
4. 独立模型仅选择是否值得常驻，可以否决。正文由程序在已审核原记忆前加「关于主用户：」，不允许模型在此环节创造或改写事实。
5. 复用共享应用审核额度（默认每日30次）、现有输出上限与 Runtime USER 容量（默认4KiB）。同一版本不反复审核；同义重复由筛选模型否决，同文已有条目不接管。
6. 写入前检查来源、建立并验证一致性快照；快照后及落笔前再次核对来源。通过 Runtime 公开维护计划和修订号 CAS 写入，自动生成 USER.md。
7. 持久化执行回执，并把 Runtime 写后版本关联到来源。中断后核对固定计划和回执，不重放聊天、不伪造源消息、不强制重跑模型。

## 更正、撤回和手工修改

- 原记录确认撤回、关闭、更正或变为局部适用后，只处理由该来源维护且版本仍未变化的摘要。
- 原 QQ 版本链可跟随到新的已审核记录。替换被模型否决时移除已经过时的旧摘要，不把旧事实悄悄留作当前画像。
- 来源暂时读不到、接口失败或核对不完整：保留摘要、显示待核对，不根据网络失败删除记忆。
- 摘要正文或版本被后续对话、页面等入口改过：停止接管，保留后续值，即使后来来源撤回也不覆盖它。
- 相同常驻条目早已存在时，记录“已有”，不获得其修改或删除权。
- 撤销某次受保护应用后，同一来源版本不自动重建；按原保护模块的条件和离线流程撤销。页面只展示批次，不新增绕过保护的撤销按钮。
- 容量不足不压缩、删除其他用户画像；前置备份失败则暂停该批写入。

## 边界

常驻 USER 供本实例主用户私聊使用。公开群聊、空间和 B站回应仍走统一画像原有的场景和公开授权过滤，不因进入 USER 就获得公开权。其他好友不会成为主用户，也不会把自己的偏好写进这份 USER。

本版是有上限的来源视图：当前最多扫描200条QQ、100条B站和100条主会话类型化记录；不是所有聊天原文的全量导出，也不对全部旧经历重新猜测人物偏好。B站只支持已有明确 profile 元数据且原 Native 内容仍匹配的事实。来源分支有冲突或无法严格核实时暂缓，不做语义合并。

Runtime 与 companion.sqlite 之间不是跨文件事务；固定计划、快照、指纹和回执用于恢复与保守拒绝。极端中断或写后指纹缺失可能需要人工核对，优先保留原件和后来修改。
