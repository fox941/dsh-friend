# 夜间记忆整理：验收结论与开发计划

更新：2026-10-27。状态：现成能力基线已验收，阶段 A 的手动只读预演已在 0.3.0 实现，见 [10-memory-preview.md](10-memory-preview.md)。阶段 B 的手动可恢复提交已在 0.4.0 实现（见 [11-memory-application.md](11-memory-application.md)）；阶段 C 的受控夜间触发已在 0.5.0 实现（见 [12-nightly-memory.md](12-nightly-memory.md)），真实实例的 Idle Review 仍关闭。

## 1. 本次决定

继续采用 DSH 0.2.1-rc.3、dsh-mnemon 0.5.36、Mnemon Native 0.2.13 和 deepseek-flash。不因后台整理的缺口立即更换记忆后端，也不同时启用两个完整记忆系统。

通过外部 companion-adapter 扩展增量维护。复用现有记忆 Sources、公开读写接口和容量维护；自研范围包括持久任务、来源关联、语义整理提案、成长状态复核及跨层更新的恢复。

“协调层”不是只有定时器。语义整理仍需模型判断和实测；相似度、时间衰减和一次复核均不能证明一个认识正确。若关联记忆召回或证据整理无法通过案例验收，应先隔离比较 Mneme/Hindsight 等后端，再决定替换或适配，不持续扩张自研检索引擎。

## 2. 本次实测得到的边界

- 在独立实例停用 companion-adapter 和会话扩展，使用现成 Mnemon 与真实 DeepSeek，完成 8 轮对话。6 轮覆盖记忆场景，另 2 轮构造空闲审查检查点；所选检查通过，逐条查看了回答和实际存储结果。
- 用户偏好主要进入持久 USER 画像。跨会话保留过去/当前区别、条件与原因；本组改述回答主要来自画像，因此不能算作 Native 语义检索质量通过。
- Native CLI 对完全相同文本返回 DUPLICATE/skipped，仍只有 1 条有效记录。初始 Native 条目是明确标注的主机测试夹具，不计为模型自动写入。
- 隔离实例实际执行 1 次官方 Idle Review，返回 skipped，未新增条目。不能据此宣称它做了全库合并或遗忘。
- gc 默认是建议模式。本次只读取候选，未运行 forget、keep 或 compact；有效记录 ID 未变。本次没有候选，不构成低分记忆清理效果测试。
- 重启保留了 Native 记录；两个测试 Host 均停止。真实 memory 和 companion 文件指纹前后相同。

首轮诊断错误地用“删除 USER 画像”模拟降温，并把用户偏好必须进入 Native 当作检查要求；这与既有 Source 分工不一致，其 3 个失败不能作为插件记忆质量结论。原始诊断记录和脚本分别保留，不混入修正后的结果。

## 3. 数据与写入规则

| 数据 | 保存方 | 维护约束 |
|---|---|---|
| 用户身份、当前偏好、交流约定 | Mnemon Runtime USER | 是持久资料，不作为可随意清空的缓存；遵守既有压缩与隐私边界 |
| 当前工作事项和简短规则 | Mnemon Runtime MEMORY | 复用容量维护；移出前核实保存去向与回执 |
| 历史经历、事实、关联条目 | Mnemon Memory Spaces / Native | 使用公开接口读写；保留来源引用、事实时间和变化依据 |
| 自我、兴趣、特质、个人表达偏好、情绪历史 | companion.sqlite | 继续走版本与审核流程；事实变化后复核依赖 |
| 夜间任务、游标、批次、待写操作、预算、审计 | companion.sqlite 新增独立表 | 增量迁移，不重建身份或覆盖旧表 |

同一内容可以在不同层有受控投影，但必须能指回同一原始事件。不能把多份投影算成多条独立证据。

事件时间、系统读取时间与事实的生效区间分开记录。缺少确切时间时保存原文与不确定性，不用 SQLite created_at 冒充事实发生时间。

重要经历保留情境、实际选择/回应和结果；不要求保存模型隐藏推理。摘要和日记是派生记录，不替代原始来源。

## 4. 开发顺序

### A. 先实现预演模式（基础版已完成）

1. 通过 DSH 公开的持久会话接口读取允许范围内的真实事件，固定本批上界，按会话游标取新增部分。
2. 区分主用户消息、助手实际回答、工具观察、定时投递、检索注入与摘要；复核原始说话者和来源，不把它们混成用户自述。
3. 复用 Mnemon 查找相关记忆，再让模型给出有引用的整理提案。输入和候选有界；缺少相关证据时暂缓。
4. 给出保留、重复、补充、时间变化、冲突待定、退出常驻建议，以及需要复核的自我状态。每项引用原始会话、消息、时间、旧条目与预期版本。
5. 预演阶段保存任务和提案报告，不自动改变真实语义记忆或人格状态。

先用隔离资料确认提案质量，范围包括无明确日期的偏好变化、条件偏好、否定/讽刺、旧资料回灌、重复总结与相互矛盾的叙述。相关旧记忆未召回时，不能将提案判为“全库无冲突”。

### B. 再实现可恢复的提交（手动基础版已完成）

- 程序验证来源引用、逐字引文、旧值摘要与版本；模型只能提出操作，不能自行选择数据库路径或扩大权限。
- 一个角色只有一个受控写入队列。提交前再核验旧值，冲突时重新读取；前台交流优先，正在审核的批次可取消或延期。
- 跨 Mnemon 与 companion 的修改先写持久操作记录，再执行公开接口、核实回执、提交派生状态和批次结果。它不是跨库原子事务。
- 结果不明的写入先核对目标记录，不盲目重放。只有已确认处理或已持久保存待定结果的来源才能推进游标；未确认写入保留恢复记录。
- 原始事件 ID 去重；同一事件的召回、改述和夜间总结不得重新增加兴趣/性格的支持数。
- 事实更正触发相关投影与自我状态复核；不能只改一个 Native 条目就宣称所有派生结论一致。

直接成长工具仍只允许本轮主用户来源。应用审核新增了宿主核验的历史原话入口，并分开保存本轮应用授权；不伪造“本轮用户消息”。自动夜间入口已以独立宿主授权实现，不伪造新用户消息。

### C. 接受控夜间触发（第一版已完成）

- 建议默认时区 Asia/Shanghai、凌晨 02:00，可配置；自动启用前完成公开接口原型与隔离重启验收。
- 实际安装的 DSH schedule 是绑定会话的持久提醒投递，不能直接当作任意后台回调。先验证受控维护入口/维护会话，再接触发；投递成功不代表整理成功。
- jobs 提供进程内任务查询、取消与控制，游标、预算、完成状态仍由自己的 SQLite 保存。
- 无新增事件不调用模型；关机遗漏按未处理事件补做，不为每个错过的日期生成一份重复总结。
- 限制每批输入、模型调用数、输出 tokens、超时、每日累计消耗和重试次数；失败也记账。具体默认值依据隔离测量确定。
- 官方 Idle Review 与自有夜间任务选择统一维护策略，初期维持真实实例 Idle Review 关闭，避免两套自动写入互相改写。

### D. 安装到开发实例

固定新插件版本，先备份、核对旧记忆和旧身份，再用既有官方安装流程升级。检查旧表与角色数据保留，验证可以停用新模块并继续普通聊天。

首次启用后提供按需查询的整理报告：处理了哪些事件、提交/跳过/暂缓了什么、原因、来源与恢复状态。默认不在普通聊天中反复播报后台操作。

## 5. 遗忘与人格复核

第一版采取保守策略：

- 从常驻上下文退出与否定事实真实性分开；历史经历不因当前偏好变化而被改写成从未发生。
- 对明确被更正的事实保留旧版本和依据；依赖它的认识进入待复核。
- 低频、低评分只是维护候选，不等于错误、无价值或不再喜欢；重要经历不因长期未提及自动删除。
- 兴趣和性格复核同时查找支持与反例。重复阅读自己的描述不是新支持；一时情绪不直接成为稳定性格。
- 不新增独立冷归档数据库或物理清理规则。Native 软删除会影响图边，不能把它称作完整可逆；跨层提交须另验历史保留和恢复边界。

## 6. 验收条件

除语义案例外，必须覆盖：重复触发、无新事件、重启补做、审核中断、写入已成功但回执丢失、前台并发修改、预算耗尽、升级旧库、停用和迁移。

语义结果逐项查看来源与实际写入，不能只看模型口头“记住了”。小样本通过只证明所选流程可行，不证明长期人格稳定或任意中文表达都能正确处理。
