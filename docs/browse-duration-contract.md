# 搜索选片与首窗时长契约修复

版本：companion-adapter 0.64.2，bilibili-tool 0.4.10。

## 真实故障

2026-11-04，主用户真实QQ请求“找一条还没读过、现在感兴趣的B站视频，实际读一小段”。模型实际提交了搜索主题“章鱼 镜子 标记测试 自我识别 实验”和 `durationSeconds=60`，工具返回后台请求已排队。

请求 `29262832-da74-4380-b2bb-efd7cb18438d` 随后在活动执行器前置校验失败，错误显示“本实例单窗最多60秒”，却并非60秒越界。根因是同一条件还要求 `clean.video` 已存在；搜索任务此时尚未选出具体视频。参数说明允许选片和首窗时长同时指定，执行器却不接受这种组合。

该请求没有创建观看run、观察、记忆应用或新长期条目，手动观看次数也未增加。原失败请求和对应注意力结果保留，不把“已排队”当成“已看过”。

## 修复行为

- `durationSeconds` 校验只检查有限数值、正数和当前 `windowSeconds` 上限；可用于指定视频、搜索主题、目录选片或模型自主选片。实际选出目标后，沿原观察器传给首个窗口。
- 它仍然是**首个观察窗口**的长度，不改每次活动最多几个窗口，也不等于整次观看总时长。后续继续或停下仍由原模型选择，回执报告实际区间。
- `startSeconds` 是针对指定视频的固定偏移，继续要求先有明确video，不借此扩大参数含义。
- 显式start或duration的片段请求，在媒体工具未就绪时报告未完成；不得降级成无时间范围的整份字幕读取。没有指定片段的原字幕回退保持。
- 工具说明同步明确首窗语义。没有更改上下文、模型、次数、冷却、存储结构、身份或隐私规则。
