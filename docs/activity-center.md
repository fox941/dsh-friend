# 独立活动中心

版本：activity-console 0.2.0 / companion-adapter 0.76.0 / bilibili-tool 0.10.0 / attention-scheduler 0.3.0。

最新执行边界见[活动可靠性说明](activity-reliability.md)：自动视频资源在模型选择前检查，网页/论文任务等待真实文档能力，资源等待与模型安静分开显示。下方保留各次部署的实际历史。

刷新 DSH 页面，从侧边栏「活动中心」打开。入口折叠时在「更多」中寻找。原记忆系统和 B站工作台继续保留，完整全局活动展示统一放到这里。

## 页面

| 栏目 | 用途 |
|---|---|
| 总览 | 分开展示当前执行状态、最近一次已提交的模型选择、执行事项和待办摘要 |
| 待办与执行 | 按来源、类型、原始状态查询事项；先筛选完整已有数据，再分页 |
| 选择记录 | 查模型选择及是否采用，进入对应任务查看实际后续 |
| 资源与异常 | 查各功能自己的额度、冷却、最近连接记录和模型异常 |
| 活动设置 | 按能力编辑现有探索开关、额度和冷却；保存前核对差异与版本 |

详情展示实际保存的状态转换、关联选择、视频覆盖或操作回执。模型选择开始不证明成功执行；自主暂缓、资源等待、执行失败、表达阶段沉默分别展示。全局安静没有单一平台归属，不自动记作所有平台都被忽略。当前状态与历史选择分成两张卡，避免旧安静记录覆盖当前实际情况。

总览仍是有限摘要。事项与选择的完整列表可翻页，单页24条；详情的转换和关联选择沿用已有记录窗口，不声称还原全部历史。缺少关联或来源时保持未知。

## 与原页面关系

记忆系统「自我与成长」中的原栏目改为「活动中心入口」，保留记忆、画像、感受、自我认识及经历页面。B站工作台移除重复的全局选择卡和记录列表，保留 B站任务、消息、操作和配置，以及筛选到 B站活动的入口。视频详情的「查看活动过程」使用原运行或连续观看编号关联；活动详情可返回 B站工作台查看原任务。

B站「自动活动准入」是原自动决策计数，和全部全局行为选择次数分别展示。探索计数仍在观看阶段前预留；它不等于成功观看次数。本次页面抽离没有改变原额度、冷却、模型选择规则或失败计数方式。

## 职责与扩展

新插件源码在 `plugins/activity-console`，负责只读服务注册、HTTP 查询承载、原生页面、通用卡片和导航。companion-adapter 在自己的受控读取器中解释原调度记录、平台回执与资源；attention-scheduler 继续持有执行与选择逻辑，QQ/B站插件继续执行实际操作。

复用原 `runtime/dev/companion/companion.sqlite` 中的 attention_*、已有活动与回执；没有第二份数据库、人格或长期记忆。页面不会生成新的角色身份。迁移沿用完整 runtime 与匹配代码版本，安装及代码更新清单已包含新插件。

新功能向统一调度器提交事件后，其类型自动显示。新增平台通过展示服务注册来源名称，并由适配器提供真实结构字段 channel；不需要复制一套页面。来源注册不授予平台能力。扩展接口见 `plugins/activity-console/README.md`。

## 更新与权限

可见页面每20秒只读更新；隐藏、详情打开或正在筛选时暂缓自动刷新。仅 owner 可读；页面与详情不唤醒任务、不做平台轮询、不调用模型，也不发送消息。管理操作继续由各功能原入口处理。

本次不处理此前发现的兴趣状态键校验失败、外部论文任务误入B站视频流程和额度耗尽后的反复选择；这些属于执行/选择层的问题，活动中心帮助区分原因，但不会自动修复或重试。
