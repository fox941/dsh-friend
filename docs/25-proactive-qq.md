# 主动QQ联系与分享：0.18.0 / 架构 v0.20

此模块继续使用原 companion-adapter、DSH、统一注意力、QQ绑定和同一个 companion.sqlite。没有新增服务、依赖或独立人格，没有修改上游源码。

## 从真实活动到联系机会

实际阅读完成、主用户相关目标完成、已有资料召回或内部反思，可以形成主动分享候选。不是每个候选都必须说，也没有固定“每天几点发几条”。统一注意力决定是否关注；表达阶段还可选择send、defer或silent。普通聊天和主动联系没有机械优先级。

来源带稳定键与原件哈希。浏览须有实际活动和观察原件；仅字幕范围不能称看完整视频。不保存/测试来源、明确learn=false的只读任务不产生候选；召回要求原记忆token仍有效，已知他人的B站私信记忆被剔除。内部反思标记为想法，不能作为外部行动。目标进展须有本目标实际步骤回执，并检查主用户归属。

首次安装只处理启用后的完成机会，不把多年旧资料一次性补发。复用attention_checkpoints记录完成通知，并有增量游标补查。默认最多20项等待机会，超额不会删除原活动或记忆；只是不无限积压主动出站机会。

## 选择、表达与核验

被选择后读取同一自我、情绪、目标、近期可使用的主用户消息和已发记录。先生成自然表达或决定不发/延后；确实决定发送才调用独立出站核验。核验检查表达依据、范围、隐私、未知链接、虚构经历和提前宣称成功。它检查内容，不另扮一套人格。

暂缓只保存原件和重新考虑条件，不保存定时发送正文。QQ未验证登录时，在生成正文之前等待qq_ready。收到新消息、状态变化、来源改变或连接变化，旧稿作废。发送器排队后仍再核验一次；正文准备后超过90秒不发送。

默认主动消息最短间隔300秒，是防刷屏资源保护，不是每五分钟必发；可在profile的friend-adapter.config.proactive中设置minIntervalSeconds（30–86400）、sourceTtlSeconds（默认86400，300–604800）、maxPending（1–100）。来源机会过期不补发；以后真正回忆到旧内容，仍可以成为新机会。不会改变普通QQ和B站事件回合额度。

## QQ发送和结果

复用QQController原有连接、实际账号验证及绑定主用户，新增共用的串行文字发送入口。普通回复和主动分享不会并发向协议端提交。主动发送只持有bindingId，不接收任意收信人、群号、NapCat通用方法或消息段。

主动发送不创建假的qq_inbox或DSH用户消息。准备、sending、sent/unknown分别留痕；OneBot返回可核验消息ID后才记sent。这表示协议端确认发送，不保证对方实际已读。网络提交后失去回执或发送途中重启记unknown，保持不自动重发；可只读查看记录再人工核对，不提供盲目重试按钮。提交前停机则丢弃草稿，恢复后重新选择和生成。

精确相同正文在已发、发送中或结果不明时不重复发送；原件稳定键防同一阅读结果多次变成主动机会。近义重复仍依赖模型结合近期已发记录判断，不保证所有语义重复都被机械识别。核验拒绝、主动沉默、过期和未知结果分别记账，不把技术拒绝伪装成角色选择沉默。

## 后续聊天与记忆关系

后续已核验的主用户QQ聊天会取得最近三条真实主动发言，用户接着问“刚才那个呢”时能接话。friend_proactive_status支持query与limit，查询更早的已确认主动文字。

真实发送及来源、回执长期保存在本地SQLite；没有把自己的文字再次当作新用户事实、人格支持或自动写入Mnemon。原活动的学习/记忆仍由原审核链路负责，用户后续真实反馈走原日常交流流程。此版本不把每条主动发言复制进Native，避免重复强化。

## 控制、数据与迁移

在Web/QQ对她说“暂停主动联系我”“恢复主动分享”或“取消还没发送的主动消息”，模型可以调用friend_proactive_control，并逐字核验主用户明确请求。暂停不关闭普通QQ聊天；取消/暂停不能撤回已经提交的网络请求。已发历史保留。

新增proactive_control、proactive_items、proactive_attempts三张表，继续在runtime/dev/companion/companion.sqlite。完整停机runtime迁移包含这些数据；旧记忆、人格、绑定与历史不清空。Proactive.cmd或node scripts/proactive.mjs [关键词]只读查看，不调用模型。
