# 待看、跨次续看与未解疑问

2026-10-29；companion-adapter 0.24.0，attention-scheduler 0.2.0，架构 v0.26。

上一版“QQ查主用户最新投稿→实际观看→原会话接话”由主用户反馈已试用通过。本版在该路径和现有统一注意力上继续开发；没有迁移框架、增加常驻服务或修改第三方插件源码。

## 意图、进度与记忆分工

同一个 `runtime/dev/companion/companion.sqlite` 新增 `activity_browsing_items` 一张操作状态表：按BV与分P唯一，保存暂定理由、最多三项未解疑问、状态、来源、版本和校验哈希。这是“以后可能想做什么”，不构成用户事实、稳定人格或已经看过的经历。原始观察与范围仍在activity_observations，视频区间仍在activity_video_segments，长期记忆仍使用原Mnemon；没有第二份人格或长期记忆库。

意图有三类入口：

1. 主用户明确要求把原话中的BV号加入待看，工具只保存这个意图。
2. 选片时，角色从当次实际目录候选里最多保留两项稍后看；保存的标题只是元数据，未选中的视频不会变成观看经历。
3. 实际观看反思后，角色可提出继续、搁置、结束关注或放弃，以及仍未解决的问题；提案锚定当前观察原件，也允许没有新意图。

## 同一角色的持续选择

自动活动选择增加watchlist来源，模型用条目ID和当前版本选择续看，也可另找内容、换主题或休息。待看不产生额外的轮询决策器或独立人格，继续共用原统一注意力、每日探索/决策额度、间隔、媒体预算和模型调用上限。没有必须清空列表、看完整片或立刻分享的规则。

主用户的pause会留下owner暂停标记，自动选择不能恢复；角色自己搁置的事项可日后重新考虑。finished只是“这个问题或这次关注告一段落”，不表示完整观看；dropped不自动重新加入，主用户可明确resume。

全局注意力与活动选择得到有界的浏览意图上下文。默认显示8项，主用户暂停项排在可执行事项后；读取工具可显式查看最多50项。最多保留50项开放意图，容量满时只跳过新的可选意图，实际观察与原记忆审核仍继续。

## 跨次理解和进度

续看会按BV、分P和CID查询此前实际取得的原件，最多带入三份有范围的1600字符摘录，供观看与反思接续理解。无保存任务的原件不会直接作为以后自主续看的语义上下文。换CID的原件不混为同一版视频。

原观察不因再次提供给模型而成为新的独立证据。当前反思的引用、兴趣和情绪依据仍必须来自当次观察；写Mnemon继续走原来源核验、保护快照与独立审核。

视频进度使用已采样观察区间的并集，分别展示累计覆盖长度、从开头连续覆盖到的位置、最近片段末尾及有界区间列表。跳到结尾不表示中间已经观察，采样覆盖也不证明逐秒理解。三窗口用尽只结束本次活动。

## 工具和可靠性

- `friend_browsing_read`：查看待看/续看、疑问、状态和版本；可包含已关闭事项或按ID读取。
- `friend_browsing_change`：按主用户当前原话queue、pause、resume、finish、drop。queue要求原话中的明确BV，后续操作需要当前版本。它只改意图；取消正在执行的观看仍使用原活动取消工具。
- `friend_bilibili_explore`：增加watchItemId和watchRevision，与视频、关键词、目录入口互斥。QQ继续用原持久后台请求及原绑定出站通道。

变化使用事务、版本比较和状态哈希；原活动账本保存候选索引、意图回执及所选BV。已经完成的提案重放返回原回执，不能覆盖之后的暂停或修改。浏览修订也进入全局注意力的新旧状态判断。

“不保存记忆”的任务不创建或更新持久浏览意图，不写Mnemon、兴趣或情绪，仍保留原有技术观察与执行回执。“暂时不看，只加入待看”允许保存明确要求的意图。

## 验证和边界

682项隔离回归通过，包括原记忆、情绪、夜间整理、保护、QQ/B站社交、预算、视频处理，以及新增的意图来源、版本冲突、重放、无保存、候选归属、进度合并、CID区分和跨次上下文。

真实DeepSeek在隔离DSH中测试加入待看、跨会话无保存续看及主用户暂停。平台内容是隔离夹具，不向真实QQ/B站发送验收消息，不写正式记忆。本次不声称自动续看频率、长期兴趣质量或多日效果已经验证；这些继续在实际使用中观察。

本版没有接入B站首页推荐、全量关注流、批量建大型观看队列或完整逐帧视听，也没有扩展对外互动权限。迁移时继续停写备份整个runtime/dev，新表随原SQLite数据库一起迁移。
