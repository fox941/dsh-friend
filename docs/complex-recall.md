# 复杂回忆的候选筛选与原文核对（0.59.0）

沿用 Mnemon Memory Spaces、Native 和现有分层 Strategy；不启用向量服务，不增加记忆库、后台模型或持久存储。目标是让复杂问题看到足够的候选，再由同一个聊天模型判断哪些原文支持回答。

## 候选与预算

普通回忆保持每回合两次查询、最多八条结果、每次最多一条中等相关候选。多事件比较、时间线重建等复杂任务可在 `friend_memory_recall` 填写 `complexReason`（8–300字具体理由），经公开 `tools.execute` 转交本轮 `mnemon_recall`，由原 Strategy 统一计算额度。

复杂回忆每次最多接纳四条中等相关候选，每回合最多四次查询、十二条结果。首查仍最多六条、8K字符；整个回合与 Related 共用12K正文字符，每条最多2K。低相关候选继续排除，未知相关性最多一条。保留 relevanceTier 只表示 Provider 的检索层级，不表示语义已证实。

第二问法、重复调用与直接 Mnemon 调用没有额外额度。重复检索重放原证据，不重新执行以“刷出”更多候选；复杂理由不能突破当前 Source/空间许可，未授权的请求也不能先改变后续预算。是否属于复杂任务主要依赖模型按规则选择，程序只核对理由格式，无法从字数证明任务确实复杂。

## 证据链

`friend_memory_recall` → 本轮公开 Mnemon 工具 → 当前 View/Strategy → 获准的 Source/Native → 候选及本轮凭证 → 同一模型选择原文 → `friend_memory_evidence_check` → 回答。

修复了 Strategy 的具名工具输出丢失外层 Evidence 元数据的问题：`MemoryCoordinator.recall` 返回 `evidence.output`，因此 Source、View 和读取身份同时保留在该输出中。真实 Native Source 经 `Strategy.query` 的安装链路有专项验证。

引用凭证保存在进程内 WeakMap，以真实 agent、session 对象及当前原话事件位置绑定。模型不能自行提交正文、Source、账号或回合号来建立证据。最多保留十二条、12K正文，换回合、新用户消息、重启或另一个 agent 都不能复用旧凭证。异步读取期间原话已变化时，迟到结果不进入新回合。

`friend_memory_evidence_check` 每次核对1–4条凭证、逐字原文和使用方式：

- 原文不匹配、凭证伪造或过期时不通过。
- 本轮发现同一引用正文变化、或同一引用的 View 改变时，原凭证作废，冲突项移出后续候选；不会替模型选择哪个版本正确。
- 显式历史画像、外部阅读经历、更正原件不能直接用作当前用户事实。
- 普通记录即使原文核对通过，也不自动认证为当前状态；需要当前统一/常驻画像或已应用回执支持。
- 当前召回工具不可用时不输出旧引用证明。

核对器只核对**本轮已经观察的引用**，不重新读取数据库，不保证来源从读取后至回答前没有变化，也不证明引用与答案语义相符。否定、条件、人物指代和时间仍由同一模型结合完整正文判断。不能把一次 `quote_verified` 对外说成“事实已核实”。历史标记仍依赖现有格式，并非覆盖任意自然语言版本冲突的通用识别器。

## 使用范围

挂载到原主用户直接会话入口，在现有 Mnemon View 许可下使用。群、普通好友、空间和B站社交仍沿用自己的身份、人物画像与社交记忆管线；本次不向它们开放主用户私密库。直接 `mnemon_recall` 仍可使用；新引用核对只接受 `friend_memory_recall` 签发的本轮凭证。

日常自然提问即可。模型可以不查询，也可能因为线索不足未召回目标；没有依据时应说“暂时没找到”，不能把无关命中或预算用完理解为事实存在/不存在。核对流程通过工具与提示词引导，未在最终输出通道强制拦截所有回答，不承诺模型永不跳过。

## 验证与迁移

边界测试覆盖复杂/普通配额、共享额度、权限、真实 Source/Native、工具输出身份、跨回合凭证、伪造引用、迟到结果、变更冲突、历史与当前状态。全量回归及隔离实际安装包复验同时覆盖现有QQ/B站和画像更正。

实际 DeepSeek 演练只使用这次新编的虚构故事、约定、条件与否定偏好等八个问题，与此前18题本地检索样本和5题模型案例分开。测试模型自己制定检索词、选择引用并回答；不会读取或外发真实记忆，不代表真实平台聊天或通用准确率。详细结果见 `.work/recall-evidence-*`。

本次模型服务先出现两次请求超时，改用流式传输后又连续返回HTTP 503。完成两个案例：丢书经历重建、当前读书会安排；其余六例（时间线、他人偏好、条件偏好、小说角色、未应用更正、缺失地址）保留待验，不计为通过。一例初次引用选择把合成当前画像ID当作长期凭证，核对器拒绝后，最终回答使用另行提供的当前画像。验收区分初次工具调用是否正确与最终回答是否有依据；既不把被拒凭证算通过，也不要求正确的当前画像凭空取得长期凭证。模板脚本的初始“所有核对均成功”统计与修正后的分项结果均保留。

无新增持久数据或表，继续使用原完整 runtime 迁移方案。引用凭证不迁移，重启后的新问题需重新检索；长期记忆本身保持原样。
