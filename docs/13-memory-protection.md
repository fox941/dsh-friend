# 记忆保护、变更查看与停机撤销

当前 companion-adapter 0.6.0，架构 v0.8。0.6.0 最初保护的是手动和夜间“提案应用”批次；0.8.0 扩展到统一入口的日常写入，仅 Runtime 新增采用轻量快照，其余沿用完整保护。以下描述最初的完整保护，复用现有 Runtime、Native 和陪伴状态；没有修改 DSH 或第三方插件源码，也没有新增常驻服务。

## 写入前做什么

无写入步骤不创建快照。有写入计划时，在共享维护锁内，先用 SQLite 在线备份接口保存涉及的 Native 空间全库（包括原记录 ID、图、元数据），再保存 Runtime 原条目及 companion 日志库。核对完整性、文件摘要、来源版本和保护空间后，才允许继续逐步提交。

快照失败返回 `backup_blocked`，本次不继续写入；夜间任务显示需要处理，不会换其他工具强行代写。模型审核可能已经消耗额度，重试相同应用计划不重复审核。若应用已有部分写入，“未继续”不代表此前所有步骤都没有发生，需看原回执。

写完保存后指纹。它和写前快照一起界定可恢复范围。检测到批次间或批次窗口内无法归因的长期库写入时，禁止继续覆盖或整库撤销。跨库仍是分步操作，不能保证原子提交；保留检查点和结果不明的状态。

## 如何查看

聊天中说：“查看最近一次整理的改动，展开原话和受影响的自我状态，生成变更报告。”工具 `friend_memory_changes` 支持指定应用批次 UUID、`includeSources`、`checkUndo`、`html`。

可以看到原始来源 ID、时间与逐字引文、旧值、新值、自我状态前后版本、每一步回执、快照状态和撤销条件。报告是本地可展开的静态 HTML，位于 `runtime/dev/companion/reports/changes-<应用UUID>.html`；明确标注历史与生成时间，不能把旧页当作实时状态。查看不调用独立审核模型；报告查询回合不触发成长，不增加独立经历。

`ready_offline` 只代表当前预检通过，执行时仍会重新检查。历史批次若升级前没有快照，不补造可撤销保证。

## 如何撤销

1. 用变更查看确认**应用批次 UUID**，不是预演报告 UUID。
2. 运行 `Stop-Dev.cmd`，等待停止成功。
3. 在项目根目录终端运行 `Undo-Memory.cmd 应用批次UUID`。
4. 只有结果是 `completed` 才运行 `Start-Dev.cmd`。`blocked` 表示未开始撤销；若没有其他未完成撤销，可以正常启动。`partial` 表示已有检查点，继续停机、用同一个 UUID 重试。

也可用项目 Node 执行 `scripts/protection.mjs check|verify|report|undo 应用批次UUID`。这些本地命令要求停机，和宿主共用独占启动锁。撤销部分完成时，启动器和插件会拦截重启，避免聊天与恢复同时写入；不要通过删锁或删检查点绕过。

撤销规则：

| 数据 | 规则 |
|---|---|
| 涉及的 Native 空间 | 整个库的当前逻辑指纹必须与批次写后指纹一致，停机后用公开 SQLite 备份接口恢复原库，保留旧 ID 和图 |
| Runtime 常驻条目 | 逐项比较本批目标版本，用公开带版本核验的维护接口反向修改；无关新增条目保留 |
| 自我状态 | 此后不能已有新修订；恢复为新的历史版本，沿用原始支持并重接依赖，不增加证据 |
| 原始聊天、报告、审核和应用历史 | 保留；记录明确的撤销结果，历史写入不再当作当前事实 |

撤销前另外保存当前 Native、Runtime 和 companion 副本，逐步记录意图与回执。中断后读回核对，已成功步骤不盲目重写。整份 companion 数据库不会回滚，避免抹掉新聊天和审核历史。已撤销报告不能直接再应用；以后有新的原始交流时，可以重新预演、作出新更正。

## 保存在哪里和多久

快照：`runtime/dev/companion/protection/snapshots/<应用UUID>`；其中 `undo-safety` 是撤销前的现态保护副本。元数据在 `companion.sqlite` 的 `protection_*` 表，包含快照、撤销步骤和已撤销更正的索引。迁移时必须包含整个离线实例及代码、profile 锁文件与 `.friend-packages`。

默认最多保留 16 个有效快照、合计 512 MiB（含已登记撤销保护副本）。超过限额优先淘汰已完成旧批次的恢复文件，保留变更日志；不删除事实、聊天和人格版本。未完成应用或撤销的快照不会为腾空间被自动删掉，因此可能暂缓新整理。突然断电可能留下未完成副本，磁盘实际占用仍需观察。

`friend-adapter.config.protection` 可配置 `maxSnapshots`、`maxBytes`、`timeoutMs`，分别默认 16、536870912、30000。上限不是长期记忆容量；大库全量快照会增加磁盘读写、占用和等待时间，库超过保护额度时需要另定增量备份方案。

## 边界与代价

普通聊天直接调用 Mnemon 工具、管理页、外部 CLI 和其他插件的写入没有全部接管。它们之后改动长期库，通常会让旧批次不能撤销。Native 访问计数、操作日志或图变化也可能改变全库指纹；即使是无关新事实，也会保守拒绝整库恢复。此时可以读取变更证据，另走新的纠错流程，不能强行覆盖。

已有备份不证明提案内容正确；此功能防止工程性覆盖和不可见误改，不解决反讽、否定、时间条件或人格变化的全部语义判断。没有新增全量夜间扫描、自动遗忘、独立冷库、平台接入或自主视频活动。管理锁只约束本项目的受控入口；自行启动其他宿主或外部写者时，须先关闭它们。
