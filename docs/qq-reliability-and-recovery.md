# QQ 收件可靠性与近期漏收

companion-adapter 0.36.0 / qq-bridge 0.5.0。复用现有 OneBot 自动重连、统一注意力、平台事件和运行保护，不新增服务、数据表或人格决策模型。

## 健康证据

原有 WebSocket 心跳只能证明本机连接还活着；get_login_info/get_status 也可能反映缓存。新的 QQReliability 默认每三十秒核验绑定账号、业务状态和好友列表，记录真实推送、心跳、历史接口覆盖和异常次数。安静、模型选择沉默、群历史没有新内容均不单独构成故障。

接口核验通过显示 ready，表示当时这些接口证据正常，不保证上游每条消息一定已经推送。首次启动的空好友列表也不直接判成断线。若曾成功加载好友、随后连续三次变空，且没有新的业务消息到来，再核对本机登录阶段和自身资料接口；多个独立异常成立后才判断 degraded。

RPC 连续失败先受控重连本机 WebSocket，每五分钟最多一次。只有实际账号再次匹配、明确的多项业务异常、当前没有 QQ 回复或社交任务正在执行时，才可重载该 NapCat 工作进程。重载预算持久保留：默认三十分钟冷却、一天最多三次；回执未知也计数，不立即重试。错误账号不重载，不接管。需要扫码时明确显示 login_required 与 Open-QQ-Login.cmd，沿用现有运行保护的本地通知；不向外部账号发送告警。

自动检测无法凭缓存 API 完全识别所有静默故障。如果所有业务接口都返回看似正常的旧缓存，又没有外部新消息证据，不能承诺自动判定真正停止收件。此次功能旨在检测已观察到的证据组合并提供有限恢复，不声称修复了腾讯客户端或 NapCat 的底层同步根因。

## 近期历史核对

首次启用建立当前时间的基线，秒级重叠；不导入基线之前的旧聊天。之后在接口核验通过时，轮换核对主用户私聊、已启用群和最多八位近期活跃/已观察到私信的真实好友。默认每次两个话题、每话题最近五十条、每次最多新增十条，检查近三十分钟。列表截断、接口失败及未能受理均保留在 coverage，不冒称全量覆盖。

只接受已核验 AI 账号返回的严格原生入站消息，核对 post_type、self_id、真实发送 QQ、群或好友范围、消息 ID、原始秒级时间和消息段。AI 自己发出的消息、错误范围、异常/未来时间、已撤回标志和畸形消息不补收。正文不会被转换成新的系统指令。

重复消息按原始消息 ID 与会话范围去重，已经发送、沉默、取消、过期或发送未知的记录不会被重新激活。读取历史接口的成功时间不作为消息发生时间，也不作为严格的“已经完整读到此刻”游标，避免旧缓存造成漏收窗口被错误推进。

十五分钟内的缺失消息进入原来的待考虑队列，由同一 AI 决定回复、等待或忽略。更早但仍在三十分钟核对范围的消息只归档，不调用模型。历史斜杠控制命令只归档，不重放 /stop。已经存在更新的主用户私聊消息时，较早漏收也只归档，防止取代新请求。普通近期主用户补收仍进入同一个原会话，不新建人格；身份保持 main-user，但该补收回合只开放明确只读工具与本轮回应选择。账号、设置、长期记忆、人格/情绪和其他修改要求新的实时消息。下一条真实实时消息恢复原工具权限。

群聊与好友补收标明原时间和来源；原时刻计算回应期限，不能因为刚补收到就重新获得完整十五分钟。补收数据不直接成为新的社交长期记忆、昵称观察、成长或情绪证据。后续新的真实交流仍按原审核机制学习。

## 数据与管理

技术状态、覆盖摘要、持久恢复预算和主用户补收来源元数据存于现有 companion.sqlite 的 platform_meta，主用户正文仍在 qq_inbox，群/好友正文仍在 platform_events，原图/语音仍复用 platform_media。补收主用户来源元数据与原记录在同一事务中写入，失败时连同额度一起回滚，避免断电后将半写入的补收误认成新的学习授权。完整 runtime/dev 迁移包含这些数据，不存绝对机器路径或平台凭据。

friend_qq_status 与运行健康快照的 qq.reliability 提供状态、最近核验/真实收件时间、预算、补收计数和各话题覆盖。Main-Status.cmd、Runtime-Status.cmd 以及现有运行保护可查看这些信息。被动状态读取不发起新的网络核验。

可在既有 friend-adapter 配置下设置 qqReliability：enabled、pollMs、lookbackMs、respondMs、historyCount、threadsPerPoll、recoverPerPoll、suspectSamples、autoRestart、restartCooldownMs、restartWindowMs、maxNativeRestarts。所有数值有界；默认补收/查询是技术核对次数，不增加 LLM 日常活动额度或改变行为优先级。

高流量群超出每轮五十条或调度延迟超过回复窗口时，可能只归档或无法覆盖；会显示覆盖限制。不会为了宣称“无漏收”而取消范围和时间限制。
