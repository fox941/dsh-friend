# B站自主收藏与关注

companion-adapter 0.26.0；attention-scheduler 0.2.0；架构 v0.28。

## 实现方式

继续使用 DSH、Mnemon＋Native 和现有统一注意力。新代码属于自有 companion-adapter，没有修改 DSH、Mnemon、第三方 MCP 或调度插件源码，没有增加后台决策循环、外部服务或依赖。

实际观看 → 可选的反思提案 → 持久操作候选 → 原统一注意力决定关注与时机 → 同一 DeepSeek 路由核验 → 核对当前账号与目标状态 → 单次平台请求 → 分别记录接收回执与只读读回结果。

观看不是收藏或关注的条件触发器。模型可以不提案、暂缓或放弃，情绪和兴趣作为已有上下文，不设置“情绪达到某数值就关注”的规则。关注对象从实际视频接口读取上传者 UID，不把动态转发者或昵称当成上传者。收藏只使用 AI 账号现有收藏夹，不创建或公开收藏夹。

## 两类来源

- 自主行为：原观看必须完成、原始观察仍可核验且允许学习；每条反思最多两个操作提案，只针对该视频及其真实上传者。推荐标题、反思复述、转发者或账号操作结果都不能成为新的观看经历。重复原件不重复提案或强化人格。
- 主用户明确要求：当前 Web/QQ 原话指定 BV、UID，或依据本程序已确认的新增操作 ID 撤销。QQ 原件沿用原账号绑定校验；外部评论、私信和视频文本不能冒充主用户。

“不保存”的观看不会派生自主账号操作，也不会写入长期记忆。主用户单独明确要求的平台操作可执行，例如“不保存聊天记忆，请收藏 BV……”，仍保留必要操作凭据。新操作层不写 Mnemon、自我描述、人格或情绪。

## 能力和控制

只新增收藏、取消收藏、关注、取消关注四项。没有增加点赞、投币、支付、拉黑、批量操作、头像和资料修改或新消息发送接口。

- friend_bilibili_account_action：提出候选、取消未提交候选，或在主用户核实现状后结束未知尝试；返回 queued 只表示排队。
- friend_bilibili_account_status：查看回执，或对单项执行只读平台核验，不重发。
- friend_bilibili_account_control：主用户启停执行/自主行为，调整资源上限、间隔和现有收藏夹 ID。

默认启用自主提案与执行；每天最多 12 次实际 POST 尝试，最短间隔 60 秒。它们是账号写操作的资源保护，与看视频、自动探索和 B站聊天额度分开。可调整为每天 1–60 次、间隔 5–3600 秒；不能绕过原总禁写或平台风控。每项最多每日三次执行核验，模型可暂缓，不会无限反复询问模型。待办最多 50 项。

候选采用原调度的 browse 类型和 biliActionId 载荷；调度提示与预览明确显示“账号操作”，不冒充视频任务。视频可在原检查点让出执行；进入账号提交边界后不切断操作，先记录回执。没有修改调度协议或增加第二个注意力调度器。

## 回执、重复和撤销

提交前持久记录目标、账号、前状态和尝试；真正进入传输时才计入写预算。平台 code=0 只表示接口接收，再只读检查目标收藏夹或关注关系。

- confirmed：接收与期望状态均已核实。
- noop：原本已有，无 POST，不归为本程序新增。
- verify_pending：接收明确，但状态未确认；只读核验。
- unknown：进入提交边界后结果不明；不自动重发。
- observed：只看到目标状态，缺少有效接收回执，不证明由本次操作产生。
- resolved：主用户核实现状后结束旧未知尝试；没有重发，也不取得撤销权。

未知写入会阻止同一资源的冲突写入。重启保留回执与不确定性，不把中断当成成功，也不盲目重试。来源后来失效不会抹掉已提交但结果不明的记录。

自主撤销及按旧操作 ID 撤销，只允许本程序已确认新增、尚未撤销且当前状态仍与回执一致的关系。旧回执已失效或已撤销时不能再次使用。取消收藏只移除原目标夹中的视频，保留其他收藏夹；关注检查关系属性、时间、特别关注和分组，不改变悄悄关注或黑名单。主用户重新明确指定 BV/UID 的当前取消指令按当前状态执行，与引用旧回执区分。

平台没有为收藏条目提供可靠的版本号；如果有人在两次检查之间手动移除又重新添加同一视频，无法保证识别这种“变回原状”的变化。核验与 POST 之间也不存在服务端原子比较更新。严格读回和旧回执失效保护能减少覆盖风险，但不承诺检测所有外部修改。

## 存储和迁移

仍位于 runtime/dev/companion/companion.sqlite，新增 bili_account_control、bili_account_actions、bili_account_attempts 三张操作表，保存配置、来源、状态版本、摘要校验、执行核验与请求回执。不是额外一套长期记忆。原人格 UUID、Mnemon、Native、视频证据和 QQ/B站身份绑定保持原存储位置。

迁移时停止实例，使用既有快照/迁移脚本复制完整 runtime/dev 并安装同版本代码和依赖。不要只复制某一个 SQLite 主文件；也不要拿公司开发实例覆盖家用实例。新电脑的 QQ/B站登录可能需要重新验证，旧账号操作不能转移成另一账号的授权。

## 验证和参考

原账号只读核验已确认登录 UID、视频真实 aid/上传者、现有收藏夹归属与关注属性。原生请求边界使用隔离 HTTP 传输验证；DSH 与 DeepSeek 实际工具选择/执行核验使用独立实例及模拟平台，不向真实账号发送随机收藏或关注。上线记录见 .work/bili-account-release.json 和 verification.json。真实平台写操作的实际送达仍以运行回执及平台可见状态为准，不把模拟验收称作真实平台写入验收。
