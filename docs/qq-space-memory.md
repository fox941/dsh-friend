# QQ 空间长期社交记忆

版本：companion-adapter 0.41.0、qq-bridge 0.10.0。复用现有 QQSocialMemory、Mnemon Native、审核队列、保护快照、追加式版本、夜间增量整理与撤销，不新增记忆产品、常驻服务或数据库表。

## 写入链路

认证空间评论 → 原说说上下文与允许的旧记忆 → 同一角色可提出最多 3 项记忆候选 → 真实回应选择落盘（proposed 或 ignored）→ 独立审核 → 原件在线核验 → 一致性快照 → 再核验原件与版本 → 追加记录 → Native 检索索引。

沉默也可留下有持续价值的对方自述，不为记忆强制回复。暂缓尚未作决定时不写；测试或“不保存记忆”内容不产生别名、提案审核、记忆或索引。回复文案不得把候选说成已经保存。

记忆类型沿用 preference、interest、experience、pending_topic、impression。必须逐字引用本轮评论者原话；别人的引用、昵称和 AI 自己拟出的回复不能作为原话。尚未实际出现的 AI 回复不能形成共同经历；已有实际页面读回时可向审核器提供带来源的回复证据，仍不证明对方已读。不能据此修改人格、兴趣或主用户私聊档案。

## 范围与跨说说

原事件仍按说说保存：`qzone:<AI>:<说说作者>:<tid>`。长期记忆使用：

- `qq-space:<AI>:public`：原公开评论。
- `qq-space:<AI>:friends`：原好友可见评论。
- `qq-space:<AI>:self`：原仅自己可见评论；不为演示伪造外部作者。

在相同范围内可跨说说回忆，但默认只召回当前评论者的记录。不同评论者、QQ 群、QQ 私聊、主用户默认记忆空间与其他可见范围不能混入，即使底层检索返回错误 ID，也会再按账本筛选。主用户在空间的身份仍有效，不因此开放私聊资料。

自定义/未知可见范围不猜成公开，不学习。别名按实际 QQ 身份登记，不能用昵称提升权限。

## 原件核验与长期保留

每次召回最多在线核对 3 条来源说说，当前原件可复用已读快照。实际核对通过标为 currently-verified；折叠、翻页、网络故障或核验额度之外，可保留带原始事件和内容哈希的历史召回，标为 historical-*。这不是刚在线核验，也不能断言对方当前仍有同样偏好。

已经确认原件内容或可见范围变化时，旧记录不进入召回；该抑制证据持久保存，之后断网或重启也不能绕过。正常轮询观察到的权限变化同样登记。恢复到原来可核验内容和范围后可重新使用。未知字段不当作确认变化，记录不物理删除。

网络故障期间无法保证即时知道外部刚发生的权限变化，历史记录反映最后已知范围，不冒充实时权限证明。新记忆写入、纠错和夜间修改则必须在线核验来源，不能靠历史模式提交新事实；失败保留原记录与审核依据。

## 数据与维护

- `runtime/dev/companion/companion.sqlite` 的 `qq_social_*` 表：正文、来源、审核、版本、批次与索引回执。
- `memory/qq-social/data/qq_<scope哈希>/mnemon.db`：相应空间范围的 Native 检索库，首次真实索引时创建；原群和好友库不变，不混入 `memory/data/default`。
- `platform_meta` 的 `qq-space-post-state:*` 与 `qq-space-source-state:*`：最后明确观察到的范围/内容变化标记，不保存新的私人资料或凭据。

夜间沿用原增量游标与审核预算，只据后来的明确更正或话题结束作 revise/close，不根据时间自动判错或删除。改动前复用已有快照；撤销核对目标是否又被后续修改。Native 索引失败不丢正文，可按原任务重试。迁移仍搬完整实例和插件版本，不能只复制新数据库。

## 统一人物画像扩展（0.42.0）

原空间社交记忆的来源范围和修改权限仍按本文管理；新增只读 personProfile 视图负责同一人的跨场景画像。公开来源的通用偏好可以进入同一人的私聊和其他公开话题；私聊和群内资料默认不公开，局部约定仍限原场景。该视图不复制原记忆，详情见 `person-profiles.md`。因此“原空间 socialMemory 不读取私聊库”与“表达可获得程序筛选后允许使用的人物画像”是两个不同入口，不能把后者当作放开私聊全文。
