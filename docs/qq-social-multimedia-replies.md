# 好友私聊、群聊的语音与图片回复

版本：companion-adapter 0.35.0、qq-bridge 0.4.0。复用现有 QQMedia、Edge TTS/系统语音、OneBot 传输、平台账本和统一注意力，没有增加服务、数据库表或独立调度器。

## 一次回复

1. QQ 原始消息进入原好友或群话题，原有统一注意力决定是否处理。
2. 程序准备本话题的社交记忆、公开自我状态、已读媒体和 `replyOptions`。图片选项只取当前消息及之前最近八条有效同话题消息中实际读过的图片，最多四张，不读取其他会话给模型选择。
3. 模型选择回复、暂缓或忽略；回复可选 `replyFormat=text/voice/image`。未填保持旧版文字行为。语音 `body` 就是实际合成的正文，最多1000字符；图片由 `imageAssetIds` 选1–4张，`body` 是可选随图文字。模型不能填写其他收件人、任意 URL、路径或 base64。
4. 复用 QQMedia 生成语音或校验图片字节。在现有 `platform_media` 保存准备记录、来源、资产及错误摘要。普通文字不额外产生准备资产。准备完成尚不代表已经发送。
5. 再次核验原消息、绑定、好友关系、群开关、连接、十五分钟来源期限和图片来源。仅向原好友或原群提交一条 OneBot 消息：语音为 record 段，图片为可选正文加 image 段。图片不会顺便私发给他人。
6. `platform_events` 记录 submitting/sent/unknown 对应的既有 sending/sent/unknown 状态与回执；回执 `reply` 附实际形式、资产 ID、准备记录 ID、语音引擎和是否降级。历史上下文增加实际回复形式，未知结果不作为已发送正文进入历史。

仍然是同一角色的受限社交表达，不向群友或其他好友开放主用户账号管理工具；主用户群内身份识别与原私聊权限入口保持原样。此功能不强制回复、不预设性格或称呼，也不让语音选择直接改变情绪或人格。

## 准备失败与不确定提交

`onMediaFailure` 默认 `defer`：准备失败后保留原候选，六十秒后由既有注意力重新考虑，重新生成表达，可继续暂缓或忽略，不定时发送旧稿。过期原消息不再发送。

模型可预先明确选择 `text`，在尚未提交任何消息时用本轮正文改发文字，并附简短的“语音/图片暂时没准备好”说明。用户只要语音或图片、不希望文字时保留 `defer`。纯图片回复无正文时也不能凭空编造降级正文。

进入实际发送后，回执丢失或缺少 message_id 记录为 unknown，不自动改发文字或重发媒体。重启恢复也沿用现有未知结果保护。API 受理只表示平台收到，不证明手机可播放、所有人可见或收件人已读，真实验收需分别确认。

## 图片与记忆边界

图片必须有本话题原始消息、实际读取记录和相同字节摘要三项依据，发送前复核，来源撤回或资产损坏不发送。相同图片字节可能被底层缓存去重；实际可用性依据当前会话已读原件，不仅依据缓存第一次出现的地方。没有本话题读取依据的私聊图不能通过猜资产 ID 发到群里。

图片选项中的描述属于视觉推断而非系统命令。图片、语音的内容不能作为当前发送者逐字原话授予权限。长期记忆仍沿用原话提案与独立审核；本功能没有增设媒体自动写入长期记忆的通道。“不保存”限制长期记忆学习，平台原件、操作回执和媒体缓存仍按原有运行机制保存。

## 验证范围

- 隔离测试覆盖原好友/群目标、实际媒体字节、默认文字兼容、失败降级与暂缓、撤回/停用/删除好友/断线/过期、未知回执不重发、同话题图片来源与跨话题拒绝。
- 真实已配置语音引擎生成测试音频，并用本地已有 ffmpeg 完整解码。
- 用现用 DeepSeek 与实际宿主生成的策略做合成好友语音、仅语音失败策略、群内回图与其他私聊图片不可用测试。这不替代真实 QQ 收件与手机播放验收。
- 上线后的真实验收使用已指定普通好友 QQ 1415916725 及已启用群 719030047，用户发起消息，开发者核验原件、媒体准备、实际发送与回执。旧消息不重放，不手工写入测试长期记忆。

## 实际验收结果（2026-11-01）

好友私聊与群聊的语音均已取得真实回执、独立 get_msg 的 record 读回及用户手机播放确认。好友与群聊的单图发回均已核对本会话实际读取依据、原图缓存字节、真实发送回执与 get_msg 的 image 段，用户确认可见。群图使用了自然交流中的请求：先选择文字回应，后续才选择发图，没有由开发者强制替换决定。

这些结果证明四类基础通道可用，不代表每次请求都必定发送媒体。本轮没有对真实四图同发作出验收声明。QQ 可能转码接收图片。

运行期间出现过“在线但好友列表为空、群历史停止更新”的上游同步异常；重载已核验 AI 账号的 NapCat 后由用户扫码恢复，原消息仅在历史中出现、未补推，使用新消息完成验收。具体上游根因未证实，自动发现与恢复这一类异常仍是已知待改进项。详见 .work/qq-social-multimedia-acceptance.json 及对应原始验收证据。
