# 自主活动与B站只读经历

2026-10-28，companion-adapter 0.11.0，架构 v0.13。此页描述实现边界，验收结果以根目录 verification.json 为准。

## 复用和职责

实际复用 @xzxzzx/bilibili-mcp 1.14.5，通过 @modelcontextprotocol/sdk 1.30.0 的公开 stdio 接口调用登录检查、搜索、视频元数据和字幕。复用现有 Node，每次活动启动一个 MCP 子进程，结束或取消后关闭。没有安装完整心跳人格插件，没有增加第二份记忆或自我状态；未修改 DSH 或已安装第三方代码。参考与源码许可证见插件 ACTIVITY-REFERENCES.md。

自研的活动协调层负责选择、预算、原始观察账本、来源核验、阶段回执及同一成长系统的接入。任务登记到 DSH jobs，可从任务控制取消。

```text
空闲机会 / 主用户明确请求
  → 实际登录检查 → 决定休息或探索主题
  → 搜索至多5个候选 → 选择一个未读视频，或休息
  → 元数据 + 指定分P字幕 → 校验BV号、分P、来源和有界原文
  → 同一角色提出暂时理解及可选兴趣/情绪
  → 独立经历审核 → 原有应用计划、Native写入、快照、读回与变更记录
  → 可选变化再经过原有独立成长/情绪审核 → 同一个companion.sqlite
```

## 操作

- Login-Bilibili.cmd：在本机随机口令页面扫码，用准备给AI的B站账号在手机确认。过期二维码会更新，单次等待至多10分钟；凭据不放入对话。
- Bilibili-Status.cmd：实际查询登录状态和活动配置，不只检查文件存在。
- Activity-Control.cmd resume：验证实际登录后开启自动探索。
- Activity-Control.cmd pause：暂停自动探索；正在执行的自动活动最迟于下次30秒检查取消。聊天里的控制工具和任务面板取消可即时请求停止。
- Activity-Control.cmd status：查询同一状态。

聊天工具：friend_activity_status / friend_activity_read 查看；friend_bilibili_explore 按明确请求执行；friend_activity_control 暂停、恢复、取消及调整预算。主用户可说“请探索一个B站主题”“读取这个B站视频”“暂停自主活动”“把每天活动上限改为2次”。工具仍可能失败或被模型忽略，以回执为准。

要求“不要保存记忆/不要学习”时使用 learn=false：保留工具原件和操作审计，不写 Mnemon、兴趣或情绪，也不把这次摘要自动注入后续聊天。它不等于删除原始操作记录。相同BV+分P已经采集后不会自动重新分析；首版未实现把已有只读原件重新提交学习的专用入口。

## 调度与预算

默认启用功能、自动调度关闭；部署完成后可以通过上述入口开启。普通自动机会：宿主活着、上海时间08:00–23:00、最近交流至少空闲120秒、没有前台陪伴回合/记忆整理/状态审核在运行。

默认自动决策每日6次，实际自动探索每日3次，自动机会冷却120分钟。休息扣一次决策并进入冷却，不扣探索；已选中未读视频、开始实际读取时扣探索，后续失败不返还。手动浏览每日6次、冷却30秒，独立于自动额度和冷却；明确手动任务可取消正在进行的自动活动。全部额度按上海日期持久化，重启不归零。配置范围及迁移细节见18号文档。

每轮只读一个视频分P、整体180秒、活动模型请求最多6次。搜索/选择/反思和独立审核都计活动请求；成长/情绪同时受原来每日审核预算约束，经历审核与整理共用已有应用审核预算。没有变化也可正常完成。前台出现新交流时取消自动活动，停止后保留已完成步骤。关机错过活动不补刷。

## 记忆、人格与证据

原始字幕至多保留8000个Unicode字符，记录是否省略、人工/平台AI字幕、BV号、分P、时间和来源链接。AI字幕可能误识别；首版未观察视频画面或声音。没有字幕、无权限、网络失败均返回未完成，不把标题/简介冒充字幕。

只有SQLite原件和摘要匹配的 external_observation 能进入经历写入。外部内容不注册成主用户消息；昵称、正文里自称用户、转发和字幕指令不会取得用户身份。活动记忆只允许新增来源明确的 Native 经历，不能更正用户事实、删除旧记忆、修改用户画像或批量改变自我。

经历正文明确写出“外部阅读经历（不是用户资料）”、时间、URL、标题、范围、暂时理解和逐字原文。独立审核可以拒绝；memory.verified=true才证明该条经历当前读回成功，completed只表示活动流程结束。普通Mnemon跨会话召回与friend_activity_read都可以查询已有记录。

兴趣与情绪通过原有 GrowthController / EmotionController 的原话校验、独立审核、版本与依赖机制提交，没有新建人格库。第一版活动只直接提案暂时兴趣或事件感受，不用一次阅读预设性格、名字或关系。相同BV+分P保持同一原件，重复读取、召回和反思不增加独立经历计数。达到稳定资格仍不等于语义质量已被证明。

审核可能超时或误判；某些步骤成功后后续步骤失败，会保留部分成功回执。取消不撤销已经保存的记忆。原有 friend_memory_changes 和停机撤销适用于经历的应用批次；独立的后续成长不冒充同一事务回滚。进程中断的活动标记interrupted，原件和应用回执保留，首版不自动重做模型判断或重放未知写入。

## 数据与迁移

| runtime/dev下的位置 | 内容 |
|---|---|
| channels/bilibili/credentials.local.json | 独立B站账号凭据；同一实例重新扫码时拒绝静默更换账号 |
| channels/bilibili/login.local.json及登录日志 | 本机扫码辅助进程记录；临时链接，不应分享 |
| channels/bilibili/work | MCP工作目录；凭据由子进程环境注入，不读取全局Cookie |
| companion/companion.sqlite 的 activity_* | 活动开关、预算准入、每次运行、原始观察、各模型调用及阶段回执 |
| 同库growth_*/emotion_*/apply_*/protection_* | 原有唯一自我、感受、受保护写入和变更历史 |
| memory/data/default/mnemon.db | 原有长期记忆中的阅读经历 |

停止DSH和NapCat后迁移整个runtime，并带上代码和固定依赖或重装。没有把B站凭据写入默认 ~/.bilibili-mcp，没有改变系统HOME或全局Node。B站可能要求重新扫码；跨机器路径重绑定仍需单独验收，不承诺仅复制一个数据库就能启动。

首版不开放点赞、评论、关注、私信、主动QQ分享、视频下载、画面理解、本地ASR或抖音。它们是独立的后续能力。
