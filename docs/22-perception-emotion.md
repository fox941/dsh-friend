# 沉默感知、情绪反馈与自主重评

2026-10-29，companion-adapter 0.15.0，架构 v0.17。

继续使用 DSH + Mnemon/Native，没有迁移框架或引入第二个人格。参考既有 EMOTION-REFERENCES.md 中事件评价、情绪与心境分层、依据重评思路；本次是原自研模块的接续，不另装情绪插件。

## 看见与回应分开

全局行为选择会向模型呈现各消息最多700字符的预览，并标明实际呈现范围、是否已呈现及能否学习。对未选择进入回应阶段的原件，模型可以附带零到若干情绪提案；不是每条消息都要产生感受，也不因为有感受就必须回话。选中回应的消息沿既有交流流程处理。

行为选择成功提交后，才保存感知回执和可选提案。过时或失败的选择不触发感知变化。没有提案时不新增情绪模型调用；有提案时后台调用原独立情绪审核器，沿用成长/情绪每日审核额度、超时、SQLite事务、版本核验和历史记录。每日交流事件仍不限，审核额度与交流回合不同。

来源只包含实际呈现的原文，原消息ID、会话或平台事件ID、账号/发言者、公开或私密范围、接收及呈现时间。仅呈现预览不能声称完整阅读、已经回应、接受承诺或共同完成行动。公共回复继续使用原受限上下文，不把私密情绪理由或全局决策材料复制出去。

每个原件的呈现回执仅记录一次。跨延后、重启、正式接纳后再次引用同一原件，不能因为换一段摘录就增加同一情绪的独立支持。新路径与新B站社交来源使用原件键；历史来源未携带键时继续依靠原摘录指纹和语义复核，不宣称已经回填全部历史关系。

## 自主反思如何影响情绪

反思仍由统一注意力选择是否开展。执行时最多提供4项已有情绪及其旧原话，反思可以只留下简短工作记录，也可以提出一项已有感受的重评。重评进入原独立审核，使用旧原件和原情绪ID，不把反思记录当新外部事实。

程序强制：纯重评不能新建情绪，不能提高当前程度或判断把握，不能刷新时间锚点，不能增加支持事件。它可以有依据地降低原感受或纠正误读；没有真实结果时，语义审核应拒绝凭空解决尚未解决的事项。语义判断仍可能误判，这项限制没有声称消除全部模型错误。

人格、稳定兴趣和长期事实不通过本路径自动修改。活动和正常交流的原有成长流程继续使用；冷归档、多日目标、主动QQ分享和抖音不在本次范围内。

## 持久化、失败和查看

回执使用原companion.sqlite中的attention_checkpoints，键前缀affect:perception:或affect:reappraisal:；只新增一个待处理索引，没有新增数据库、服务或第三方依赖。实际情绪仍在原emotion_*表，来源在growth_events及growth_event_origins。

seen表示已呈现且无提案，delegated表示交由已选择的交流路径处理，pending/processing表示待审核/审核中，completed表示审核已结束（实际是否改变以receipt为准），skipped/invalid/failed/interrupted表示未提交或需查看。失败不在每次计时器触发时反复请求模型。重启先按固定批次ID核对已提交回执，未完成的审核标记中断，不盲重放。

提交前重新核验原件、身份、学习设置和版本；原件撤回、账号变化、只读设置或并发情绪变化均可阻止提交。同一决定的多原件提案可以顺序跟进本决定刚提交的版本，其他决定不能据此覆盖新状态。

不保存、不学习、只查询和接入测试消息不进入新情绪写入；原件后半段的禁止保存要求也会核对。这里的不保存仍允许保留原始收发与操作记录，和既有测试约定相同。

Attention-Status.cmd及friend_attention_status展示处理状态、批次回执与错误；感受和历史沿用friend_emotion_read/history。生产升级前停机备份完整runtime，插件通过DSH官方安装接口更新，不修改DSH或Mnemon安装源码。

## 验收范围

自动测试覆盖Web/QQ/B站身份与范围、沉默情绪、并存感受、未读部分、不保存、跨阶段去重、独立审核失败、并发版本、撤回、取消与重启恢复，以及反思不增加证据/程度/时间。另用独立DSH和真实DeepSeek检查接入、审核与反思，平台为模拟。具体计数和结果记录于项目verification.json；这不等同于长期人格质量或新一轮真实平台送达验收。
