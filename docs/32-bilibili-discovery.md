# B站只读内容发现与观看衔接

2026-10-29；companion-adapter 0.23.0，attention-scheduler 0.2.0，架构 v0.25。

## 能力与职责

- `friend_bilibili_discover`：按精确UID读取一页投稿、动态、资料、合集或系列；可搜索UP主；可读取AI当前登录账号的收藏。昵称搜索只产生候选，不确认唯一身份。分页必须原样使用对应目录的 `next_cursor`。
- `friend_bilibili_explore`：沿用 video / query，增加 discoverFrom=owner_latest、creator、favorites。owner_latest从本机已有主用户绑定解析UID，排队时冻结UID；creator需要creatorUid，不能用昵称代替。
- 投稿/收藏候选进入原选片与观看链路。指定“最新”按投稿首页实际发布时间选出最新可见条目；不承诺已删除、私密或尚未展示的内容，也不保证目录里的联合投稿是该UID独立创作。
- 自动探索可由同一模型在关键词、精确UP主投稿、AI收藏和休息之间选择。没有固定兴趣，不按消息到达顺序强制打断。

## 执行路径

QQ/Web原始请求 → 核验主用户与原话 → 精确UID/来源 → 原统一注意力调度 → 只读目录 → 固定BV检查点 → 原字幕/分段音频/抽样画面观察 → 原经历、兴趣及情绪审核 → 原绑定出站。

QQ长任务仍持久排队，返回queued不表示已经观看；统一注意力可以先做别的事、延后或不回应。后台恢复复用原活动ID和固定BV，不反复查询最新、不重复花手动额度。B站主用户绑定变化时原任务要求重新确认，不自动换查新账号。Web可同步等待原观看工具。

目录元数据不会创建activity_observations，也不会触发Mnemon经历、兴趣或情绪审核。实际观看后才沿用原证据链；learn=false保留操作/观察回执，禁止该任务写入Mnemon或自我状态。目录中的标题和动态均是外部数据，不能作为用户指令。

## 复用与兼容

继续依赖固定版本[@xzxzzx/bilibili-mcp 1.14.5](https://github.com/XZXZZX-Ai/bilibili-mcp)（Apache-2.0），新增开放其UP主搜索、动态、合集/系列、收藏只读操作。

实测该版本的投稿/资料WBI请求使用timestamp并有不同的签名构造，投稿目录返回ACCESS_DENIED；同一账号用本项目已有WBI组件可成功读取。投稿和资料因此通过自有薄适配 `bilibili-catalog.js` 复用已有 `BilibiliInboxClient` 的登录核验、受限响应、流量保护和 vendor/dsh-bili-whale MIT签名（wts/w_rid）。正常拒绝直接报错，不退回无签名请求，不修改DSH或第三方安装包。

没有引入新框架、常驻服务或记忆库；没有新增数据库表。目录来源、时间、限制和选片结果存入已有activity_runs.decision_json，续接沿用原检查点。人格、情绪、原始消息、长期记忆和既有身份沿用runtime/dev。

## 范围与预算

每次只读一页，视频目录最多20条；UP主搜索使用上游有界候选；不会自动爬完整个空间或收藏。目录返回最长48K字符，文本字段有界。保留原视频自动探索6次/日、自动决策12次/日、60分钟间隔、手动30次/日，以及原模型/媒体预算。元数据查询不消耗观看额度，仍受工具超时、宿主回合和接口流量保护约束。

本次没有接入首页个性化推荐、全量关注动态流、抖音，也没有新增点赞、投币、关注、收藏修改等写操作。已有B站私信/评论交流通道沿用。
