# 记忆提案应用与跨层更正

当前：companion-adapter 0.4.0，架构 v0.6。复用既有 Mnemon Runtime 与 Native，自研外部插件中的应用协调层。没有修改 DSH 或第三方插件源码，没有增加常驻服务或数据库后端。

## 使用

1. 聊天中请求：“请做一次记忆整理预演，只给建议，先不要应用。”
2. 查看报告后，在下一条消息中说：“应用刚才那份报告里可以执行的提案，保留原话和旧版本；有冲突的先待定。”也可以只选择报告中的部分提案。
3. 可以说：“查询刚才的应用回执，哪些完成了，哪些还没完成？”

预演回合始终只读。明确的应用请求调用 `friend_memory_apply`，报告查询使用 `friend_memory_preview_read`，应用查询使用 `friend_memory_apply_read`。应用期间其余工具也限为只读，防止主模型绕过审核补写。

“应用”会重新核验和判断，可能返回无需改动、暂缓或部分完成。程序不会仅凭模型一句“已记住”判成功。未提供报告时先查询，不能凭猜测构造编号。

## 一次应用经过什么

- 从持久会话重新打开报告中的原始事件，核验说话者、来源、消息 ID、序号、时间、原文摘要和逐字引文。另存本轮主用户的具体应用授权，不将它当成新的事实证据。
- 重新读取当前 Runtime、相关 Native 和自我状态，并读取报告后的有界新交流，用于发现旧报告的反例或过时。原引用已失效则要求重做预演。
- 对可执行项进行一次无工具的独立审核，区分过去与现在、条件、未来切换、引用和真实自述。keep/duplicate 无需审核模型；冲突、未知生效时间和未来才生效的变化暂缓。
- 先持久保存固定计划和每个待执行步骤，再按当前版本执行公开接口；每步读回核验、保存回执。重试同一报告及相同选择先核对原计划，不重复审核或盲目新增。

审核默认每天最多 6 次、每次最多 60 秒及 8192 输出 tokens、最多 8 个写入步骤。失败、超时和取消也计调用数；预演和成长分别有自己的预算。不新增自动循环。

## 支持的操作

| 情况 | 实际处理 |
|---|---|
| 用户偏好或工作事项补充 | 当前事实可进入既有 Runtime USER / MEMORY；不代写人格 |
| 已有事实更正 | 核验完整旧值及版本，保持未变细节；已发现的完全相同旧副本须一并更正 |
| 新经历事实 | 写入现有已激活 Native 空间，保留主体、时间与结果；不批量转存 USER |
| 普通事项退出常驻 | 先完整转存到现有 Native、核对回执，再移出 MEMORY；USER、critical 约定不执行此操作 |
| 相关自我认识失去依据 | 已有关联的版本及依赖进入 `needs_review`，保留旧版本，不自动编写新性格、情绪或提示词 |
| 一组操作中途失败 | 保存已完成、结果不明与尚未执行的步骤；查询或明确重试，不声称整体原子回滚 |

常驻转存是复用已有长期空间，不是独立冷归档数据库。旧经历不会因低频或低评分被自动删除。

## 一致性与恢复

Runtime Source 0.5.16 的普通写入没有 CAS。本版使用其公开的 maintenance-plan / compact-and-mutate：锁内核验 revision，原样保留其他条目，不为本次写入压缩或丢弃它们。容量不足或有尚未适配的跨机 origin 元数据时暂停。

Native 更正复用既有更正日志、串行锁和记忆存储锁，先保存新值、读回，再退役旧值；自有日志保留旧完整快照及来源。Native 的 forget 会删除图边，不能承诺恢复完整原图。

跨层没有全局事务。事实已写但自我复核未完成时，相关旧认识和依赖暂时退出当前上下文。所有步骤成功后方可报告该组已核对完成；`partial`、`cancelled`、`interrupted` 可按原记录继续。进程重启不自动请求模型或继续所有应用写入。

新增动作在发出前保存意图；回执丢失后先核对目标。资料已变化且无法确定上次结果时暂停，避免重新新增后来被用户移除的旧内容。已完成的目标后来又变化，回执显示 `historical`，再次应用原报告不会恢复旧值。

## 数据、迁移及关闭

应用数据保存在 `runtime/dev/companion/companion.sqlite` 的 `apply_*` 表：运行、选择、授权、固定审核材料、计划、步骤回执、调用预算与事实到自我版本的关联。新增独立表，不重建身份、不清空原表。原始交流仍在 DSH 持久会话中。

停机复制整个 `runtime/dev`，或使用现有离线备份/恢复方案；同时保留代码和 profile 的 `.friend-packages`。仅复制 Native 数据库会丢失自我状态、原始会话和恢复日志。

可在自有适配插件配置中设置 `application.enabled: false` 停用新应用入口；历史仍能查询。已有普通聊天、成长及直接事实更正入口保持原有规则。

## 当前边界

跨层复核仅覆盖本应用流程中发现并核实的旧副本与状态依赖；Native 检索有界，程序不能证明全库无冲突，也没有监听所有 UI、CLI 或其他插件的写入。人工在外部改数据不会自动建立关联。模型负责语义判断，程序只能验证结构、原始引文、版本和执行范围。

尚未接自动夜间触发、自动补做队列或全面去重/遗忘策略；不按“每天晚上已到”自动编造新经历。下一步是先验证 DSH 受控维护入口及单次调度的暂停、预算、错过后补做，再开放夜间运行。

## 验证

使用项目 Node 24，`node --test tests/*.test.mjs` 包含 32 项应用专项检查及原有 72 项检查。专项使用真实 Runtime Source 测版本与并发，Native 故障注入测试回执丢失、转存中断及重试。真实 DSH/DeepSeek 验收另在隔离实例执行，不把测试记忆导入用户实例。详细版本、数量、升级保留和快照证据记录在根目录 `verification.json`。
