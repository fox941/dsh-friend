# QQ 主动好友申请与关系跟踪

companion-adapter 0.37.2、qq-bridge 0.6.2、NapCat 本机扩展 0.2.2。延用 DSH、Mnemon Native、统一注意力及原角色；没有新记忆库、服务或数据库表。

## 能力与决策

主用户私聊或 Web 中的 `friend_platform_action` 可提出 `qq_friend_add` 候选，参数为准确 `userId` 和最多300字的验证留言 `text`。验证留言会对外发送，不能包含主用户私聊、记忆、密钥等私人资料。候选交给统一注意力和既有模型操作核验，可以执行、暂缓或拒绝。群友和普通好友的表达回调不能调用管理工具，补收旧主用户消息的只读限制继续生效。

QQ 好友社交关闭时不提交新申请。准备与提交前重新核对 AI 账号、目标资料、当前好友名单和扩展能力；已是好友则无需再次申请。现有好友申请接收、加群邀请及主动加群继续使用原入口。

## 协议与边界

官方 OneBot `set_friend_add_request` 处理收到的请求，不用于主动添加。主动路径由认证本机扩展调用固定 NapCat v4.18.41 声明的 `getBuddyService().reqToAddFriends(number,string)`。不尝试其他写入签名，不调用任意内核方法；运行时缺少该方法则显示接口未支持。声明可用不等于真实平台已经通过，真实发送仍需实际验收。

接口返回 void 只记录已尝试提交，不能称为 API 受理或成为好友。非零原生错误明确保留；超时/连接中断保持结果未知，不换路径重发。好友名单中的真实成员关系才确认成功。申请查询只匹配目标 QQ 对应的原生 UID、主动方向和提交时刻之后的请求；对方同意但名单尚未出现仍待核验。请求记录缺失不表示被拒绝，只有实际匹配的拒绝类型才记录拒绝。读取器不会返回原生 UID、验证正文、认证信息或任意待处理列表。

## 防重与持续跟踪

相同目标已有候选或跟踪中的申请时，重复提案返回原操作 ID。扩展提交前先写持久账本，再进行一次原生调用；同一 ID 重试仅返回已有记录，不再提交。不同 ID 在24小时内也不能重复申请同一目标；当前跟踪中的请求最多七天保持防重。实际原生待审核记录存在时不再次申请。

关系跟踪复用 QQ 收件保护的巡检，仅在账号和业务状态正常时执行；每轮最多3个到期申请，初次约一分钟，随后退避至最多十五分钟。它只读平台状态，更新本地技术回执，不调用人格决策模型，也不重新提交操作。重启保留下一次检查时间和原操作。七天仍无法确认则结束自动跟踪，显示结果未确认，不把它改为拒绝。

好友/群申请不再因原来8次短期核验结束而停止长期等待。确认入群后更新接入范围；确认退出后移除该群接入范围。好友是否可交流仍以实际名单及现有好友开关为准。删除或退群不会清除原社交记忆、历史和附件，不把关系变化直接写成人格或情绪结论。

`friend_qq_relationship_read`、`friend_platform_status` 及 `QQ-Operations.cmd` 可查看技术状态。只读查看不发起新申请。完成确认不会机械地强制向用户发送通知；可以在原聊天中询问实际进度。

## 存储、部署与迁移

跟踪状态及时间保存在 `runtime/dev/companion/companion.sqlite` 原 `platform_operations.value_json` 的 relationship 字段。扩展沿用 `runtime/dev/channels/qq/napcat/ai-friend-social-helper/join-ledger.json`，新增条目标明 friend_add，原加群账本条目保留。完整停机迁移 runtime 会携带两者，不要单独清空账本来重试。

扩展仍在 `plugins/qq-bridge/napcat/qq-social-helper`，新增 friend.mjs，由安装器复制至实际 NapCat 插件目录。此次包含扩展更新，需要专门部署；原普通更新工具对扩展摘要变化的门禁保持。若固定版 Plugin/SetStatus 可用，可仅停用并重新启用本扩展，沿用当前 QQ 登录；无法热加载时明确记录待登录后加载，不以代码复制成功冒充已运行。

真实好友申请仅使用用户指定的测试 QQ 1415916725；不会为测试删除其他好友或改动主账号。真实结果、手机确认、隔离测试与实际安装代码分别记录，不用模拟成功代替平台验收。

## 2026-11-01 真实验收与当前限制

真实主用户请求已进入原QQ会话（inbox e7f2967c-1c6b-4e2a-9776-0da3a7eb2bd0），形成操作19a101fb-5718-44d7-81ac-58ab5bd880c4，模型选择执行。第一次原生调用未取得可确认结果，原生请求查询没有找到待审核条目；测试QQ用户明确确认未收到。因此主动发送尚未通过真实验收，不能把原生方法存在或隔离通过说成可实际加好友。原操作unknown、账本和只读跟踪全部保留，没有清空或重放。

复查上游服务代理存在同步异常后回退原方法的逻辑。修正版通过 eventWrapper.createEventFunction 取得绑定的原始方法，只调用该方法一次，不经过该服务代理；增加固定的脱敏错误分类与只读方法诊断。此次部署不重发原申请。
