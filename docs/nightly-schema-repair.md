## 协议和诊断

复用现有 Zod 4.6.7，以同一份严格 Schema 生成模型输入协议并验证输出。action 是八种动作之一；evidence、referenceIds 是数组；原有数量、文本长度及引用约束保留。移除容易误抄为字面值的竖线拼接动作例子。模型输入同时列出本次可用来源、用户原话和旧条目 ID；这些 ID 仅是可引用范围，不证明提案含义成立。

PREVIEW_SCHEMA_INVALID 给出字段路径、错误类型及长度，例如 proposals.0.evidence 应为 array。诊断不复制错误值或额外字段名。PREVIEW_GROUNDING_INVALID 区分引文、来源、旧条目和适用范围不成立；它不触发格式纠正。Zod 在错误容器上附带的长度错误被过滤，避免把一个 ID 字符串误报成超过数组条数。

## 最多一次纠正

仅当可辨认提案意义、现有引文和引用没有已知问题时，结构不合规的 JSON 可请求同一模型纠正一次。示例：引用对象改为单元素数组、单个旧条目 ID 改为数组、非法枚举表达、遗漏格式字段或额外字段。截断、JSON 语法错误、敏感内容、未知来源/旧引用、引文不匹配、仅助手自述、超长内容、无法辨认的提案不尝试纠正。

纠正使用冻结的同一份来源及旧资料快照，保留原总结、已有提案文字、顺序、数量、有效动作、引文和已有引用集合。缺失的格式字段只能从同一快照补齐，结果重新经过完整结构和引用校验；后续独立应用审核仍需判断是否值得修改记忆。纠正改变原意、丢弃提案或仍然不合规，整个预演失败，不能推进游标。

纠正前后分别核对资料版本。旧资料改变时结果标为 stale，保留原报告和进度，不能使用旧快照提交。主用户取消、服务停止和超时后晚到的输出不能提交。手动预演仍是只读回合，纠正不会放开后续写入工具。

## 时间和额度

初次生成与纠正共用一个预演超时：后台默认 120 秒、手动默认 45 秒；外层夜间任务仍为 300 秒时间片。纠正完整输入也受同一个输入上限约束，不截断原件来凑预算。后台输出默认 16384 tokens，手动默认 8192，纠正沿用同一路由和上限；路由变化时停止，不切到其他模型。

每次纠正同时消耗预演每日调用额度；后台还消耗夜间角色调用额度，角色名为 preview-repair。预留与预演预算计数在同一事务中保存；重启不返还或重复分配该次额度。每天额度不足时保留失败稿和原进度，按已有预算等待规则处理。每个预演尝试最多一次纠正，原本有界的整任务失败重试机制不变；不会自动重开已经终止、取消或被模型放弃的旧任务。

## 存放位置及读取

仍使用 runtime/dev/companion/companion.sqlite，不增加表、依赖、后台轮询器或另一个记忆后端。preview_attempts.result_json.reviewPhases 保存 initial、repair 两阶段的状态、字段问题、模型元数据、计时及必要的未验证输出。敏感或超过 18000 字符的拒绝稿只记省略原因。preview_runs.result_json 只保存最终有效结果，未验证稿不会混进获批提案。

friend_memory_preview_read 默认只给诊断元数据；主用户确需核对原文时 includeSources=true 可看到标为 unvalidatedDecision 的拒绝稿，它不是新证据或已保存事实。旧版无阶段记录的报告仍能读取，返回空阶段列表。阶段计时按每次调用分别记录，原汇总 trace 的首个里程碑不用于推算两次调用之和。
