# 有据回忆入口与检索质量评估（0.58.0）

本次目标是验证换词回忆、历史更正和人物/场景边界，并补上可选择的有据回忆流程。长期记忆仍使用原 Mnemon Native；没有新增向量库、后台模型或持久存储。

## 本地备份评估

采用 2026-11-03 的一致性快照，隔离复制后通过已安装 Memory Spaces Source、Native Provider、原结果质量策略与 friend-three-tier 会话预算执行。真实备份的原文只在本地处理，生产库没有被测试改写。

18个预先编写的问题中，16个有目标资料，其中11个在单次原问法检索时包含目标，5个未命中目标；另2个没有记录对应事实的问题也返回了无关候选。精确实体词较容易命中，绕述与泛词会出现排序噪声。该语料很小，主要是相近视频经历，不代表长期或通用准确率；没有据此断言真实聊天答错或记忆丢失。

“有候选”“能找到目标原文”“能够正确回答”是三个不同指标。原 Mnemon 已有中文关键词补检及质量筛选，不能简单将问题归为没有向量。现有两次查询允许模型换词补检，但也不保证每次都会产生有效改写。

## 新入口

主用户直接会话可调用 friend_memory_recall，输入 query 和可选 alternateQuery。两个检索词均由当前模型根据问题提供，不能编入尚不知道的答案。

- 经公开 tools.execute 进入本会话已有 mnemon_recall，保留父调用授权、agent、signal、附加上下文和终止信号；没有可用工具时不直接访问数据库。
- 与直接 Mnemon 共用普通两次、复杂任务四次的原会话预算，没有独立“赠送额度”。提供第二表达时最多调用两次；未执行、额度耗尽、取消和不可用分别保留。
- 合并原 Source 已接纳的内容，按 Source/空间/ID 去重，保留原文；总内容最多12K字符、每项最多2K、最多12项，实际还受原会话剩余额度约束。
- 两次读取同一引用却得到不同正文时，该引用会移出本次结果并记录 conflicts；不能默默留下较早版本作为现行依据，也不会因此改写原记录。
- 每项标明 semanticMatch=not_verified，提醒模型自行核对是否真的回答问题。外部阅读经历标为 external_observation，显式旧画像为 history_marked/historical_only，更正原件为 correction_source；更正是否已生效仍需当前人物画像或应用回执。
- 空结果、无关命中或未执行不意味着记忆库不存在相关资料。不自动判定事实，不写记忆、用户画像、人格或情绪。

这是有据检索的组合入口，不是新增语义搜索引擎、答案审核模型，也不能保证消除所有漏召回。Web/主QQ会话中的使用以当前工具挂载和View许可为准；B站社交与其他QQ好友/群聊仍沿用自己的记忆管线和统一人物画像边界，未为它们开放主用户私密库。

## 验证边界

新增隔离测试覆盖公开 Source+实际 Native、原质量策略、普通共享额度、重复调用、当前ReadGrant、父授权、取消、隐私正文处理、历史标记与来源区分。既有画像跨平台、更正、群聊、普通好友隔离回归同时复验。

模型演练只使用脚本内完全虚构的故事和偏好，不读真实记忆。它验证模型能否自己提供检索词、在候选有噪声时有据作答或承认未知，不代表真实DSH平台聊天已端到端验收。

自动审批拒绝了将真实备份中的私密记忆发送到外部DeepSeek作额外测试，该动作没有执行；采用了完全合成资料作为替代。没有为测试而发送QQ/B站消息或植入生产记忆。

## 使用与迁移

日常可以自然提问，例如“还记得那次相机意外吗”“以前的约定后来怎么改了”。是否回忆、用什么检索词仍由同一模型决定，不能机械承诺每次必查。主用户通用称呼、兴趣等已验证画像仍优先参考现有常驻/统一人物画像；新工具不会替换它们。

沿用完整 runtime 迁移流程，无新增数据目录或数据库表；本地评估原始语料不会随源码或发布包带走。验收证据见 .work/recall-quality-*，包含样本和真实账号测试范围的限制。
