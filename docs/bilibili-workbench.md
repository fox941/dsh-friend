# DSH 的 B站工作台

版本：companion-adapter 0.76.0 / bilibili-tool 0.10.0。

活动兴趣提案、执行对象和前置资源检查的新边界见[活动可靠性说明](activity-reliability.md)。下方保留早期各版本验收历史。

## 打开与使用

刷新现有 DSH 页面，点击左侧「B站工作台」。如果入口折叠在「更多」，从那里打开或固定。它是 DSH 原生 main 面板，不是 iframe、外部静态网页或另一套聊天界面。

- 总览：当前是否有实际观看、待关注事件和已有操作；全局选择统一到独立活动中心。
- 观看任务：查看普通与连续任务、实际覆盖区间、字幕／音轨转写、既存画面原件、章节和未解问题。目录搜索不当成观看。连续任务的暂停／恢复复用原控制器，恢复只重新开放选择机会。
- 收件与回应：按现有私信和评论事件查看原文、选择、原会话范围、发送与读回回执。筛选作用于当前页，历史记录可翻页。
- 账号操作：收藏、关注及现有 bili_* 平台操作的候选、提交和核验结果；页面没有重复提交、批量发送或自动重试入口。
- 设置：沿用原白名单调整探索、冷却、收件、回复、收藏／关注能力与额度。修改前展示旧值和新值，提交时核对版本并记录回执。视频采样与窗口参数可受控编辑，保存后用于后续批次；当前批次和检查点继续使用原快照，见[视频参数在线配置](video-settings.md)。

页面开启时每20秒读取一次已有数据；隐藏、编辑、管理请求进行中或详情打开时暂缓自动更新。手动刷新也不调用模型、不发现视频、不轮询平台、不唤醒任务。账号详情中的「读取关注列表」是唯一按需平台读取，不自动执行。

## 数据与显示边界

任务与观察来自原 activity_runs、activity_video_readings、activity_observations、activity_video_segments；交流来自原 bili_inbox_* 与 bili_social_*；操作来自原 bili_account_* 与 platform_operations；活动选择统一在独立活动中心读取 attention_decisions。不另存页面快照、人格或长期记忆。

观察区间不等于逐帧理解。任务详情最多显示48张已经保存的画面、24段语言原件和32个派生章节；图片经过任务归属、原件哈希和媒体类型检查，通过现有 DSH 附件服务读取，不下载视频、不调用视觉模型、不向前端暴露本机路径。字幕与画面是原件，章节与摘要是派生理解。

没有正在执行的视频时显示近期任务，不说正在观看；没有选择依据时保持未知。账号绑定和最近轮询记录不等于登录此刻有效。接口接受、实际提交、曾读回和对方可见分别展示，不把未知回执当成成功。已有操作计数包含候选，不是「今天成功操作次数」。

## 管理一致性与权限

五个精确 Fetch 端点挂在现有 DSH /api 承载层，仅允许 owner。未登录返回401，agent 返回403；不再挂载 /dsh-bilibili-tool/api 原始 HTTP 路由。旧静态控制台与离线配置脚本仍可使用。

管理 POST 还要求真实同源 Origin、JSON、8KiB 请求体上限与字段白名单。页面既有输入使用转义输出。错误不携带原始凭据、本地路径或签名媒体地址。原件与接口响应均设置 no-store。

暂停／恢复检查连续任务的递增版本，不能重开已结束事项。设置检查有效配置、视频版本和管理版本，不能覆盖另一窗口的新修改。最近100条管理请求的编号、指纹和回执存入既有 platform_meta 的 bili-workbench:commands:v1；设置另存单调管理计数 bili-workbench:config-epoch。变更与回执在原 companion.sqlite 的同一事务完成，重复请求返回已有结果；结果不明不自动重试。

上述键属于操作记录，不是 AI 的人格或记忆。迁移继续使用现有完整 runtime 打包流程，无新数据库、服务或密钥。插件源码在 plugins/bilibili-tool/src；页面修改后运行 node scripts/build-bilibili-client.mjs 生成客户端入口，再走现有版本化插件安装流程。

## 实现与验证

复用已固定的 DSH rc.3 connection.fetch.register。此前 cannot get property "webServer" without inject 不能证明第三方页面不可行：旧 connection.rpc.handle 内部读取调用方上下文的 webServer，Mnemon 用显式 extend 传递该服务；本工作台沿用现有表情库的 Fetch 路径，避免这个 RPC 上下文依赖。

源码和真实安装包的同一套相关回归分别执行；另有真实 DSH 权限承载层、隔离浏览器交互、正式库只读兼容检查及部署后原生页面验收。临时合成视频与消息仅在独立测试库中，不写正式角色。准确结果以发布记录 .work/bilibili-workbench-release.json 与相关验收报告为准。

## 活动展示已独立

自0.74.1起，完整全局选择和运行过程统一到[活动中心](activity-center.md)。本工作台保留B站任务、事件、账号操作和设置，以及带原编号的活动跳转入口，不再重复展示全局最近选择。


活动额度与冷却现统一到[活动中心→活动设置](activity-center.md)。B站设置页保留视频观察参数、收件回复和账号操作；原活动表单替换为跳转入口。静态控制台/CLI作为维护入口继续读写同一份配置。
