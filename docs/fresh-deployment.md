# 空白部署实现与边界

空白部署是新建实例，与完整角色迁移分开。入口为 Pack-Fresh / Verify-Fresh / Install-Fresh，模型密钥通过目标 Configure-Model 设置。用户操作见根目录《家用电脑空白部署指南.md》。

## 打包

复用原代码文件白名单、路径检查、逐文件哈希与一致性核对、流式ZIP以及固定工具链。源码只读，不调用停止主实例，不访问 runtime 或原角色身份。tools 使用明确目录和NapCat程序文件白名单，排除 config、guild数据库、日志、缓存和本地认证文件；保留工具自带的 node_modules，避免损坏工具。根 npmrc 只生成无凭据的公共源配置。

清单协议 `ai-friend/fresh/1` 明确 `containsRuntime:false`、`containsCredentials:false`、`newIdentityOnTarget:true`，没有原身份和角色快照。整个包验证同时检查声明路径与额外文件；不能夹带 runtime 或 NapCat 运行配置。源码含疑似模型密钥会停止发布。代码和工具在复制、压缩后重新核对，变动不发布成功ZIP。

## 安装

要求空目标或同包中断安装。先写 `.fresh-install.json`，原 Host/运行保护共用的 assertNoMigration 会拒绝尚未完成的空白安装。复制完成后在目标执行原 Setup.ps1，使用空 profile 初始化原插件，再通过 Journal/GrowthStore 创建新UUID及零条成长记录。不复制源profile、不预填用户画像/性格或情绪。原长期记忆由既有插件首次启动时创建空容器。

`.fresh.lock` 防止并发安装。锁记录包ID和进程，只允许同包重试回收已退出安装进程的锁。中断时不删除身份或数据库；初始化有本次 fresh-origin 标记，空白检查通过才可续用本次刚生成的UUID。已有私人记忆、工作区资料或平台配置会停止初始化。安装成功后重复执行不重新初始化。

不自动启动模型、平台或自启任务。模型密钥仅在目标隐藏输入，写入新的 credentials.local.json；不作为进程命令行参数传递，不覆盖已存密钥。QQ/B站在目标重新配置与验证。

## 保留项与限制

旧完整迁移入口不变；公司角色不删除、不改名，也不转成家用角色。操作设置使用代码默认值，源机 runtime 内的个性化参数不自动携带。平台账户本身的服务器历史、好友、昵称、头像、收藏等仍存在；空白本地记忆不等于新平台账号。Python虚拟环境有路径依赖，推荐相同D盘路径，跨路径需重装媒体工具。

验证记录见 `.work/fresh-deployment-release.json`。本机隔离安装与家用机器实际登录、硬件兼容性分别记录，不把模拟或本机通过说成已完成跨电脑验收。
