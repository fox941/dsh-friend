# 任意电脑的代码更新、独立预览与受保护回退

架构 v0.34，更新工具 1.0.0。现有 DSH、Mnemon、companion-adapter 0.29.0 和 attention-scheduler 0.2.0 的版本不因此改变。

## 使用流程

公司和家里都可以开发、打包和接收更新。源电脑决定要发布哪份源码，目标电脑使用自己的角色、配置和模型密钥验收；代码同步不包含记忆同步。

1. **源电脑运行 `Pack-Update.cmd`**。将当前源码和自研插件打成更新目录、ZIP 与 ZIP 的 SHA256，输出到 `releases/updates`。打包不停止 Main，也不把该电脑的角色、会话、情绪、密钥、QQ／B站登录信息和工具目录带走。
2. 私下传输 ZIP，完整解压。目标电脑使用自己项目根目录的 **`Verify-Update.cmd`**，输入包含 `update.json` 的解压目录。可对照源电脑的 `.sha256`；校验和用于发现损坏，不是发布者签名，只使用自己认可的代码来源。
3. 目标电脑运行 **`Preview-Update.cmd`**，输入同一目录。它会停止普通 Test，用该包的源码及冻结依赖创建临时测试项目，执行回归、启动真实 DSH/Native，并进行一次真实模型文本测试。Main 可以继续运行。模型测试使用目标电脑的密钥，会产生少量 API 费用；网络或模型故障也会使本次预览不通过，可以重试。
4. 本机预览成功后运行 **`Apply-Update.cmd`**，输入同一目录。它停止 Main/Test，保存代码与角色快照，替换代码和 Main 的插件安装元数据，安装冻结依赖并核验身份及记忆服务。成功后启动 Main；失败保留检查点，不自动创建角色或覆盖角色数据。
5. 普通 Test 保持停止。后续运行 **`Setup-Test.cmd`** 安装当前版本到普通 Test，再用 `Start-Test.cmd` 启动；其原测试身份和记忆保留。

可通过命令行避免重复输入：

```powershell
.\scripts\Update.ps1 -Action Verify -Bundle 'E:\更新包\ai-friend-update-本次编号'
.\scripts\Update.ps1 -Action Preview -Bundle 'E:\更新包\ai-friend-update-本次编号'
.\scripts\Update.ps1 -Action Apply -Bundle 'E:\更新包\ai-friend-update-本次编号'
```

已拉取 Git 源码也不能直接等同于完成插件升级。推荐先在开发电脑生成上述更新包，再走目标电脑预览和安装；开发提交、分支合并及推送仍由 Git 管理，工具不会替你推送仓库，也不合并两台电脑的运行数据。

## 文件与数据

| 内容 | 处理方式 |
|---|---|
| `scripts`、`plugins`、`docs`、`tests`、根启动器和项目声明文件 | 列入程序白名单，逐文件核对 SHA256 |
| 更新包的 `profile` | 只有包声明、冻结锁文件和自研插件安装包／回执，没有外来用户配置 |
| 目标电脑 `runtime/dev` 的人格、记忆、会话、原话、凭据、平台设置 | 沿用本机文件；更新包不能提供这些文件 |
| 目标 Main 的 profile 包、锁文件及 `.friend-packages` | 更新为新代码对应的安装版本 |
| Main 的 `cordis.patch.yml` | 保留本机设置，不用源电脑配置覆盖 |
| 普通 `runtime/test` | 停止并备份，数据保持原样，稍后用 Setup-Test 更新插件 |
| 临时测试项目 | `.work/up/<短编号-随机值>`，新身份和空白测试记忆，平台关闭 |
| 升级备份与检查点 | `backups/updates/update-<事务编号>` |

临时预览使用独立程序目录，因此不依赖“Main/Test 共用源码也算代码隔离”的假设。它不复制主角色的私密记忆；仅将目标电脑的模型密钥临时写入测试凭据文件，在退出时清理。测试回归、模型结果与故障日志留在对应 `.work` 目录，方便排查。预览阶段会暂停普通 Test，不自动恢复它。

## 升级约束与中断恢复

预览回执绑定更新清单哈希、本机路径和预览时的程序文件哈希。换包、换电脑，或预览后再修改本机源码，都必须重新预览。没有回执时不会先停止 Main。

升级操作串行执行。`.update-pending.json` 在事务未完成时阻止普通启动、恢复运行、Setup 和迁移；只有仍存活的升级进程可授权一次受监督的健康验证启动。角色 UUID、受保护数据、包哈希或文件归属异常会停止操作，未知进程不会被强杀。

复制时只接受计划中的旧文件或新文件哈希。失败后保留原包，运行 `Update-Status.cmd` 查看事务路径，再对同一包重试 `Apply-Update.cmd`。工具不会用历史快照自动覆盖当前记忆；安装日志在 `.work/update-install.log`，控制日志为 `.work/update-main-control.log`。

升级前快照必须一致。如果其他维护程序或平台助手仍在写相关文件，备份可能被拒绝，应先停止对应写入再重试。不要删除记忆数据库或检查点来绕过保护。

## 回退规则

`Rollback-Update.cmd` 默认选择当前未完成事务，否则选择最近一次升级。也可指定：

```powershell
.\scripts\Update.ps1 -Action Rollback -Transaction 'D:\ai friend\backups\updates\update-事务编号'
```

回退会先正常停止 Main/Test，只还原该事务的代码及 Main 插件安装元数据，并重新安装原冻结依赖，**不恢复旧角色数据库**。完成后保持停止，由你运行 `Start-Main.cmd`。

只有角色文件仍与升级前的受保护数据一致，才允许回退。新对话、记忆、后台处理或其他状态变化均可能使回退被拒绝；文件级检查是保守规则，不会自动判断哪些新内容可以丢弃。此时保留当前数据，使用原包继续修复或发布向前兼容的修复版本。不能承诺使用新版数天后仍可一键无损回退。

## 首版范围

支持当前固定 Windows x64、Node 24.22.1、DSH/Mnemon 及根锁文件不变的代码与自研插件升级。自研插件修改源码后必须增加其版本，不能把同版本不同内容交给缓存解析。

基础依赖、根锁文件、工具链变化，或涉及现有存储实现文件的变化，会被普通升级入口拒绝。这是保守兼容门槛，不代表已经自动证明了任意新代码的语义兼容；涉及数据库迁移，需要单独设计和验证。当前没有自动执行任意迁移脚本、跨路径重绑定、后台自动下载安装或无人值守发布。

首次安装本工具后才能使用上述入口。首次把角色迁到另一台电脑仍使用完整 `Pack-Migration`／`Restore-Migration`，不是代码更新包。迁移和升级是两个不同流程。

## 验证记录

2026-10-30：最终候选 871 项回归通过，包含 21 项更新包／事务／回退专项，以及两项冷启动保护回归。独立演练实际生成并解压 ZIP，使用包内源码启动临时 Test、执行全套回归及真实 DeepSeek 测试；原隔离 Main 在预览时保持运行。

演练将隔离 Main 的实际陪伴插件从 0.29.0 更新到 0.29.1，验证升级前原会话继续回答临时代号，原 Native 记忆保留；受控安装失败可回退兼容代码，升级后产生新对话则拒绝回退。0.29.1 仅为演练包的版本，当前正式陪伴插件仍为 0.29.0，没有发布该测试版本或向真实 QQ／B站发送消息。

演练同时发现并修复 Windows 预览目录过长、冷 SDK 加载短暂阻塞控制管道的问题：临时目录使用短路径；只对本次启动、PID 一致的 Host 使用既有 90 秒启动宽限，未知进程和超时仍保留现场，不重复拉起或强杀。发布记录为 `.work/code-update-release.json`，实际演练记录为 `.work/code-update-integration.json`。这不替代家用电脑的首次迁移验收。
