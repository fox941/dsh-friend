# 已读 QQ 媒体的调度预览修复

companion-adapter 0.49.1；QQ 桥接继续使用 0.13.0。

真实验收发现：图片和语音已经被聊天阶段实际读取并回复，媒体经历任务也已经保存来源证明，但反思候选的预览仍取平台原消息的“媒体消息，尚未读取内容”占位。调度模型据此反复选择等待，而非依据实际内容决定是否反思。

修复由 `social-experience-source.js` 生成调度预览。先校验原消息、来源证明与观察记录，再呈现最多 1,600 字符的已读内容、读取时间、媒体数量、识别不确定性、是否截断和当前阶段 `after_actual_media_read`。有实际发送回执时另附最多 700 字符的自身回复，不把自身回复当成外部观察引文，也不声称对方已读。

来源失效时预览明确标为 `source_unavailable`，不继续呈现旧观察或声称只是尚未首次读取。候选状态键带预览协议版本，使新进程重新考虑原有待办。没有修改调度器源码，没有强制开始、自动批准提案、补发旧聊天、重新识别媒体或改写待办的历史选择理由。

原有等待中的任务保留，部署后仍由同一模型决定反思、延后或放下。最终提交继续走 0.49.0 的冻结来源、独立审核、有变更才备份和提交前复查。

## 发布与真实结果

0.49.1 源码及实际安装包各 1542 项回归通过，3 组官方模型验证能在旧“未读”工作记录下识别实际已读阶段。四个插件源码及实际安装字节核对通过。原等待任务在升级后由同一模型接续：图片实际评价为 no_change；低信息量的第二段语音及“徒步”文字被主动放下；第一段语音进入评价，但因状态键格式不合规而在写入前失败。自我版本7、情绪版本2保持。

用户确认图片描述和雨崩/自由讨论两轮回复均在手机群里可见。图片评价通过不等于语音成长写入通过，后者仍未完成。证据：.work/qq-social-media-experience-live-acceptance.json。
