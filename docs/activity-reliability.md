# 活动执行边界修复

版本：companion-adapter 0.76.0 / bilibili-tool 0.10.0 / attention-scheduler 0.3.0。活动中心 0.2.0、QQ 桥 0.20.0 保持原版。发布状态以 `.work/activity-reliability-release.json` 为准。

## 原因与结果

1. 视频已经读到内容，却在成长写入时因兴趣键包含 `interest:`、顿号等字符失败。现在反思完成时先按成长层原有规则校验键、内容和理由长度；不悄悄删标点或合并名称。完整输出的格式错误沿用原来最多一次的纠正，模型可换成合法键，也可不提出兴趣变化。仍无效则停止后续写入，保留真实观察与失败回执。已发生的记忆写入若遇到其他后续错误，仍保留真实回执，不声称整批未发生。
2. 通用 browse 事项以前默认交给 B站，读论文原文可能被替换成看检索教程。现在同一次全局选择必须为该事项明确执行目标 `bilibili_video` 或 `external_document`。只有视频目标进入视频执行器；网页/论文原文任务保留等待 capability_change，不发起 B站搜索、不消耗观看额度。没有新增通用网页或论文阅读器，也不使用关键词屏蔽：确实想看论文检索教程时仍可选视频。手动观看请求、续看检查点、账号操作及 QQ 平台事件沿原通道。
3. 过去模型先选择视频任务，执行器才发现额度不足，可能反复选择和暂缓。现在在模型调用前以只读资源检查筛掉当前不能执行的自动视频事项，按原来的冷却时刻、次日窗口或开关变化等待。其他候选仍由模型自主选择；不强制先聊 QQ。检查期间发生新事件会使旧检查失效，真正执行前保留原来的再次检查，避免并发消耗后使用过期准入。

## 自主性与成本

额度、冷却、重试次数均未放大，不清零当日使用次数。没有增加额外路由模型：执行对象由原全局选择模型在同一份候选和协议中决定。资源不可用的事项无需再付费选择一次；格式纠正最多沿原有一次机制执行。资源检查失败只延后该事项并记录错误，不挡住其他就绪事项。

自动主题标为 autonomous，明确请求标为 explicit_request；来源由执行入口确定，不信任调用者自己传入的标签。反思不能把自主主题冒称为主用户的原话。活动中心将资源/能力等待与最近一次模型的安静选择分别呈现；等待资源不是情绪判断。

## 数据及恢复

沿用原 attention_*、activity_*、成长与记忆存储，没有新增数据库或重建人格。旧观察、失败事项、使用次数、已保存记忆均保留，不自动重放旧失败任务。此前已误入视频流程的历史任务也不改写成正确执行；新事件和正常唤醒按新边界处理。

以后若接入文档阅读能力，需要注册真正的读取执行器和来源证据核验，再通过 capability_change 重新考虑等待事项；不能只发一个唤醒信号就声称已经具备能力。当前版本的外部文档候选被明确保留为不支持，等待真实接入。

## 验证方式

隔离用例覆盖：非法兴趣键的一次纠正及保留原件、后续写入失败回执、自动来源标记、额度耗尽前置检查、QQ 混合候选仍可自主休息、检查期间新事件、单项检查异常、选择后的资源竞争、论文原文等待、合法教程视频、路由一次纠正、手动和 QQ 分支兼容。源码测试显式重定向调度依赖，避免工作区 node_modules 指向正式旧包；另在独立安装实例验证实际 tgz。最终数量及部署验收见发布记录。
