# 陪伴适配插件 0.1.1

更新：2026-10-27。代码位于 plugins/companion-adapter，JavaScript ES Modules，使用 DSH 公开插件接口、Mnemon 扩展 SDK 和 Native CLI；不修改上游或第三方源代码，不新增模型、数据库服务或向量库。

## 本次行为

当用户明确更正当前长期事实时，模型先召回旧条目，再调用 friend_memory_correct。插件检查本轮主用户原话引用、激活空间和旧内容快照，写入完整新条目并读回核验，之后软删除旧条目，最后提交纠错日志。后续正常召回使用最新条目；friend_memory_history 单独查询旧版本。

连续更正复用同一事实链。保留未改动字段、分类、重要度、标签及实体；新来源为 user，旧来源存入历史。Native 当前公开插件未暴露 supersedes 边，本实现不假装已写入该关系，而以旧记录软删除和独立历史链管理版本。

普通聊天默认简短回应；用户要求简短时加入本轮展示约束，减少技术回执，不截断用户要求的详细回答。没有预填名字、性格、称呼或关系。模型仍可能措辞冗长或误解语境，规则不是输出长度或语义正确性的硬保证。

运行快照来自当前 profile、可见工具和激活目录，也通过只读 SQLite EXISTS 查询检查激活长期空间是否存在有效记录；未知时明确标为未知，不凭热记忆为空推断长期库为空。说明同一实例已保存资料可跨会话使用，区分可用能力与实际执行记录。没有浏览回执时不得编造刷视频；当前实际配置渠道只有 Web。

## 恢复、停用与迁移

持久数据是 runtime/dev/companion/companion.sqlite，SQLite WAL + FULL 同步，包含旧快照、新内容、用户依据、后端 ID、阶段、暂停状态和少量工具执行元数据。它不是人格状态或长期检索引擎。

跨 Native 与日志库不能做一个原子事务，因此使用可重试步骤。写新失败保留旧记录；写入成功但回执丢失时，通过 Native 精确去重确认已有条目。启动最多恢复三项未主动取消的操作；其余通过明确重试继续。取消后暂停恢复，但已提交的后端步骤不自动回滚。失败和待处理状态不算保存完成。

常驻画像/工作记忆由模型使用 Mnemon 原有 Runtime 替换工具同步更新，不直接重写 JSON。长期与 Runtime 的更新不是跨源事务；必须查看两边实际回执。不能保证绕过本工具的手工修改、第三方写入或所有重复条目自动纳入历史。

完整备份继续使用 Stop-Dev.cmd 后 Backup-Dev.cmd，包含整个实例的 companion、memory、会话、配置、锁文件和 .friend-packages。安装包路径相对 profile，Setup 按锁文件重装依赖。更换目录仍需重绑原有绝对路径；本次未完成跨机器启动验收。单独 Mnemon 导出不包含本插件完整历史。

插件代码更改必须提升 package.json 版本，再停机执行 Setup.ps1。相同版本源码变化时安装脚本拒绝覆盖，避免旧包与新源码混用。安装记录在 profile/.friend-packages/adapter-install.json，包含源码摘要和安装包 SHA256。

在插件配置停用 friend-adapter 后，子插件会等待可选服务，基础聊天和原有 Mnemon 继续工作。彻底卸载包前，还应移除 companion 预设中的 friend-interaction 引用；不删除 runtime 数据。

## 验收范围和限制

自动测试覆盖故障恢复、取消、重复执行、并发冲突、旧快照拒绝、Native 去重回执、来源与作用域、真实 Native 连续更正。另用独立 DSH_HOME、工作目录和虚构资料执行真实 DeepSeek 对话，检查跨会话、清除热记忆后的召回、热副本更新、连续更正、历史、重启以及停用插件。

语义对应、条件事实、反讽与未来生效时间仍依赖模型正确理解，不能用这组小样本证明长期人格质量。配置 DSH 接管的自定义嵌入路由后，本版适配写入会暂停，普通 Mnemon 不因此被替代。
