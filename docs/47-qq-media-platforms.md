# QQ 多媒体、群聊与新增平台操作

架构 v0.39，陪伴插件 0.32.0，独立 QQ 桥接 0.2.0，NapCat 本机扩展 0.1.0。沿用 DSH、Mnemon／Native、原人格和统一注意力，没有迁移记忆后端或修改 DSH 源码。NapCat 原始引擎保留，使用下文注明的独立兼容入口加载本项目扩展。QQ 收发、媒体和账号协议实现已移入 `plugins/qq-bridge`；陪伴层保留人格、记忆、模型和统一调度接口，详情见 [独立 QQ 桥接](48-qq-bridge.md)。

## 可用能力

| 入口 | 实现 |
| --- | --- |
| QQ 图片 | 实际下载已核验的 QQ 图片，保存附件后调用当前模型理解；可选择向原联系人或已接入群发送实际图片 |
| QQ 语音 | 本地 FFmpeg＋原 Whisper 转写，区分识别文本与用户逐字文字；可用固定版 Edge TTS 合成中文待发送语音 |
| 引用与合并转发 | 通过原消息／转发 ID 读取，引用必须属于原话题，转发作者标记不能冒充当前发言者 |
| QQ 群聊 | 首次接入 719030047，非 @ 消息也可以成为关注候选，由模型选择回复、等待或忽略 |
| QQ 好友 | 好友列表、已有好友的独立私聊、在线收到的好友申请同意／拒绝、删除好友；禁止删除主用户 |
| QQ 群操作 | 实际群邀请同意／拒绝、主动申请加入指定群、退出群；不通过退群入口解散群 |
| QQ 头像 | 使用已经实际读取且内容哈希匹配的图片设置头像；主用户私聊图片需明确原话允许用作头像 |
| QQ 空间 | 读取可访问的近期说说／指定原件、发布纯文字说说、评论指定说说 |
| B站 | 新增视频点赞／取消点赞、投币、发布纯文字动态；原收藏／关注、私信与评论继续沿用 |

可直接说“看一下我发的图”“听听这条语音”“把这张图片设为你的头像”“给 BV……点个赞”“给 BV……投一个币”。这些请求会形成原件或操作候选，仍允许模型按上下文重新考虑；排队不表示已执行。

主用户可以查询 `friend_platform_status`、`friend_qq_contacts_read`、`friend_qq_social_read`；修改社交范围和额度使用 `friend_platform_control`。工具详情用于核验，不要求普通聊天逐项展示技术字段。

## 统一行为与资料范围

QQ 群、其他好友和请求通知转换为持久事件，账号操作转换为候选；二者使用原注意力的 browse 载体，以 platformEventId／platformActionId 明确区分，实际执行器不会将它们当成视频。没有固定聊天优先级，也不要求被 @ 就必须回复。QQ 断线时先等待连接恢复。

主用户私聊继续使用原会话和原身份。群与其他好友采用按账号、群号／对方 QQ 号隔离的话题历史，只提供同一角色的可用性格、兴趣和感受摘要，不加载主用户私密记忆、目标或聊天，也不开放主用户工具。主用户在群里发言仍属于群话题，不提升为私聊权限。外部消息可以提供有来源的情绪评价线索，仍经过原独立审核；不会把所有群消息直接写进主用户画像。

决定处理主用户消息后才进行媒体感知，并在表达前提供实际结果；忽略的消息不预先调用识图。图片解读、语音转写、引用和转发分别标注来源，不拼成主用户逐字原话或账号操作授权。撤回／停止后检查原件状态，避免继续提交旧回应。主用户私聊图片向外发送或设头像需要本轮真实文字中的明确分享依据。

## 主动加群与执行回执

NapCat 普通 `set_group_add_request` 处理已有请求／邀请，不能拿群号冒充 flag。主动加入使用本项目的独立 NapCat 插件，通过已核对的 QQ 内核 `reqToJoinGroup` 调用提交；先实际查询群名、入群方式、验证问题和容量。

本机扩展仅监听随机本地端口，要求随机 Bearer 令牌和原 AI QQ 身份；不提供任意内核调用接口。每个申请先写持久操作键，同一键不会重复调用；超时不换另一条写路径重试。原生无明确回执只记为提交未确认。需要审核的群保持“等待审核”，实际群列表出现后才确认入群，并把本次已确认加入的群纳入接入范围。用户已允许自主加群；不能绕过验证题、验证码或群主审核。

账号操作区分 queued、accepted、confirmed、unknown、unconfirmed 等状态。点赞、投币、好友关系、群成员关系及发布原件尽量读回核对；API 受理不等于公开可见或对方已读。发送结果不明不会重发；只读核验有退避和次数上限。B站新写操作复用原共享限流和发送边界，不另外绕开原风控状态。

## 参数与当前范围

- QQ 每次最多读取 4 张图片、2 条语音；图片上限 8 MiB，语音转写最多前 180 秒。超过范围明确保留未读说明。
- 转发展开最多两层，展开处理总量有界；不会读取任意本地路径或任意 URL，引用不跨私聊／群范围。
- 新增账号操作默认每天 30 次，B站投币默认每天 4 枚、单片每次 1–2 枚且不超过平台单片余量。投币消耗 AI 账号已有硬币，不充值、不支付。这些额度不等于消息接收的每日回合额度。
- 其他好友／群的待发文字最长 1500 字符，超过 15 分钟需重新考虑。语音合成正文最长 1000 字符。
- 中文合成采用 edge-tts 7.3.1，只将待说正文提交给 Edge 在线语音服务，不带 QQ／B站 Cookie 或模型密钥；网络不可用时明确失败。语音识别继续在本机执行。
- 视觉步骤针对当前 DeepSeek Flash 使用关闭推理模式；自主选择、情绪、成长和普通表达仍沿用各自设置。实测同一红色图片在低推理视觉请求中曾被误判为绿／白，关闭该视觉步骤的推理后正确识别；这不构成任意图片零误判的保证。

本次空间和 B站动态支持纯文字，不含图片动态、视频投稿、支付或批量操作。好友管理支持实际收到的申请，不宣称已经支持按任意 QQ 号主动添加好友。更深／更多转发、长语音后半部分以及更复杂的视听仍需后续扩展。

| `.tools/voice`、`scripts/voice-requirements.lock.txt` | 独立固定版语音合成环境及锁定依赖 |

手动备份和迁移仍携带整个停机 runtime 与匹配代码／工具，不单独搬一个记忆数据库。NapCat 扩展由安装脚本同步并在 QQ 插件加载时启用；它的源码或版本变化需要专门核对，普通代码更新会拒绝悄悄换掉该内核扩展。Test 禁用所有新平台服务，工具守卫同样拒绝平台调用。

实际固定版 NapCat 的加载器只接受官方插件名单，普通安装目录和启用标记并不足以加载自研扩展。启动脚本先校验原始 4.18.41 引擎的完整 SHA-256，再生成同目录的独立兼容文件；两处改动是在加载名单中增加 `ai-friend-social-helper`，并让原有工作进程继续启动同一兼容入口，其余检查和进程管理保持原样。原件、兼容件和校验记录都保留，已有兼容件不一致时拒绝覆盖。更换 NapCat 版本必须重新评估，不能直接套用。撤销兼容时将启动入口恢复为原始 napcat.mjs；这会停止主动加群扩展，不删除记忆或入群操作账本。

## 验证状态

0.30.3：真实语音测试曾在生成前被调度模型忽略，原因是把 `perception.eligible=false`（禁止附带情绪提案）误读为消息不值得处理。传给模型的字段现明确为 `emotionProposalContext.allowedToPropose`，并标记仅用于情绪提案；原后端的学习禁止和来源审核保留。测试／只查询／不保存记忆依然可以进入正常理解和工具使用，模型也仍可依真实语境选择沉默，不设置测试消息必回规则。

0.30.2 的真人验收已覆盖引用原图、合并转发文字展开和作者区分，并发现转发图片不一定进入 NapCat 的 get_image 本地索引。图片读取现优先使用该消息原件携带、通过同样白名单及字节检查的 QQ CDN 地址；地址失效或内容无效时才查询 OneBot 补取。取消读取后不再启动补查。原失败记录保留，不修改历史结果来冒充当时已成功读取。群聊接续、语音发送及转发图片复测以 `.work/qq-social-acceptance.json` 的实际结果为准。

隔离验证包括真实 DSH／Native／DeepSeek、模拟 OneBot 的图片实际识别与中文语音转写后回应；Edge 中文语音合成和原本地 ASR 已实际连通，未写正式角色记忆或向真实联系人发送验收消息。首次失败及视觉请求修正记录保留，不以文件读取成功代替识别成功。

真实平台的好友删除、退群、换头像、投币、说说和动态发布没有通过测试随意执行；其真实账号受理及可见性应逐项核对。本机 QQ 登录、指定群成员状态和扩展加载结果以发布记录为准，不把模拟协议或单元测试称为真实 QQ 收发验收。发布记录为 `.work/platform-release.json`，隔离联调为 `.work/platform-integration.json`。
