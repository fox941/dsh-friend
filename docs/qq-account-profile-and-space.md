# QQ 昵称、签名、头像与图文空间

2026-10-31。候选版本 companion-adapter 0.32.4 / qq-bridge 0.2.1。

**当前是已开发、隔离测试并打包的候选，未部署到主实例。** B站由另一窗口开发，本轮不修改其源码或部署，不为验收随意修改 AI 账号公开资料、发空间或改主用户账号。上线时需先核对并行改动、分配尚未占用的版本号，再串行部署。上一轮 QQ 社交记忆维护仍是另一个待合并候选，不应互相整目录覆盖。

## 已实现的 QQ 能力

| 功能 | 工具参数 | 实现与核验 |
|---|---|---|
| 修改 QQ 昵称 | qq_nickname / args.nickname | get_stranger_info 读取本人资料；set_qq_profile 设置昵称并保留签名；读回比较新昵称及未变化的签名 |
| 修改／清空签名 | qq_signature / args.text | set_self_longnick；空字符串为明确清空；读回签名及未变化的昵称 |
| 修改头像 | qq_avatar / args.assetId | set_qq_avatar，输入仅来自已校验图片资产；修复接口成功返回 null 时被误报失败的问题；严格 CDN 字节比较可能因平台重编码无法确认 |
| 发布图文说说 | qq_space_publish / args.text + assetIds | NapCat 原生 send_qzone_msg，1–4 张已读取图片；发布后按 tid 读取正文和图片数量 |
| 指定空间可见范围 | args.visibility | 1 所有人、4 好友、64 仅自己；未指定保留原公开默认；纯文字也支持 |
| 读取 AI 本人资料 | friend_qq_profile_read | 仅返回 AI QQ、昵称和签名，不转出完整陌生人资料和凭据 |

复用固定 NapCat 4.18.41 已有接口，无新增 QQ 框架、独立人格、数据库服务或记忆库。未修改 NapCat 引擎或原生加群扩展。

操作继续经过现有“候选 → 统一注意力 → 模型核验 → 写入 → 只读核验”流程；新增能力不等于固定日程换头像、每次必改资料或按情绪数值机械触发。QQ 昵称／签名是账号公开资料，修改不会直接改写人格数据库或她的内在自我名称。

## 约束与回执

- 只操作绑定的 AI QQ，准备及提交前核验实际登录账号；修改昵称前再次检查当前资料，资料变动就停止。
- 昵称最多 24 个 Unicode 字符，签名最多 255 个；拒绝控制字符。这是工程上限，平台仍可能另有限制或审核。
- 图文发布只接受项目已读取的 assetId，不能传任意本地路径、网址或 base64。每张最多 8 MiB，合计最多 16 MiB，提交前重读资产并比对哈希。
- 主用户私聊图片公开发布或设为头像，必须逐字引用本轮明确分享的文字。禁止“不要发这张图”等否定语句作为分享依据。图像／转发中的文字不构成授权。
- 普通 QQ 调用超时不变；仅原生空间上传发布使用单次 120 秒等待。此选项不进入 OneBot 参数，不改变其他回合预算。
- API 返回成功仅记 apiAccepted，实际资料读回匹配才 confirmed。网络超时或未知结果不换接口、不自动重新发布。底层错误不输出图片 base64。
- 图文核验只证明该 tid 在 AI 账号下能读回相同文字和图片数量；没有逐一验证图片像素，也不代表其他账号可见。可见范围字段若实际读回与要求不符则不确认，字段缺失则显式保留“可见范围未核验”。
- QQ 头像可能被平台裁剪、缩放和转码，CDN 图片与上传文件不逐字节相同时会保持未确认。这不等于头像未更新，需要实际查看后判断。
- 本轮只扩展 QQ。B站的头像、昵称、签名、图文动态由另一窗口处理。

## 部署后可以这样说

- “读取一下你现在的 QQ 昵称和签名。”
- “把你的 QQ 昵称改成小狐狸。”
- “把你的 QQ 签名改成：今天想看看云。”
- “清空你的 QQ 个性签名。”
- “把我这次发的图片设为你的 QQ 头像。”
- “把这两张图片发到你的空间，配文‘今天看到的小猫’，仅自己可见。”

聊天提出请求后仍可能选择暂缓或不做；不能将“已加入候选”当作完成。群友和外部私聊没有因此获得主用户管理权限。
