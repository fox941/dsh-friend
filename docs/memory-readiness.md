# 长期库初始化、分层检索与夜间诊断

适用版本：companion-adapter 0.79.1，2026-11-07。

## 已实现

1. 正常 Host 启动后，通过 Mnemon 的公开接口检查空间目录。首次空白部署没有空间、没有遗留数据库时，创建并启用一个空的 Native 空间。空库可以查询，无命中不等于服务不可用。
2. 已有启用空间只读检查；所有旧空间被停用时不替用户重新启用。发现未注册的旧数据库时保留原件，不创建新空库掩盖它。创建回执不明确时不盲目重发；激活失败可继续核对已确认创建的同一空间。
3. 新增 `friend_workshop_search`，实时检索工作间当前文本的文件名与内容，返回路径、版本、摘要和作品标记；随后使用 `friend_workshop_read` 读取。不是全盘搜索，不扫描历史版本，不将梦、小说、日记自动写成长期事实。
4. 新增 `friend_library_search`，分别调用原权限下的长期召回、项目档案搜索和工作间搜索。保留各来源状态与查询额度；一层不可用不遮蔽其他层，不直接绕过 Source/View 读取数据库。
5. 对 Native 的精确 `空间名: sparse_results` 无命中提示进行兼容处理，保留提示元数据。未知错误、混合故障仍保持 unavailable，不把所有错误都当空库。
6. `friend_nightly_read` 返回诊断：预演／应用阶段、原报告与应用编号、已保存的审核调用信息和错误分类。它不代替审核、不增加额度、不重做已经完成的任务。

初始化回执位于当前实例 `operations/memory-bootstrap.json`。工作文件仍在当前实例 `workshop/files`；会话日志、常驻记忆和 Native 数据库沿用原路径。本次没有数据库结构迁移，也没有复制公司电脑的记忆到家里。

## 家里更新

推荐沿用 [代码更新流程](45-code-updates.md)：源电脑 `Pack-Update.cmd`，目标电脑依次 Verify、Preview、Apply。只拉取 Git 源码不会自动替换已经安装的插件包；必须完成原安装／更新流程，启动新版 Host 才会执行初始化检查。不要重新安装空白包覆盖现有 runtime。

若新版启动后仍不可用，先看 `operations/memory-bootstrap.json`：

| 状态 | 含义及处理 |
|---|---|
| ready | 已有激活空间；无命中不说明数据丢失 |
| no_active_spaces | 在记忆系统页面选择原空间并启用，保留原选择 |
| unregistered_stores | 原数据库存在但未注册；核对原注册信息后恢复，不删除数据库 |
| creation_unknown | 上次创建未取得明确回执；核对目录及日志，不反复创建 |
| native_unavailable / service_unavailable | 排查 Native 或接口故障，不能靠重置记忆解决 |

只读状态检查也可运行现有 `scripts/initialize-memory.mjs`；其在真正空白实例上可能创建首个空间，不能把它当作任何情况下都完全无写入的命令。主实例默认是 runtime/dev，Test 使用独立目录。

## 本次没有实现的内容

自动导入所有聊天、将所有日记同步进长期库、把零变化视为审核失败，以及新的共同经历专用写入入口，均不属于本次修复。自我状态 revision 0 可能是没有通过成长提案，并不单独证明存储坏了。家里那次“提案应用审核未完成”需在家里读取原失败回执，不能用本机最近成功记录代替诊断。
