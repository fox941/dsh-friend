## 发现的问题

2026-11-03：原Host和守护进程仍实际存活，原令牌、PID、记录启动时间与实例/项目路径均通过控制通道核验，QQ实际账号3197399707正常。新命令计算的Windows开机时间哈希与保存值不同，旧recordAlive却直接返回false，导致外部状态命令误报dead，并跳过后续鉴权。

本机另有15.2002毫秒的系统校时事件；目前没有证明它恰好解释哈希差异，不据此断言唯一触发原因。确定的代码错误是把哈希不同当成进程已退出的充分证据。

## 修改

- 先检查实际PID是否存在。新增进程记录保存操作系统创建标识：Windows读取Process.StartTime转为UTC FILETIME字符串，Linux使用boot_id和/proc启动tick的组合摘要。JSON记录写入时间仅用于控制通道核验，不能替代进程创建标识。
- PID不存在才确认退出；创建标识可比较且改变才确认PID被复用。身份查询失败、缺少字段、格式不支持均按“仍需保留”处理，不能放开离线锁。
- 开机哈希仅为兼容元数据，不再单独证明死亡。旧记录没有创建标识时，存活PID继续阻止重复启动与离线写入；Host状态可通过原令牌和PID/启动时间/实例/项目路径交叉验证为running。
- Host与守护进程的控制通道统一检查归属。归属不符、认证失败或暂时无响应时保留现场；不会强杀未知进程。健康响应上限由32KiB调整为有界的1MiB，避免正常的较长快照被误判无响应。
- Host、守护、离线维护和自启动的新增记录均携带创建标识。相同PID的旧版存活锁无法确认时，可能需要人工核验，这是保守处理的代价；不自动删除它来让维护继续。

查看状态、重复Start及Recover仍只接管已核验的原实例。QQ离线、模型静默、任务暂缓和视频观看不属于进程已退出，不会因此启动第二实例或强迫回复。
