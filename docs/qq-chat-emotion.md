# QQ 聊天临时感受与深度反思分离

适用版本：companion-adapter 0.51.0、qq-bridge 0.14.0。B站插件和调度器包未修改。

## 目的和范围

QQ群、普通好友私聊过去只有在统一关注机制选择背景反思后，才会提出情绪变化。现在正常表达模型可在同一次输出中附 `emotionProposals`，通常为空。它可以回答、暂缓、忽略；选择不深度反思，也不再自动等于没有临时感受。模型仍可完全不改变情绪。不预设性格、情绪映射或赞美/辱骂的固定反应。

本轮只覆盖 QQ 群和普通好友私聊。主用户 QQ 私聊沿用原 DSH 会话及原情绪工具；QQ空间、B站沿用既有路径。长期兴趣、性格、自我描述、个人提示词仍通过原深度反思和成长审核。本次不改用户画像、长期社交记忆或回复优先级。

## 处理过程

1. 表达前只准备当前真实原件的情绪依据：当前发送者、当前会话、当前实际已读媒体观察。没有可核验的原件则禁止提案，聊天照常。
2. 同一次表达 JSON 可带 0–4 项感受提案；允许多种感受并存。新建不填 ID；修改只能引用本会话实际展示的既有感受 ID。
3. 有回执的回复、忽略、暂缓可以快速登记提案，不等待审核。发送失败或结果不明时本路径不登记，也不重发。无效的可选感受字段单独拒绝，不让正常回复失败或额外修复一次表达。
4. 复用现有调度时钟，在无活动冲突时处理队列，不新增“必须反思”的行为意图。它执行的是模型已提出的感受的技术审核，而不是强制角色做另一项活动。聊天可继续，审核只在版本和来源仍有效时提交。
5. 使用原 EmotionController、独立 reviewEmotion、共享成长/情绪日额度（默认50次）、审核输出上限8192 tokens、既有超时及写前一致性快照。审核拒绝、版本冲突、原件变化、快照失败均保留原状态。没有提案不调用情绪审核、不消耗其额度、不创建快照或队列记录。非空提案多一次独立审核，非每轮新增一个评分模型。

## 来源、去重和恢复

- 提案的逐字引文只能取宿主冻结的当前原件，不能用自己的拟回复、其他人的原话、历史或稍后到达的新消息顶替。图像模型解读和 ASR 明示不确定，不当作用户逐字自述或授权；不会为审核再读一次媒体。
- “不要保存”“不能记录”等禁存及测试标记继续禁止这条情绪写入；不妨碍普通回复。历史恢复和升级前旧消息不补学、不补发。
- 每条真实事件最多登记一次非空提案。暂缓后重新考虑不会重复消耗审核额度。
- 聊天感受与深度反思各用独立来源 ID，避免二者材料范围不同却覆盖同一个来源记录；两条来源共享实际事件因果键、接收顺序对话窗和媒体证据键。原情绪控制器据此阻止同一段短对话/同一媒体反复提高强度、延长时效或增加独立支持。窗口只是去重边界，不证明语义相关。
- 只传给聊天本会话已有感受的简要事项和 ID；不加载别的好友、主用户私聊的情绪原文。全局感受如何影响表达仍沿用原 self 摘要。
- 队列最多100个待审核项。临时提案15分钟后过期，避免额度或离线造成隔天补写旧心情。额度耗尽时等待，过期后退出；不挤占普通聊天。
- 崩溃时已完成的批次以真实 `emotion_batches` 回执为准；正在审核且没有回执的记为中断，不自动重跑模型。尚未开始的提案仅在未过期、原件可核验且版本未变时继续。

## 数据与查看

持久数据仍在 `runtime/dev/companion/companion.sqlite`，没有另建人格或记忆目录：

| 数据 | 位置和作用 |
| --- | --- |
| 原QQ消息及媒体依据 | 原 `platform_events`、`platform_media` |
| 可选聊天感受队列 | 新 `social_chat_emotion_jobs`：原事件、冻结来源哈希、旧版本、提案、实际审核回执或失败原因 |

原 `friend_social_experience_read` 概览和运行健康信息新增 `chatEmotion` 子项（状态计数及近期任务 ID）。指定聊天情绪任务 ID 可读取冻结提案、快照及实际回执。原情绪历史工具继续查看状态变化和独立审核。完整角色迁移继续复制完整停写实例，勿只复制新队列表。

选择零变化和审核否决都是有效结果。上线后自然聊天是否提出感受、怎样变化，需要看真实提案和回执；这些工程状态不证明内生意识。

## 称呼辅助背景修补（0.51.1）

真实好友私聊中，表达模型正确使用已保存的称呼，但情绪审核只看本轮原话，曾把旧称呼误判为凭空补写。现在仅从本轮表达已经召回的社交记忆筛出最多2条称呼偏好，按QQ号、AI账号、原私聊或原群、记录内容哈希、原件哈希及有效状态重新核验，冻结为assessment.kind=qq_chat_context的namingReferences。仅明确称呼约定入选，其他兴趣、对别人的印象、群来源进入私聊、后来到达的原件、当前消息刚写的记忆均不入选。

这份辅助背景只解释称呼和指代，不证明实名、亲属关系或权限，不是新经历。感受依据仍须逐字来自当前source.content；不能把旧偏好或这次召回作为新的情绪支持。称呼正确也不保证提案通过，混合标签、无意义或其他问题仍可拒绝。每个感受提案应保持标签与内容对应，多个感受可分项或留空。

引用的旧记录在审核前、快照前后失效或变化时，取消本次旁路提交，保留普通回复。不为这项修补新增模型、数据库表或额度，也不重放旧的拒绝提案；既有记录仍保留原回执。名称辅助记录随现有聊天情绪队列和审核快照存入companion.sqlite，角色迁移方式不变。只作为历史称呼辅助，不成为情绪对旧画像的长期因果依赖；名称后来更改不等于当时的真实当前事件被撤回。
